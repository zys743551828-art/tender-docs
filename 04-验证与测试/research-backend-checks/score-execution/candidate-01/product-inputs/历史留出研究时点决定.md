# 历史留出研究的时点与产品边界

产品Owner接受研究提出的独立回溯模式。本文件是[历史proof协议](历史可见证明与回测输入协议.md)的当前模式说明；[研究提交材料](历史实验时点产品待审.md)保留原待审身份，不回写成当时已批准。严格StageA旧协议和原证据不改。命名、字段及下述接受条件可进入实际契约设计，软件和模型资格尚待验收。

## 1. 两种模式不互相替代

| 页面名称／语义标识 | 允许的研究与结论 |
| --- | --- |
| 严格未来提交留出／strict_future_submission_holdout | 沿用已冻结StageA的全部训练、标签实际知晓、未来提交及组／曝光限制。缺真实时点证据不能借回溯模式取得该模式资格 |
| 按历史提交时间留出的回溯研究／retrospective_submission_time_holdout | 现在取得和训练历史资料，按真实历史提交事件划分训练／测试组，重建各样本当时有据可见的输入；报告历史提交留出误差，不称未来预测精度、当年已有模型或线上事前误差 |

创建时必须明确模式；历史资料研究入口可预选回溯模式，但不能按资料年份猜好资格，也不能将既有严格实验自动改模式。当前严格StageA只支持合成软件研究，新proof／新模式不自动打开其real执行入口。两种模式各自冻结协议、数据来源、配置、分组和执行权限，不共用含糊的“已校准／通过”绿标。

## 2. 四个时点及边界

| 字段 | 唯一含义与校验 |
| --- | --- |
| submission_split_at | 回溯模式的真实提交事件切分界：训练候选submitted_at<该值，最终测试候选submitted_at≥该值。不得以2026录入时间代替2019提交时间；同一相关组不能拆入两侧 |
| label_available_as_of | 本次研究允许使用的、实际已经取得标签的截至时点。每条标签known_at保留实际取得，必须≤该截至；不从公布日期改写。不晚于training_frozen_at；后得标签须另建相应输入版本，不能补入原冻结训练 |
| training_frozen_at | 服务端实际冻结训练输入、方法、特征和参数的当前时刻；不可由客户端倒填。训练标签集合和摘要在此固定，最终测试标签不交训练进程 |
| historical_as_of | 每个HistoricalInput对应的实际历史提交边界，只用于证明该精确正文／招标补遗／必要事前事实当时可见与有效，不等同于标签可得、训练发生或系统创建时刻 |

例如2019提交的真实标书、2026才取得的官方技术分，known_at和label_available_as_of可在2026、训练冻结也在2026；submission_split_at仍可按历史提交事件设置，historical_as_of是具体当年提交时点。这支持回溯拟合，不证明2019当时模型已知标签或拥有预测能力。

训练／开发／最终测试成员、相关组及各自原提交时间都冻结。组从HistoricalSubject的工程／标段／轮次／主体、原件摘要、模板／近重复关联形成，不能从当前profile重新推断。跨切分边界的相关组默认排除并说明group_spans_submission_split，不能拆分泄漏或自动挪到能得到更好误差的一侧；另需保留为特定研究集合时须显式冻结不同协议，不能改本次规则。开发集仅在训练侧按冻结分组协议划出。

## 3. 页面与创建字段

创建页最少包含研究模式、数据集／历史输入、submission_split_at、label_available_as_of；training_frozen_at由服务端返回，historical_as_of在样本详情只读。给训练／开发／最终测试的组数／样本数、排除及缺证原因、真实／合成／不确定来源构成、当前权限和费用预览。没有可用real路径时显示“真实历史研究执行尚未开放”，仍可补证或保存配置草案，不能改origin字段假装合格。

回溯创建／运行／结果页固定显示“回溯历史研究：标签与训练在现在取得／进行，不代表当年预测或未来预测精度”。结果同时列四时点、protocol_digest、split_manifest_digest、data_origin、prediction_timing=retrospective、research_only=true和模型业务资格。不得把“留出”简写成容易误解的“未来验证通过”。

研究预览需暴露按原因排除的缺历史可见证明、身份／实际稿不符、完整章节缺口、标签未核实、跨组、时点不符等；未知不补默认早期日期。创建研究／确认费用仍复用已有一次明确动作，不增加岗位审批。只读模式选择和保存草案不触发模型调用。

## 4. 标签曝光与退出条件

训练、评估的用途与角色隔离保持。最终测试标签曝光必须先持久记录，再向独立评估执行端释放；training_frozen_at、划分、特征和参数固定。曝光后不能根据该最终误差重调再把同一集合称为新的未见最终测试；恢复只复用同一次已冻结评估及幂等结果。普通返回页面不重复曝光或执行。

产品接受条件是：模式／四时点及组规则进入实际Schema与authority；受限SQL和执行权限经架构静审；新普通上传→proof/历史身份→完整HistoricalInput→样本/划分→当前训练/独立最终评估的真实API长路径和反例通过；实际UI说明与错误恢复一致。缺real资料时只可验明确合成工程，real研究效果及模型业务资格继续pending。

回溯结果不能回填原submission.review_id、当年预测绑定或在线20配对，不自动发布正式模型。真实有据历史样本可供未来模型监督候选；将来未来预测资格依独立真实数据协议、基线／校准／观察和发布治理另判，不能因回溯误差好就转正。[本增量待执行任务](timing-acceptance.json)与已有HIST任务分别保留pending。
