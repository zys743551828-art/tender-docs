# 历史资料与评分研究后端架构审查

结论：候选 01 有两项阻塞，修正后才能放行新的研究模型请求。历史资料登记、只读产物及其他未受影响模块无需因此停工。候选 SHA256 `20e92d95e30325f3a44d98bb160fa680dcfe777c05ce60c64faa33326e1279d5`，16 份冻结源已逐项核对；报告行号均指 `research-backend-checks/frozen-inputs/` 的原字节，不能套用后续修改源码。

## RS01：费用预留使用的 token 上界可小于实际请求上界（P2，阻塞研究新调用）

位置：`packages/research/batches.py:200`（尤其 220–227）；`packages/research/model_port.py:61`（69、72–75）；固定 profile 见 `packages/research/profile.py:35`。

触发：使用正确 profile_digest 的价格配置，但填 `max_output_tokens=1, context_tokens=2`。配置、预览、启动均接受；实际模型请求仍按固定 profile 发送 `max_tokens=4096`，预留与预览却按 1／2 计算。

独立实证：全新 PostgreSQL、受限 API／研究 LOGIN、真实 ASGI、原生 DeepSeekClient 配显式 MockTransport 下，同一条目三次请求均带 max_tokens=4096，每次仅预留 `0.00000180`。见 `budget-counterexample.json`。实际 usage 事后补记不能代替发送前费用上界保护；部署配置误填即可造成预算检查偏低。

修正：执行上界唯一来自 profile；价格配置中的重复参数须类型严格为 int、精确匹配 profile，或直接由 profile 派生。冻结价格摘要、预览与每次调用预留必须使用同一上界，不仅比较 profile_digest 字符串。

验收：1／2、bool、非整数和不匹配 profile 配置在预览／预留前拒绝，外部尝试零次；合法配置仍可执行，预留与预览覆盖实际发送上界，超额及未知费用处理保持原语义。

## RS02：冻结章节后原件撤回不会阻止新的研究请求（P2，阻塞研究新调用）

位置：`packages/research/chapters.py:15`（原文／页码覆盖检查，但未形成来源祖先授权闭包）；`packages/research/worker.py:49`（package 载入与字段比对）；`packages/research/model_port.py:79`（预留前缺完整来源资格重核）。结果发布见 `packages/research/execution.py:188` 起。

触发：按合法路径冻结完整章节、数据集和研究批次，然后撤回该正文的稳定原件根，之后才调度该条目。

独立实证：真实非 owner PostgreSQL 中通过 canonical parse/source 接口登记并撤回根；原件状态为 withdrawn，process 仍发送三个新 Mock 请求并把条目标记 succeeded。见 `withdrawal-counterexample.json`。章节包 SHA、sample.admission、标签与提交身份未改变，因此现有检查全部放行。历史产物能只读还原不等于其仍可作为新请求的有效输入。

修正：API 冻结、每次新调用和结果发布应从服务器固定的 run／attempt／sample／submission／review／chapter 关联派生完整来源与原业务时点，验证 canonical 原件／parse／page／evidence、用途 prebid、全部祖先当前 published、known_at 及有效窗，并绑定 head 版本。研究角色无需获得任意来源或标签表扫描权限，可新增受限资格函数和必要不可变映射表。资格函数不得接受 Worker 自报白名单作为权威。图锁仅持至同一短事务 effect 提交，不跨模型或对象网络。

验收：冻结前撤回／未来来源拒绝；冻结后撤回、祖先变更、过期、重发布旧包以及错误 parse／证据绑定均阻止新请求；计算中撤回阻止旧结果发布，但仍如实记账；合法路径真实研究 LOGIN 可执行。函数固定 search_path、撤销 PUBLIC、最小角色授权，并由新空库初始化实证，旧冻结证据不覆盖。
