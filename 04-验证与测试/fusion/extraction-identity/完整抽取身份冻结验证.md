# 完整抽取身份冻结验证

本片实现新抽取任务的精确包输入与结果绑定，应用提交 `0978ba1`。适用于融合分支候选代码及专用新空库，**尚未部署到当前 fusion_v2 预览库**；当前 5188 仍为上一批人工范围工作面的运行版本。整包正式评审／评分／提交资格保持关闭。

## 身份与信任边界

准备阶段仅在现有完整资料与唯一当前权威包精确相符时生成 `package-rule-extraction-input/1`：项目／主体／标段／轮次，权威包明确修订及摘要、原身份快照，全部成员的文件版本／文件摘要／明确解析与解析配置、证据摘要，分册物理页段和共享附件归属，以及方法及其摘要。没有唯一匹配、页段不全或解析未冻结时，不推测整包身份。

此处匹配发生在新任务准备时，不按时间反推历史。任务冻结后，Worker 读取原 descriptor，核对原明确修订，执行与完成均不以当前 head/latest 替代。除了明确 parse ID，还逐项核对实际任务携带的物理页、证据 ID、文字、几何／结构和摘要与冻结解析一致，防止删块或换正文后仍宣称相同输入。新解析与新包 head 不会改动旧输入。

`bid_package_requirement_extraction_runs` 由 Worker 在创建规则集的同一完成事务内追加，绑定准备 operation、输入 blob、输入摘要与规范正文、结果规则集、方法、实际证据集合摘要和抽取覆盖状态；SQL 约束校验 operation/outbox、项目、权威修订和摘要。API 不能插入该表；已有追加不可变守卫保护原记录。初始化仍走统一全新库 SQL 计划，权限收敛脚本与正式计划共用。

新规则集有真实完成绑定时，可追加 `bid-package-requirements/2` 清单；旧未证明规则集继续写/读 v1，不补写旧清单、不改摘要。v2 清单读取核对冻结结果与规范正文，数据库内完成，不依赖原件对象存储在线。`inventory_complete=false`、`review_ready=false`，覆盖评估仍不宣称整包完整。`all_frozen_evidence_submitted` 仅表示该输入范围送入提取器，`extraction_coverage` 是提取器结果，质量仍为 `not_measured`。

## 验证

- 固定 `tender-fusion` 检查 profile：**真实 PostgreSQL／非 owner API 与 Worker 32 项通过，34.51 秒**，含原 25 项、新精确冻结／结果记录与历史回读 2 项、正文篡改等参数化反例 5 项。[原始 XML](evidence/requirements-api.xml)、[执行尾日志](evidence/checks.log)。本批不是整个后端基线全绿。
- 新输入校验实际在非 owner Worker 连接执行；API 直接伪造完成记录被权限拒绝。新增头和解析后，原冻结输入仍通过原身份校验；错项目、错轮次、删证据、改正文、改页号、成员页段与原包不符均拒绝。
- 同一合成规则集先保存 v1，再记录完成事实并追加 v2；旧清单完整响应、摘要保持不变。关闭合成对象存储适配器后，两版仍能读取，不把当前来源重新写入旧清单。
- **纯领域／实际契约 32 项通过，1.60 秒**，含新增 6 项及原要求领域、证据契约；[原始 XML](evidence/pure-32.xml)。这些与真实库计数分别记录，不相加为业务验收数。
- **完整前端 43 文件、276 项通过，15.97 秒**；[原始 XML](evidence/frontend-276.xml)。同步实际 OpenAPI 的要求清单形状和前端生成类型；原 v1 与新 v2 均可解码。本批未改 UI/CSS，构建主包及范围模块内容 hash 与上批相同。
- 后端相关 7 源格式／ruff、5 源 mypy／bandit，前端格式／ESLint／类型／生产构建通过；构建 2.23 秒。既有助手静态／动态混合导入提示保留。融合 Compose 配置检查通过。
- 专用库及两个登录账号结束后均为 0，检查服务停止；[清理回执](evidence/cleanup.json)。未启动原 dev 或 Claude 容器，未安装新软件。[源码及证据指纹](evidence/receipt.json)记录的是候选工作树，不冒充部署版本。

执行入口：`fusion.ps1 -Action checks -Suite requirements-api`；纯测试为 `pytest tests/test_bid_package_extraction.py tests/test_bid_package_requirements.py tests/test_bid_package_evidence_contract.py`；前端为现有 format/lint/tsc/vitest/build。

## 未验证与后续

未验证：真实供应商模型、实际 OCR／表格质量、对象存储原件取回、Kafka 全任务执行链和新协议的预览部署。真实库测试的对象存储为显式内存适配器，完成回执由专用非 owner 测试 Worker 写入；不将其说成真实模型完整执行通过。

验证方法：先对新空预览库执行当前统一初始化与完整运行权限检查，在独立 Compose 服务组内走实际 prepare／compute／publish／幂等重试和浏览器历史读取；旧 fusion_v2 保留，不用初始化 owner 对旧库补权限或覆盖旧规范正文。部署必须明确标注新空库与原预览的区别。真正整包输入适配及正式评审／评分／提交链另验；抽取漏提质量和官方评分精度需要真实样本，不由本片授予通过。
