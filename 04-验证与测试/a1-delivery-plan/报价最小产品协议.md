# 报价最小产品协议

本协议由产品Owner按[PRD第15.1节](../../02-业务与产品/AI投标工作台PRD.md#151-报价fr-006)收口，落实FR-006与[目标D07](../../05-技术与设计/detailed-design/保留功能实现规约.md#7-报价曲线与方案版本d07)。以下是待开发的实际契约要求；报价计算纯函数及手算测试不代表API、来源事务、页面或业务验收通过。完整评分、否决核对和报价为不同能力，报价不改变提交gate。

## 1. 入口与最短路径

项目报价工作面按需进入：查看有据公式→已有已确认公式可直接输入情景并试算；没有时从本项目生效招标／补遗原页提取或手填→一次明确“确认并登记公式”→输入本方候选与对手假设→查看分数、限制及曲线→需要保留时“保存当前情景方案”。不要求新建模板、任务、知识条目、编辑器或岗位审批。试算不会自动保存成方案。

公式确认是人工确认该原文如何对应受限计算参数，不等于确认某个报价最优或实际有效。确认按钮本身已经明确提交，不再走聊天复述或第二张确认卡。公式未支持／原文有歧义时保留输入和原页，写“当前不支持此计分规则，不能计算价格分”，允许继续其他工作。

## 2. 公式身份与来源

采用独立的不可变`formula manifest`保存规范化JSON，`formula_version_id`就是其blob版本ID，由服务端生成。不能借用模板ID、规则ID或让浏览器填写UUID。修改参数或依据均追加新manifest；旧版本、引用与已存方案不覆盖。

manifest至少冻结以下信息；具体Schema／路由由实现方统一导出actual契约：

| 信息 | 最小内容及约束 |
| --- | --- |
| 归属 | bid_id、当时material_snapshot_id／material_revision，适用标段／轮次与公式标题 |
| 计算参数 | method、maximum、minimum_price、maximum_price、minimum_valid_bids、above_coefficient、below_coefficient；数值用有界十进制字符串，有效数量用整数 |
| 量尺 | amount_unit，明确元／万元等输入单位；currency可明确或记未知，不自动换算；rounding_policy只接已支持且原文有据的策略 |
| 精确依据 | source_id／source_revision、document_version_id、parse_id、physical_page、evidence_id、逐字quote，以及这些依据支持的计算字段；客户端从可信原页投影选择，不手填技术ID |
| 人工决定 | confirmed_by／confirmed_at来自服务端会话和时间，reason记录解释；客户端不能自行赋已确认身份 |
| 可还原身份 | blob ID、formula_digest、calculator／method实现身份；读投影给当前适用性及原因，不改写旧manifest |

公式在来源图登记`kind=feature`、事前内容用途，并连接精确解析子来源及原件祖先；这属于实际来源图节点，不向目标`SourceRef.kind`枚举硬塞feature。服务端在同事务核对本项目、原文、精确解析与来源版本、当前效力和人工确认后登记。没有逐字出处、跨项目、撤回、过期、补遗冲突或适用不明，整笔拒绝并保留表单，不能部分保存后声称公式可用。

试算及保存前重验公式与全部来源祖先。新补遗不能仅因旧公式已确认就绕过；来源变化时给“公式依据已更新，请核对后重新试算”。证明仍等价且有效可沿用，否则需有据登记新版本；不把所有无关资料变化强制变成新人工审批。旧方案仍可还原当时公式、输入与结果，显著说明历史依据及当前影响。

## 3. 只支持两种精确方法

以下符号仅用于解释；服务端不执行用户表达式、任意脚本或AI临时写的公式。

| method | 唯一计算语义 |
| --- | --- |
| lowest_valid_ratio | 在本方这一候选及用户提供的对手假设中筛出数值资格有效报价，取最低者B；价格分为maximum×B／本方报价。above_coefficient和below_coefficient必须为0 |
| mean_valid_deviation | 同一有效集合求算术均值B；本方≥B用above_coefficient，否则用below_coefficient；价格分为maximum×(1−abs(本方−B)／B×对应系数)，限制于0至maximum |

每一个候选／曲线点独立代入本方报价并重新计算B，不能拿主候选基准价套整条曲线。数值资格只表示报价>0且满足已明确的闭区间边界；null边界表示有据确认无该数值边界，不能表示原文尚未读懂。`minimum_valid_bids`明确包含本方，范围1—201；同价的不同对手情景保留，不能按金额值去重对手数量。缺少对手信息不等于实际没有对手，持续标为用户情景假设。

当前支持最终价格分的`half_up_2dp`或`half_even_2dp`，全程Decimal、不做中间取整。登记时必须确认原文与本实现的基准集合、上下限、数量、双向系数、截断及取整完全一致。存在抽签系数、去极值、不同有效报价口径、分段／阶梯、先对基准价取整、其他精度或特殊保留规则时均拒绝，不能选一个近似方法凑结果。输入金额单位不一致也不计算，不自动转币种或金额单位。

有效集合数量不足时，本方可能`eligible=true`而`price_score=null`；本方超数值区间时`eligible=false`且`price_score=null`。只有公式真实算出零分时才返回字符串零。`eligible`不是整体投标资格，界面写“符合本公式价格区间”／“超出本公式价格区间”，不能写“投标合格”。没有完整原文依据不能把假设补成正式参数。

## 4. 最小实际接口与读投影

以下新增公式路由为建议实现形状，未注册前不得宣称可调用；现有目标试算／方案路由继续沿用。写入统一认证、CSRF、幂等及对应强If-Match。ETag由读取响应提供，客户端不猜拼法。

| 动作 | 需要的资源与结果 |
| --- | --- |
| 确认并登记公式 | 建议POST /bids/{bid_id}/pricing-formulas；输入参数／量尺／精确证据／reason；服务端重验当前资料并原子保存manifest、来源图及人工决定，返回可读公式版本及令牌，不另增加确认接口 |
| 选择／回看公式 | 建议GET /bids/{bid_id}/pricing-formulas及GET /bids/{bid_id}/pricing-formulas/{formula_version_id}；稳定分页，列出当前可用与历史／失效原因，详情可打开真实原页 |
| 试算 | 目标POST /bids/{bid_id}/pricing-simulations，沿用PricingRequest；最多50个补充候选，主候选始终保留，候选按Decimal值去重；对手最多200项；curve_range可空，lower<upper、2—101点 |
| 保存情景方案 | 目标POST /bids/{bid_id}/pricing-plans，沿用simulation_id／reason；读取服务端已冻结结果，不相信客户端重传分数。允许保留当时score=null的情景，但必须持续显示缺口，保存不赋有效报价或提交资格 |
| 历史方案 | 目标GET方案列表及指定方案；返回原公式、输入假设、结果、保存人／时间与当前依据影响；不能按最新公式重算后冒充旧结果 |

目标`PricingSimulationView.price_score`必填string不足以表达真实状态，actual必须扩展为`string|null`并返回主候选`eligible:boolean`与`notes:string[]`，与每个PricePoint一致。至少同时给formula_version_id、formula_digest、input_digest、candidate_price、maximum、candidates、curve、assumptions、calculation_steps、technical_exchange_note、formula_evidence_ids；只读扩展还须让公式快照和当前适用性可查。

输入不合法／不支持规则返回字段错误且不建成功结果；已支持公式的合法情景但数量不足／本方超区间可形成真实模拟记录，price_score=null并给notes。两类不能混为0分。来源或条件已变化返回409，可看原输入及出处并重新核对，不静默改公式；并发412保留人工输入和当前差异。

## 5. 页面与全入口开关

首次有据预填只填用户尚未编辑的空字段。用户已输入报价、假设、取整或选定公式后，异步加载、规则刷新和旧响应均不能覆盖；可显示“发现新的公式依据，查看差异”。报价变化400ms防抖；请求和结果绑定input_digest，旧曲线暂留标“待更新”，迟到结果不能抢新参数。

结果先显示本方情景价格分及原因，再给多候选比较和受限区间曲线。未知点断开／标未知，不画成零谷；同时列本情景基准价、有效报价假设数、被排除原因、每步计算及明确量尺。没有技术分权重／同量尺条件时只写不能直接换算，不伪造技术分补偿、中标概率、最佳报价、成本或利润。

关闭pricing时，导航、页面直接链接、AI操作／会话卡片、普通提醒和新报告共同遵守设置；服务器也拒绝新登记／试算／保存，不只靠前端隐藏。已有公式／方案不删除。直接历史链接说明模块已关闭，可在设置开启；不能在关闭状态泄露结果。恢复开启后保留历史与未提交输入，不自动重跑或保存。已下载旧报告不会自动改字节，按既有报告生成时点说明处理。

## 6. 验收边界

[pricing-acceptance.json](pricing-acceptance.json)给出待执行任务，包括合法两方法、无效／未知／真实零、来源竞争、预填保护、关闭模块和历史快照。当前10项手算测试只证明纯函数的指定输入结果，不替代来源登记、API权限与幂等、浏览器多候选曲线、历史保存或真实招标公式适配。代表性真实价格条款缺失时可用明确合成夹具完成工程验证，真实业务适用性继续待材料，不阻止其他模块开发。
