# 投标工作台前端

React、TypeScript、Vite 实现的内部资料工作区。使用实际后端接口，不内置演示项目、风险或分数。当前切片支持登录和会话恢复、项目列表和简建、PDF原件上传与核验、批次确认、文件版本与历史链、解析范围与物理页依据。A1已提供概览、评审与风险、矩阵、规则、事实、处理记录与设置的客户端骨架；是否开放由实际OpenAPI注册操作决定。当前后端尚未注册的工作面明确显示未开放，不提供模拟数据。完整评审、技术评分、提交登记及Word转换尚未验收。

## 运行

在本目录执行：

```bash
npm ci
npm run dev
```

默认只监听 `127.0.0.1:5173`，`/api` 同源代理到 `127.0.0.1:8800`。先按项目部署说明启动后端、私有存储及Kafka Worker，并由维护人员创建成员。浏览器不保存密码和CSRF令牌，刷新通过HttpOnly会话恢复。登录过期保留当前页面输入，重新登录不会自动重放写入。

独立验收环境可使用：

```bash
API_PROXY_TARGET=http://127.0.0.1:8801 npm run dev -- --port 5174
```

后端允许的Origin及私有存储CORS需与实际端口一致。项目列表为 `/projects`，详情为 `/bids/:id/materials`。项目首页 `/bids/:id` 恢复有效工作位置，否则有当前轮次时进入评审，无结果进入概览；显式资料和历史轮次链接保持原对象。A1工作区展示客户端已完成的页面，并在未注册接口处说明不可用范围。

## 上传与恢复

当前只接受PDF，单文件上限100 MiB，使用真实私有对象存储的单次PUT授权。授权指向同源应用传输时携带HttpOnly会话，PUT附当前CSRF；指向外域S3时不发送Cookie或CSRF。PDF固定以application/pdf发送，不手设浏览器禁止的Content-Length。先按文件选择用途及独立文件／指定文件的新版本，再上传核验，最后明确确认有效集合。传输成功、核验通过、入库完成和解析完成分别展示；均不表示评审通过。

部分失败需要明确选择仅将核验通过的文件入库；失败补遗不会悄悄略过。412时保留已核验原件，刷新资料包后重新核对；需要变更目标时填写原因并建立新的入库绑定，不自动覆盖最新版本。写入命令按输入及实际ETag保留幂等键，网络重试复用同一命令键。

批次ID保存在浏览器本地以便刷新后恢复，上传命令身份及摘要保存在当前浏览器会话。若刷新时传输尚未完成，可在对应文件行重新选择相同摘要的原文件接续，已核验文件不需重传。新的浏览器没有未完成传输的接续记录，需要重新选择文件；服务端已收到的业务资料仍保留。签名URL过期会重新授权同一上传，暂不提供分片上传。Word请先导出PDF；当前不声称已保存Word原件或已核验两种格式对应关系。

原件查看使用有时限的私有下载授权，由自托管PDF.js绘制真实物理页，与解析文本并排展示。Worker、CMaps、标准字体、WASM及ICC资源在安装／构建时从锁定依赖复制到本地，运行时不访问CDN。页码取PDF真实总页数，包含未提取文本、扫描和空白页。没有可靠坐标时显示整页；扫描／OCR缺口持续显示，不绘制推测高亮。原页绘制失败时持续显示错误并可刷新访问地址，仍可直接下载资料原件。有新版本的资料行提供历史入口，逐版读取真实元数据，历史文件名、原件、解析依据及下载身份分别保留。文件身份只在详情展开，不把摘要塞进日常表格。

## 契约与验证

`src/contracts.ts` 仅生成当前UI消费的schema闭包，来源是根目录 `packages/contracts/implemented.openapi.json` 的实际实现契约。生成类型不表示完整目标系统已实现；本页面只调用当前注册接口。生成文件也包含实际method/path能力列表；目标schema存在不代表对应服务已注册。后端actual契约更新后重新生成才能开放对应工作面。

```bash
npm run contracts:generate
npm run format:check
npm run lint
npm run typecheck
npm run test
npm run build
```

资料查证从工作区“查证资料”按需打开，不挤占风险流程。查询草稿在当前浏览器会话保留，网络重试保留原查询及幂等键；编辑后的查询需要明确重新查证。结果持续显示索引缺口，不把空命中称为不存在要求。引用使用真实文件版本与物理页；打开前复用原请求核对来源，409后明确标记历史，仍可追溯当时原页。检索摘录不作为正式评分的完整输入。接口未注册时仅保留草稿并说明未开放；模型服务不可用时保留真实失败，不生成假摘录。

A1骨架区分执行失败和业务无法判断、事实未知和false、处理确认和风险解决；风险暂缓仍保留，关闭检测后已有关键项不消失。单条决定使用对象ETag，事实变更使用事实集头ETag，规则补漏使用规则集ETag。准备接续的跨浏览器恢复、评审历史分页与服务器主要下一步，仍依赖后端A1 actual接口落地并独立验收。

组件测试使用明确的测试响应，覆盖登录失败、会话过期不重放、网络故障、部分入库、412恢复、响应丢失后的幂等键复用及解析缺口／物理页。新增A1/RAG组件用显式未来接口测试夹具，验证覆盖和空/失败/来源变化等状态；这不代表这些API已部署。字节传输测试验证同源认证与外域隔离。开发自查结果见 `qa-previews/selfcheck-result.json`：真实浏览器／API／S3／Kafka与合成三页PDF，检查真实canvas、空白页、解析缺口、390px及刷新接续。它与独立测试证据分开；单元测试不代表真实解析质量、模型效果或业务验收。

桌面与390px布局支持键盘、可见焦点、持续错误文字和按用途命名的下载入口。手机资料行使用紧凑卡片，原件入口与解析范围保持可见；项目列表只在表格容器内横向滚动，页面本身不应横向溢出。
