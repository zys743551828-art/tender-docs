## 1. 交付边界和顺序

先补无收费的软件链：可核验研究结果→版本化特征→分组时间训练/开发→冻结模型和验收协议→一次独立测试→候选登记→相同输入影子比较→人工验收/发布/回退。另实现当前review的完整章节三判断生产者，与核心核对分开；无适用业务模型时只返回合法原始判断/未校准估计或unavailable，不生成accepted预测。

本阶段不默认启用近邻、锚点、排序、入围概率、微调、图页猜测或超长层级汇总。已识别但当前方法不支持的规则/图页/范围明确拒绝整轮总分，不从评分分母剔除；不影响已完成核心核对与合法实交。后续方法另立digest与实验，不把不支持内容静默映射为档位。

可用明确合成夹具交付数学、泄漏门禁、幂等、事务、恢复及拒绝发布路径；合成产物永久research_only，不能事后改标real来取得资格。没有真实官方标签、代表性资料、最终业务协议、独立精度和观察证据，正式验收/发布保持拒绝。现有2call核心验证授权不覆盖研究或正式评分调用，所有新收费执行默认禁用。

- clean_feature_manifest：不含标签、评委意见、事后内容；每例关联完整评分范围与三次有效调用身份；所有特征复用同一纯FeatureBuilder。
- fit/development label manifests：只含对应训练/开发/校准来源的有效技术总分、满分、核验出处与取得时间；数据来源由服务器冻结映射决定，不接受客户端labels/features JSON。
- sealed_final_test label manifest：独立评测角色读取，训练与评分进程不取得其正文或对象能力；最终测试预测先冻结，再与该标签合并计算指标。

## 3. 特征与判断方法

现研究03判断schema只有档位、理由、引文、完整度和有效状态。首个可实现FeatureBuilder只从这些真实字段计算，绝不补造要点覆盖、针对性或具体性数值：

| 特征 | 定义和边界 |
| --- | --- |
| 档位频次与分歧 | 每规则3次真实档位频率、众数占比、边界范围；规则ID只做引用，不作为记忆标签的特征 |
| 档位原始估计 | 只有规则有明确、有效、有来源的points或上下界时，冻结“区间中点仅作未校准输入估计”的算法；不是官方分项真值 |
| 加权摘要 | 用规则原始满分加权，保留每条分项输入和分母，不固定各分项对正式总分的贡献 |
| 读取及证据质量 | 完整章节/图页覆盖、三次有效数、逐字引用校验；失败或无法判断不填0，不假定已经完整读图 |
| 背景 | 评分办法、量尺、地区、工程类型；只允许预先定义低维字段，不用项目/企业/原件ID当回归输入 |

技术总满分需有已核实原文依据，且全部必要评分项满分合计一致。缺总满分、关键项、有效三判断或明确档位时，特征结果携带拒绝原因，计入失败/拒绝分母。后续增加要点/针对性/具体性需要新判断schema/profile及相应质量验收，不在此版本虚构。

当前章节构建器保守使用全文，超过受控大小或存在图表/解析缺口仍拒绝；本阶段不声称层级分包质量通过。

## 4. 统计候选与选择规则

候选家族来自评分主记录，不由实现者临时指定“最好模型”：训练均值、训练中位数、评分办法分组收缩基线、可定义的原始档位估计、带正则线性/岭回归、一维有排序意义的原始估计保序校准。近邻/锚点保持关闭。

训练协议在计算前固定允许家族、岭参数网格、分组基线回退/收缩规则、特征schema、缺失策略、编码/标准化策略、开发指标及确定性并列处理。没有协议参数不代用户猜超参数。所有变换在本fold训练来源拟合；不全库填补/编码/标准化后再切分。保序只用明确的raw scalar，不把多维特征任意排序。

训练目标统一为100×技术总分/技术满分。输出时还原原量尺，报告百分制与原量尺误差；原量尺换算不是补救不一致的评分满分。按项目等权拟合/评测，另报样本加权结果，连通组仍为独立划分和不确定性重采样单位。

先用训练内分组折确定各家族内部参数，开发集仅用于家族选择；最终测试不参与任何选择。模型选择后，是否在训练+开发重新拟合由协议提前冻结；保留独立校准组，不能将其混入拟合。重新拟合的最终模型、特征变换、实现和依赖环境摘要在最终测试前锁定。

产物使用有界JSON参数/系数/单调结点及预处理描述，不反序列化用户pickle，不执行任意表达式或脚本。只加载服务器登记、对象实际字节SHA匹配、实现/feature schema支持且范围匹配的产物。实现算法的数值解法与极端条件须独立合成手算/数学反例验收，不据此声称真实误差。

## 5. 划分、校准和一次最终测试

沿用冻结train/validation/test/excluded，新增训练协议内显式calibration_group_ids（必须是train内独立连通组），与proper_train和validation/test完全隔离。所有拟合/开发/校准标签取得时间早于最终测试起点；跨起点连通组剔除。整个项目/模板/近重复/同正文闭包不跨用途，新增准入导致组变化即失效。

独立最终测试在查看其指标之前冻结：完整成员与源闭包、最终模型SHA、业务验收协议SHA、拟合/校准/开发记录、运行种子、预期全分母、范围和拒绝规则。API只接受这些服务器产物ID，不接受客户端分数或“已验收=true”。

新增append-only test exposure记录并保存底层项目/正文/相关组成员，防换manifest顺序或实验ID重开同一最终测试。允许保留探索复跑但永久不作为新的独立资格证据；方法失败后使用新增独立项目形成下一最终证据。数据集digest不同不等于测试来源独立，必须检查来源闭包与已暴露成员。

区间采用独立校准数据的软件方法：预先冻结80%/90%层级及组级残差/分位规则，以校准组最大绝对残差构造保守组区间，最终独立测试同时报告覆盖与宽度。有限样本分位秩超出校准组数则区间unavailable；三次LLM波动绝不当预测区间。此区间方案为待架构/方法审查的明确工程选择，未验收前不展示成正式区间。

指标报告至少包含MAE、P90、偏差、±3接近比例、相对各基线增益、组级重采样95%区间、80/90区间覆盖和宽度、同输入整轮极差P90、全体成功/失败/拒绝/无标签分母，以及评分办法/满分/工程类型分层。无所需数据的排序/入围/评委分歧统计为unavailable，不造0或相关性。重采样种子、次数、分位定义、缺失及并列处理均在协议冻结。

PRD建议MAE≤3等门槛仅作开发对照，不默认已获业务确认。正式protocol中点分门槛、区间宽度/覆盖、成功覆盖、独立组/样本数量、分层要求、稳定性均须显式冻结且有业务确认记录；缺任何必需门槛则 acceptance=blocked，不以合成或旧在线配对数补齐。

## 6. 登记、观察、发布与回退

复用目标model_artifacts/model_acceptances/model_routes及shadow_comparisons，不修改其冻结DDL。新增最小可信评测/观察/来源映射由API受控写入或受限函数写入；研究/训练/评分角色不得修改路由或人工验收。现schema没有final-test exposure、冻结评测授权及在线score-job身份的表达能力，需新的独立SQL草案经架构静读后fresh安装，绝不热补release。

状态由不可变产物和追加决定投影：candidate / rejected / observing / accepted_for_scope / business_active / suspended / rolled_back。模型登记不授业务资格；真实标签更正、来源/身份/相关组变化经依赖清单暂停新增使用，旧报告保留并提示影响。

影子默认复用同method/feature schema、同review冻结输入和已验证三判断，不重复付费。若方法/profile/章节策略不同，必须新研究实验、预算和身份，不能在影子接口偷偷重抽章节。对照结果存独立research_artifact，不改business prediction或route，不增加官方独立样本数。业务基线无有效点分时比较的该项为unavailable，不能先造一个accepted基线。所有项目相关读/下载执行show_prediction隐藏投影，隐藏时不序列化value、interval或差分。

发布需同时满足：真实来源/独立划分、冻结协议门槛、候选及报告SHA匹配、范围限制、可部署读取、观察证据及有效回退对象、明确人工命令。业务精度未有证据时拒绝，不提供可以“强制忽略”的参数。路由首次revision=0/model=null；首次发布显式rollback_model_id=null。已有路由CAS失败412；回退只指仍合格范围对象或null（正式预测不可用），不删除路由重置revision。新路由只影响后续任务，已启动任务固定当时模型；严重失效禁止新增并保留历史影响。

独立handler `score/1`、topic `tender.task.score.v1`、consumer group独立；普通核心Worker不接管。新增受限scoring角色只读已冻结无标签来源，通过owned operation/step/generation/fence/owner取得具体章包授权，不能扫描官方标签和会话。普通core模型账本的10调用/32768输出上限不适合3×全部评分项，不能为本任务放宽共享core源；新增独立受控score ledger复用安全模式和原生生成端口，按固定profile保守价格精确预留。

每规则同一包三次独立判断，不把前次输出、RAG片段或研究标签放入下一次请求。成功项按持久身份复用，不因Kafka重复新收费；未知是否计费保留reserve且暂停，不自动补发。全部有效项齐备、来源/身份/模型/范围和fence在最终短事务重核后才写新prediction（历史append-only）。无业务模型时最多raw_uncalibrated或unavailable，区间null；accepted只来自本系统合格路由/产物，并由受限发布函数核验。评分失败不改核心覆盖/Gate，不抹掉核心风险结果。

## 9. 软件验收与真实依赖
