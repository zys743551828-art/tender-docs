# 工作台运行、数据库与验收

## 选择源码与配置

当前开发分支为 tender-app `dev`，跟踪 `origin/dev`（保留 render-acceptance-20261026 来源历史）；fusion分支和历史Windows宿主有各自固定证据，不能交叉声称运行了新代码。主源码在 workbench，根 backend/frontend 为历史供体。要求Python3.12、Node24和Docker Compose；依赖按 requirements.lock.txt 和 apps/web/package-lock.json，禁止随意升级替代验证。

默认只运行本地机制检查。`.env`及私有profile由授权操作者注入、忽略且权限600，不打印、不提交；缺配置拒绝启动。不得因非owner业务权限失败改用初始化owner。不要为了跑测试连接已有未知数据库或读取其它会话secret。

## 数据库初始化与变更

这是全新系统，既有需求不要求旧部署数据迁移。`deploy/schema_plan.py`、`deploy/fusion_full_init.py`和相应固定环境清单定义各自初始化范围；不能将 deploy/sql 按文件名排序全执行，也不能把早期19SQL清单当所有新增功能的完整安装器。

预测/认证相关 deploy/sql 为可选、fresh-only扩展，必须在空隔离库按文件声明的依赖装配并核对角色/摘要；例如 package-prediction-selection.sql 在 package-formal-prediction.sql 之后，结果插入guard负责固定计划约束。通用初始化成功不表示这些扩展已安装。新增依赖SQL安装与拒绝/真实传输链已验证（见[原生记录](../04-验证与测试/预测原生联合验证.md)），正向认证发布整链尚未验证，不能直接给现存库套补丁或重封存guard。以后若有已安装部署升级需求，另做有版本的迁移与回退评审。

## 可执行检查

从应用 workbench 运行（原生测试默认skip，不代表通过）：

```sh
.venv/bin/python deploy/ci_checks.py --suite unit --report-dir .local/ci/docs-sync
.venv/bin/ruff check apps/api apps/worker packages deploy tests
.venv/bin/ruff format --check apps/api apps/worker packages deploy tests
.venv/bin/mypy apps/api apps/worker packages deploy
.venv/bin/bandit -q -ll -r apps/api,apps/worker,packages,deploy -x packages/parsing/qa
```

前端在 apps/web 依次 format:check、lint、typecheck、test、build。不要并行多轮全量争抢CPU；代码冻结后取最终回归，保留首轮失败日志。部署结构检查使用 deploy/check_compose.py；缺 `.env` 是配置阻塞，不是业务回归通过。

原生入口包括 tests/test_slice_integration.py（PG/S3/Kafka）、test_word_intake_integration.py（独立PG及可选真实renderer）、各 *_pg.py。先核对每个显式RUN开关、准确SQL和角色要求，再对临时隔离资源运行；禁止盲目一次启用所有集成开关。固定Word profile/镜像/字体/隔离条件必须齐全；系统LibreOffice或合成PDF不能代替Word03验收。

## 运行与恢复边界

API/Worker/协调器须分别装配受控依赖。新预测 API 宿主使用 package_prediction_pipeline.composition.api；协调器使用 composition.coordinator；Worker使用 package_prediction_tasks.composition.compute。这些是现有任务执行器的装配接口，不是新长期服务的自动启动许可。缺依赖返回不可用，默认不调用真实模型。

故障先查原command/operation、租约代次、发布/取消标记和费用账本；丢ACK先恢复，未知费用不能重发。不要删除审计来“重置”任务。健康检查、备份/恢复及清理按 deploy/backups 与 deploy/application_recovery 固定程序；隔离恢复成功不等于生产RTO/RPO或生产恢复验收。

## 外部验收条件

隔离PG17+pgvector、S3、Kafka及准确角色/扩展SQL；指定Word03镜像与字体；真实配对和参考标注；真实合格模型/执行证据；整包标准提交、完整UI用户与容量验收。生产部署/恢复、真实付费调用和签发认证不在当前执行授权内。每次记录实际可用条件，不能把旧受阻结论当新探测。


原生路由安装采用`deploy/sql/package-model-route-v2.sql`（在observation之后、business-shadow之前）。原/1SQL保留为历史方法输入，不能拿来建立当前库。当前完整可复现安装序列在`extended_recovery.frozen_plan(prediction=True)`，基于原history隔离夹具；这是验收依赖清单，不授权直接改现存库。FR032使用显式prediction=True的/4计划覆盖新认证/预测扩展及私有对象；旧/1、/2按原SQL清单验证。详情按[扩展核对](../02-业务与产品/融合扩展实现核对.md)继续跟踪。


当前材料执行 fresh安装使用material-execution-attempts-v2.sql，绑定执行方法/3；内部live_send_current无PUBLIC EXECUTE。恢复生成格式为完整/3与预测扩展/4，旧/1和/2只按旧SQL闭包核对并隔离恢复，不重放任务。原因、失败与兼容反例见[dev CI修复](../04-验证与测试/dev-CI原生权限修复.md)。默认后端CI整体预算45分钟，测试命令不变。

## 测试专用成功链与恢复

按[测试协议](测试专用预测认证协议.md)在已登记隔离库额外安装，不加入业务初始化/恢复计划。真实PG/S3中的测试资格、Worker成功计算和测试发布不等于正式认证发布；DB实例重启/跨库恢复使旧测试资格失效。API/Worker重启的恢复由跨进程原生用例验证。CI新增独立测试成功链job，既有8项之外单列，未运行不得标通过。指定Word03镜像本轮重新inspect仍不存在，未替换镜像。

## Word03精确来源依赖

[2026-10-30来源核查](../04-验证与测试/Word03来源与复现核查.md)已实际逐文件确认宿主10组资产及三个原审定源码匹配，仅原基础image ID缺失且无可定位registry/归档/构建材料。根deploy/word/Dockerfile是不同供体服务，不得替换。最小输入为原镜像docker-save归档及SHA256，或实际映射到原image ID的可信不可变registry引用；不是泛泛申请模型key或购买转换许可。材料到位后按原工具生成新路径profile并做真实隔离转换，不能复用旧绝对路径profile或改IMAGE。

## 报价独立原生与浏览器验收

`deploy/ci_checks.py --suite pricing --disposable-postgres --weed <已核验4.48二进制>`使用显式临时CI_POSTGRES_DSN，业务仍使用独立非owner连接；工具不查业务.env。浏览器依赖显式PLAYWRIGHT_MODULE/BROWSERS_PATH及可选CHROMIUM_EXECUTABLE，真实HTTP仅本机临时API。聚合禁止skip，结果/浏览器回执入report-dir；退出清理临时服务。详见[11项实际记录](../04-验证与测试/报价历史原生验收.md)。不需要Word03、模型key或持续存储凭据，不将其标为真实招标效果验收。
