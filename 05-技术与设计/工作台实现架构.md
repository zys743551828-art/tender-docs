# 工作台实现架构

本页描述已整合 dev 的实现；[融合技术方案](融合技术方案.md)与[融合详细设计](融合详细设计.md)仍维护目标约束。源码基线和需求边界见[追溯矩阵](../02-业务与产品/实现追溯矩阵.md)。

## 模块与事务职责

| 实现目录（workbench内） | 职责与边界 |
|---|---|
| apps/api | Cookie/CSRF、成员/范围授权、DTO、调用应用用例；实际路由快照 fusion-implemented.openapi.json.gz |
| packages/platform_runtime | 配置及数据库适配；domain.runtime保留兼容出口，不是新增共享Session |
| packages/model_registration | 登记应用编排与事务端口；不把HTTP对象带进领域 |
| packages/package_model_registry、package_model_admission、package_model_certification | /3 artifact显式适配、final曝光前无默认阈值协议、认证有效期及终态撤销；旧模型版本独立 |
| packages/package_model_live、package_model_observation、package_model_route | 可信执行上下文、受控观察和回退事件；synthetic/retrospective不能当live认证依据 |
| packages/package_prediction | 认证/完整材料复验、冻结模型与输入推断、事务发布；计算前及落库前重新检查 |
| packages/package_prediction_tasks | 复用operations/outbox/lease/fence，私有CAS输入结果；Worker只计算，API有权发布 |
| packages/package_prediction_pipeline | 既有范围/开始意图→唯一认证→固定命令；GuardedTransaction及数据库结果插入守卫阻止取消/漂移发布 |
| packages/package_unified_reports | 同冻结上下文的核查、预测、报价、响应矩阵；JSON/Word/UI共用投影与最终复验 |
| packages/model_governance、material_jobs | 材料资格、账户/profile、价格、预算、发送及结算；接受任务不代表发送授权 |
| packages/authoring、word_intake | 固定来源原子修改、Word导入、受限富内容生成与几何校验；不支持布局失败关闭 |

API/application/ports/infrastructure按实际业务切片隔离，不要求全仓机械搬目录。连接在短事务内创建/释放，不跨CPU或对象I/O共享；Worker不得借API或owner身份。冻结源码摘要含义不随重构暗改；有语义变化须新协议版本和兼容反例。

## 任务和报告生命周期

1. UI按当前成员、bid和technical scope恢复；`GET prediction-pipeline`读取，`POST /advance`推进，`POST /cancel`取消（前缀 `/api/v1/bids/{bid_id}/technical-scopes/{scope_id}`）。封闭请求不接受任意证书选择或分数。
2. 自动开关开启时以冻结scope命令为意图，关闭时等待已有开始评审命令；核查未就绪或文档版本/parse/file_digest集合不相等不提交。多个/零合格认证明确拒绝。
3. 固定计划写原审计，UUID5命令去重；先授权，再写私有对象，再短事务复验入队。重试与丢ACK查原操作，不创建平行队列。
4. Worker按原lease/generation/fence取得执行权，读固定对象并计算；计算完成不是正式结果。过期主机结果不得覆盖新主。
5. API发布前复验认证、输入、取消和范围；结果与发布标记同事务。协调器默认关闭，启用后恢复已有任务，无需浏览器常驻。
6. 统一报告绑定同scope最新合格核查、当前人工决定/设置/报价及结果；对象读取和Word计算在事务外，最终快照不一致拒绝。partial/unknown保留，隐藏数值所有出口一致。

实际全部路由以[机器快照](https://github.com/zys743551828-art/tender-app/blob/50657762cb2eaa08f81db87e188eba8e629dd131/workbench/packages/contracts/fusion-implemented.openapi.json.gz)为准；目标 contracts/openapi 不代表已注册。接口改动先导出实际OpenAPI，再生成前端操作类型。

## 执行、费用与模型质量分开

材料审核通过只授权指定模型/profile/输入版本和价格条件的执行申请。发送边界仍复验有效性与预算；未知计费不按零展示、不重新发送，撤销后允许已有调用结算。真实调用默认禁用，凭据经受控宿主注入，不进请求、日志或Git。DeepSeek名称沿用现有配置，不证明外部型号/能力有效。

预测认证是另一条权威链：显式冻结阈值、原生final报告、合格live观察/回退、绑定模型与输入身份、有效期/撤销。人工批准执行不等于准确性验收。所有正向fixture仅验证机制。

## 实际接口与状态消费

统一前缀为 `/api/v1/bids/{bid_id}/technical-scopes/{scope_id}`：

| 相对路径 | 操作 | 消费语义 |
|---|---|---|
| `/prediction-pipeline`、`/advance`、`/cancel` | GET、POST、POST | 恢复或推进既有开始意图；不让客户端任选认证 |
| `/prediction-tasks` | POST（202） | 显式固定命令提交到原持久任务系统 |
| `/prediction-tasks/{command_id}`、`/advance`、`/cancel` | GET、POST、POST | 原命令状态/发布恢复/取消；接受不代表结果有效 |
| `/formal-predictions`、`/{command_id}` | POST、GET | 保留直接预测兼容用例与当前资格复检读取 |
| `/formal-predictions/{command_id}/report[.docx]` | GET | 配套预测报告，仍有效但不替代四部分组合 |
| `/formal-predictions/{command_id}/unified-report[.docx]` | GET | review_id及可选simulation_id绑定共同快照，按当前设置隐藏 |

pipeline可显示cancelled、blocked、ready或report_blocked等服务端状态，UI不能把Worker succeeded直接显示为有效预测。ready后仍可能因资格/设置/输入变化在生成时拒绝；历史已失效结果不给数值。未配置装配返回不可用，不能用空卡片冒充评审成功。准确字段、错误码和required集合以实际OpenAPI为准。

原生执行helper不是可直接调用的RPC；PUBLIC及普通受限Worker不能直接执行live_send_current。当前SQL安装/2和执行方法/3修正安装权限，旧方法/归档事实按原版本保留，详见运行说明。

## 不可晋升的测试预测切片

`packages/prediction_sandbox` 分应用用例、原生事务适配及CLI；`apps/api/prediction_sandbox.py` 是独立且默认关闭的测试应用工厂，业务main不挂载。复用原任务/Worker，仅证书和测试结果采用独立schema与环境绑定。权限、版本及反向隔离约束见[协议](测试专用预测认证协议.md)。原正式认证、预测、报告/Word和registry未改为接受synthetic。

## 报价历史读取

报价历史复用pricing.repository与原PG/私有对象存储，不新增领域框架。读取按(created_at,id)倒序，UUID游标在同bid定位后执行二元组续页；同时间戳稳定，跨项目/未知游标拒绝。API响应/保存语义、计算器冻结摘要与源效力复验不变。新增实际PricingPanel→本机HTTP→原非owner API→PG/S3验收，与原内存对象机制用例分别标识，详见[记录](../04-验证与测试/报价历史原生验收.md)。

## 组合验证入口

`TEST-WORKSPACE-JOURNEYS`通过实际App、本机HTTP代理、原生API/Worker与PG/S3验证既有业务切片。测试助手不加入应用路由；通知由原有tasks.runs.notify生成，取消由既有Worker reconcile(once=True)恢复，不复制业务状态机或替换权威函数。详见[四组记录](../04-验证与测试/工作台四组原生组合验收.md)。
