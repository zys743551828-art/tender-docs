# 身份与检索的归档边界审计

本记录审计 observed 中的九个精确输入；普通业务 07 仍在开发，因此本记录不是其集成通过证明。

| 入口 | 归档后行为 | 当前源码证据与后续动作 |
| --- | --- | --- |
| 企业主体登记、个人默认主体 | 允许；不绑定某个已关闭项目 | 全局目录或成员个人选择；不回写任何既有实交身份 |
| 项目身份更正 | 明确原因、强 ETag、命令幂等后允许追加更正 | bid 行锁、identity.bound 新审计、递增 revision、失效待处理建议；at_time 和已冻结评审/实交不从新 profile 重构。07 需在 command 前调用公共 RC 守卫 |
| 项目检索与旧检索重放 | 允许只读查证；失效来源不可当当前依据 | 首段、末段与 replay 均校验新鲜 RC；模型 RPC 外无 DB 锁，最终 source graph 效力复查。history 目的只是历史阅读，不产生正式评分资格 |
| 项目可读解析的向量/词法派生索引 | 允许，必须以派生用途排程并可见 | index-parse、rag.index_scheduled；只派生 source/chunk/embedding，不更换正文/规则/评审；发布仍需 Worker fence 和新鲜 RC。07 统一发布守卫要保留此例外 |
| 企业知识索引 | 允许；origin 项目归档不应使企业资料永远不可检索 | item/原件/祖先来源效力仍受 lock_graph 的 RC 与撤回检查；不得借派生索引新增发布内容或业务决定 |
| 新正文、规则、应用生成建议、生成任务 | 关闭/终止/归档时拒绝新增工作 | 由各生产入口和最终发布环节的普通 work 守卫控制，不以全局 enqueue 禁用替代 |

当前观察没有调用外部服务、修改业务资料或运行付费模型；未执行端到端验收。实现新增守卫的并发与幂等行为由 07 冻结后独立验证。
