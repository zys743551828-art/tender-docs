# PRD 逻辑检查与场景验证

文档编号：VAL-PRD-001  
类型：产品规格审查、反例推演与设计约束检查

## 1. 对象、方法与证据边界

审查对象为 [AI 投标工作台 PRD](../02-业务与产品/AI投标工作台PRD.md)。检查项目、会话、任务、知识、历史档案、评分标签和模型之间是否存在状态冲突、身份混用、无法完成的路径或信息泄漏。

使用三类方法：人工走通端到端路径并提出反例；把关键决策抽象为可执行规则，与手工指定的反例期望对照；检查需求、场景、章节和本地文件链接是否完整。为检查反例的有效性，另主动注入错误规则，确认反例能够发现它们。

本次没有改应用实现，没有执行这些新增能力的软件验收，没有调用真实模型，也没有新增真实评分样本。下文“修正”指规格已经补齐，“通过”仅指相应文档／抽象规则检查。它不证明软件已经遵守规则，不证明真实预测精度，也不代表业务方已接受建议的精度目标。

| LC-14 | 按原文接受是否绕过全部检查 | 只放宽规则人工确认；核心覆盖、版本和阻断问题不放宽 | 7.4、10.3 |

| LC-20 | 公司台账、综合分、未知分、被否决是否混入正式标签 | 来源分层，正式主验收与在线统计严格核验；未知不填零；技术综合分开 | 13.1、13.2 |
| LC-21 | 用户已在聊天中看过成绩，再评分是否读到标签 | 正式评分另建结构化白名单输入，隔离带分摘要、工具结果、索引和缓存 | 8.3、13.3 |
| LC-22 | 测试案例是否通过企业知识、近重复案例或未来锚点泄漏 | 全通道遵守项目／模板连通分组与时间限制，记录来源和实际检索清单 | 13.3、14.2 |
| LC-23 | 后来上传的稿件／回测是否冒充实际稿／事前预测 | 分别记录实际提交与可核验时间；回测独立标记；不事后挑最接近的一次 | 10.4、13.4 |
| LC-24 | 时间只保存上传时间，是否错误拒绝历史原件或接受事后改稿 | 发布时间、生效、取得与录入分开；未知不推断，核实实际版本 | 13.4 |
| LC-25 | 双击、重放、他人修改后旧卡是否重复写入 | 服务端幂等和版本检查，旧卡失效；重新登录不自动执行未确认操作 | 8.1、16.1 |
| LC-26 | 错误标签修正后，训练模型和提炼知识是否仍受污染 | 追踪提交、统计、实验、模型和知识；暂停受影响的新增使用，保留更正链 | 14.3 |
| LC-27 | 分数隐藏开关是否只隐藏页面，聊天与导出仍泄露 | 跨入口遵守同一设置，后台预测回流与数值展示分开 | 7.4、15.2 |
| LC-28 | 删除会话或原件是否造成知识与评分证据失联 | 展示删除与物理清理分开；有依赖原件不直接删除，恢复验证关系与摘要 | 17.1、17.3 |
| LC-29 | 新PRD是否把原型或新增状态写成已有后端能力 | 文档开头区分目标与实现，第19节列契约及运行缺口，实施必须同步测试 | 1.1、19.1 |
| LC-30 | 建议精度或性能指标是否被默认为已认可、已验证 | 建议、测量方案和发布门槛分开；最终测试前冻结，不依据测试调目标 | 9.5、16.2、20 |
| LC-31 | 缺正式成绩时，项目是否能从已提交结束并归档 | 人工结束不要求成绩完整，归档仍显示待补；补录不改冻结稿 | 5.1、5.5 |
| LC-32 | 新模型是否借旧模型的大量在线配对获得精度资格 | 默认按方法版本和适用范围看有效分母，跨版本汇总不授予新模型精度 | 9.4、15.3 |
| LC-33 | 空库是否阻塞首个项目，早期入库是否没有备份 | 空库可直接做当前项目，未配置模型明确失败；真实入库即启用基本备份，正式恢复仍须演练 | 3.4、19.2 |

上述处理是设计层面的取舍。仍需真实投标人员验证主会话、卡片和事实补录是否容易理解，真实案例验证规则与评分能力，正式环境验证持久化、并发和恢复。

### 2.1 融合方案三轮核对

三轮分别检查业务流程、跨模块状态和完整任务反例；每轮在修正后运行文档与抽象规则检查。机器记录见[fusion-review-rounds.json](prd-checks/fusion-review-rounds.json)，各轮记录保留核对前后输入摘要、问题、修正落点、场景及当轮结果文件。第三轮最终一致性核对补查了生成动作，之前结果单独保留为中间检查，不替代终轮结果。前两轮结果是当时规格快照，不能当作终稿全部通过的替代。

| 轮次 | 核对重点 | 已修正规格问题 | 新场景 | 当轮结果 |
| --- | --- | --- | --- | --- |
| 第一轮 | 业务范围、入口、主要动作、自动评审与交付依赖 | 5项：默认落点冲突、动作优先级、多文件重复触发、逐章汇编范围、A1/A2依赖 | AC-112—AC-116 | [第一轮检查](prd-checks/fusion-round-1-result.json) |
| 第二轮 | 草稿／文件／评审／实交身份、保存与取消、来源及接口 | 6项：未保存生成旧稿、当前指针混用、Word/PDF对应、取消竞争、失效来源应用、编辑构建契约缺口 | AC-117—AC-122 | [第二轮检查](prd-checks/fusion-round-2-result.json) |

## 3. 六条连续路径推演

| 路径 | 连续操作与关键分支 | 必须落下的持久结果 |
| --- | --- | --- |
| 新项目至提交 | 上传→补缺→评审→证据→建议→预览应用草稿／外部修改→生成或上传V2→复评→规则确认→标准登记；中途关闭浏览器并返回 | 每轮输入与结论、采纳决定、V2有效复检、真实提交与当时预测分开保存 |
| 线下历史资料至配对 | 拖入批次→分组预览→处理主体／终稿歧义→有据补录提交→核验正式技术分→归档；重复批次重跑 | 独立样本不重复；未完整检查身份可见；无当时预测则不进事前误差 |
| 知识引用至失效 | 项目提炼候选→人工确认发布v1→新项目引用→编辑v2→停用错误v1→查看影响 | 项目不自动变知识；旧引用可还原；运行中结果受影响；在办项目有复核入口 |
| 评分至正式成绩 | 盲预测→登记实际稿→取得成绩→核验→计算合格对照→训练候选→独立测试→观察→发布 | 没有通过验收不切业务；范围不匹配不套精度；标签不进入事前输入 |
| 错误成绩至模型回退 | 发现成绩冲突→暂停配对→有据追加更正→定位实验模型知识→暂停新增使用→复核→决定恢复或回退 | 旧分、旧预测与旧报告保留；有效统计重算；更正不计新独立样本 |
| 全新入库至备份恢复 | 空库初始化→新资料dry-run→核验出处与关联→独立备份恢复→核对摘要与引用 | 不要求旧系统迁移或兼容；新身份与业务关系完整，资料入库不授予模型资格 |

路径已做规格推演；未在应用中逐步执行。详细可执行验收清单见第 7 节，每条软件执行状态均为未执行。

## 4. 可重复检查方法

在仓库根目录运行，Python 标准库即可：

~~~sh
python 04-验证与测试/prd-checks/check_prd.py --output /tmp/prd-review-result.json
~~~

场景主数据为 [scenarios.json](prd-checks/scenarios.json)，手工指定期望的抽象规则反例为 [design-fixtures.json](prd-checks/design-fixtures.json)，检查程序为 [check_prd.py](prd-checks/check_prd.py)。修改场景后可通过下列命令重新生成本文的场景与追踪部分：

~~~sh
python 04-验证与测试/prd-checks/check_prd.py --render-scenarios --output /tmp/prd-review-result.json
~~~

终稿可同时核对三轮输入、修正与检查结果身份：

~~~sh
python 04-验证与测试/prd-checks/check_prd.py --check-review-rounds --output /tmp/prd-final-review.json
~~~

该选项检查三轮输入前后衔接、每项问题的有效章节及场景、各轮检查结果摘要，以及终稿是否仍对应第三轮输入；不能证明自然语言语义或软件实现正确。若终稿输入变化，应针对影响重新核对并保存新证据，不能悄悄改摘要使旧记录冒充当前通过。

检查覆盖以下范围：

- 40项FR、14项NFR定义与128条验收场景的追踪、字段完整性、章节和本地文件目标；不请求远端链接。
- 76个手工指定期望的正反例，包括核心闸门、事实补录、知识引用资格、评分展示、样本、事前配对、模型发布、比较、归档条件与量尺。
- 标准提交128种前提组合、评分数值展示128种组合、知识状态／适用／有效组合40种、任务完成顺序与成败8种。
- 四类生命周期图的可达性、未知状态及终态不允许的转换。状态图只涵盖同一对象版本／任务尝试，转换保护条件仍需实现测试。
- 13类故意错误的规则是否会被反例识别，包括部分分外推总分、20组授予验收、待核验成绩准入、新冲突回退旧分和带分聊天入模。

检查不会读取自然语言后自动证明全部业务含义一致。抽象规则自身可能遗漏条件，人工反例可能不完整，输入与实际实现可能不一致；因此保留真实软件验收、专业标注与独立评测门槛。

## 5. 验证结论与未验证范围
