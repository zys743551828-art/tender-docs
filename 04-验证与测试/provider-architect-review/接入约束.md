# DeepSeek与杭州OSS增量架构约束

本轮只读review适配器、配置身份、对象完整性和调用预算，不修改前批设计／实现证据。连通测试不授予完整A1、RAG或正式评分资格。架构角色不执行付费chat、不读取或输出secret内容；测试角色按PM统一额度执行最多一次极短chat及合成对象探针。

## 1. 配置与资料身份

- 现有dev／QA数据库及其S3引用保持原解释。远端OSS验证使用独立进程配置与专用合成命名空间；不能复用现有DB仅切全局backend／bucket，把原blob.object_key解释为另一个存储中的对象。
- 共享DB若正式引用多个存储，须先有持久、不可变的storage profile／对象locator，明确backend、endpoint区域、bucket、key及可用version／checksum身份。应用按对象绑定身份读取，不能依赖当前环境的全局默认值。该能力未实现前，远端验证与本地数据隔离。
- providers.env权限600，被Git忽略；运行进程只注入所需凭据。公开结果仅列配置名、非敏感provider／模型／region、固定端点及能力状态，不输出密钥、签名URL查询串或请求头。
- 原生OSS接入及新模型适配是新系统正常建设，不增加旧库迁移、旧接口兼容或旧模型资格承接。

## 2. HTTPS、代理和错误

- 服务端只接受已配置的官方DeepSeek HTTPS及杭州OSS HTTPS端点，不从浏览器或文档内容接收任意endpoint。
- 保持TLS验证、运行环境代理及CA信任；不使用verify=false、跳过证书验证或更换外网直连绕过配置。
- 异常输出限错误类别、可重试性和安全的provider request ID；不直接记录含URL／签名／请求头／原文的SDK异常repr或完整响应。

## 3. 原生OSS对象与签名

- get／head／put／sign以明确bucket及受控key为参数，兼容现有存储端口的响应形状，不把ETag、CRC或声明SHA当成业务字节SHA。
- 写前用实际字节核算SHA及长度；读取／核验以真实返回字节复核。HEAD的元数据语义须明确，不能因存在任意checksum字段就认定内容身份正确。
- 正式对象禁止静默覆盖，应使用实际供应商支持并经验证的条件写或明确版本身份。仅对随机合成前缀验证第二次同key写入的拒绝／版本行为，不触碰bucket既有对象。
- PUT签名所含Content-Type等头与实际调用一致；授权期限有界，正式内容不开放浏览器PUT授权。get、head、过期、缺失、权限和条件冲突分别返回明确状态，不用空字节冒充成功。
- 不改bucket版本控制、CORS、ACL、生命周期等全局设置；合成探针若需要额外能力而未具备，应报告未验证，不修改用户存储策略来取得绿色结果。

## 4. DeepSeek调用与资格

- 显式限定provider、请求model、返回model、用途、输入／输出上限、超时和方法配置；provider可用与业务review已配置分开。供应商可变模型别名不能冒充已冻结且独立验收的正式评分方法。
- SDK内部自动重试关闭，例如OpenAI兼容SDK显式max_retries=0；重试由持久logical call及总预算统一管理，不能与Worker重试叠乘。
- 本次一次极短chat只作连通与真实响应形状验证，不带投标资料、不触发三次评分判断或额外修复请求。超时／连接中断可能已计费，应保留unknown及对账身份，不自动补发。
- 限定连接和读取／总时限；输出截断、空选择、错误结构、限流或认证失败如实返回。不将短探针成功写为正式评审、预测、模型发布或数据资格。

## 5. 候选复审所需材料

开发提供冻结源文件及摘要、实际配置选择路径、依赖锁、接口与错误映射、secret脱敏规则及存储身份隔离说明。测试提供固定输入／用途、实际调用次数、对象前缀、字节摘要、条件写和读回结果，以及未测范围。架构师核对实际源码与证据身份后给增量结论；需要改变共享DB定位协议时先由PM组织最小设计收口，再修改实现。
