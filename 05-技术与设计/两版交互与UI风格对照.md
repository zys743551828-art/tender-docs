# 两版交互与UI风格对照

交互结构优先吸纳 Codex，基础视觉规范优先沿用当前 dev 的语义颜色、字体、组件和密度控制。Codex 的产品方案更完整，不代表其所有页面排布都更好；当前版本更简洁，也不代表它已经承接章节编制和连续工作的交互。

项目定位为整份投标标书工作台，施组为技术部分。品牌名称和入口应按该定位表达；本次是对照与取舍建议，未修改产品 UI、分支或运行环境。

## 1. 比较依据

当前 dev `45a5921`：通过内置浏览器只读查看合成项目列表及报告，并检查 `styles/index.css`、AppShell、ProjectNav、Button、Dialog、报告、资料和助手组件。Codex `27bc639`：查看归档桌面／手机原图及 styles.css、WorkspaceNavigation、AssistantDrawer、SectionEditor 等源码。共查看 10 张归档原图和 2 张当前截图，7 张代表原图保存在[对照截图](交互对照截图/sources.json)，复制前后字节一致。

归档原图来自不同阶段和显式合成状态，部分为完整长页；当前为现有桌面窗口截图。屏幕尺寸、数据量和状态不一致，比较的是布局和交互表达，不按同屏行数推导性能，不把某张早期错误图当 Codex 当前整体能力。手机、深色和键盘的部分判断来自实现，未进行两套相同设备的完整可用性测试。下表“更好”属于基于这些依据的设计判断。

## 2. 视觉风格与组件

| 维度 | 当前 dev | Codex 分支 | 取舍建议 |
| --- | --- | --- | --- |
| 整体气质 | 中性灰白底、深松绿强调，接近紧凑的专业工具 | 带绿色调的浅底、较大标题和面板，工作台品牌感更强 | 当前做基础规范，Codex 的品牌和工作区层级可保留 |
| 产品命名与品牌 | 显示“施组工作台／技术标评审与报价” | 显示“投标工作台”，品牌更符合整份标书 | Codex 更贴近范围，统一为投标标书工作台相关命名 |
| 颜色体系 | 主色 #0d5c55，红／橙／绿／靛蓝分别表达危险、待核对、成功、AI | 主色 #176b50，绿色及浅绿面板应用更广 | 当前语义分工更明确；绿色不同时承担 AI、成功和主要操作的所有含义 |
| 字体一致性 | Inter 与 Noto Sans SC 实际打包，中文跨设备字形较稳定 | Inter／系统中文字体栈，中文由可用系统字体决定 | 优先当前字体配置，不以字体库名称代替真实可读性检查 |
| 标题层级 | 页面标题约 20px、卡片标题紧凑 | 全局 h1 28px，品牌和工作区标题更醒目 | 概览可用 Codex 的标题感，编辑／核对任务采用当前紧凑标题 |
| 正文与辅助说明 | 正文 14px，大量辅助信息 12—13px，紧凑但复杂解释易显小 | 正文 14px、较宽行距，仍有很多 10—12px 状态说明 | 两边都需让关键依据和错误说明保持可读，不能把重要局限压成小灰字 |
| 留白与密度 | 列表、矩阵和指标更集中，首屏较快看到风险与动作 | 标题、返回、工作区导航和大面板占用较多纵向空间 | 评审／列表优先当前；编辑正文保留 Codex 的阅读空间 |
| 卡片和分组 | 细边框、小圆角、轻阴影，分组较克制 | 较大白色面板、浅绿区块，层次清晰但部分页面嵌套较多 | 当前卡片规范；减少一段说明单独占一个大卡片 |
| 主次按钮 | 组件区分实心、描边、无框、危险，默认次按钮 | 有主／次按钮和文字操作，但部分长页操作密集 | 当前按钮规则，单个任务区只突出当前主要动作 |
| 图标 | 统一图标组件，导航图标语义较丰富 | 有统一 SVG 图标，但基础图标集合较少 | 统一一套图标规范，避免多个模块继续各自补图标 |
| 表格和数值 | 明确 data-table、等宽数字、行状态与图标，适合核对 | 档案／资料有清晰表格，更多业务转为长面板 | 保留当前数值与表格规范；长解释按需展开，不挤进表格 |
| 深色与主题 | 浅／深色语义令牌、浅色／深色／跟随系统入口 | 检查的主样式和入口未发现对应完整主题体系 | 当前实现更完整，纳入统一视觉规范；Codex 深色运行态未测试 |

## 3. 导航与页面操作

| 维度 | 当前 dev | Codex 分支 | 取舍建议 |
| --- | --- | --- | --- |
| 全局与项目导航 | 进入项目后侧栏切为项目导航，三常用入口加更多 | 全局侧栏保留档案／知识等，项目内横向工作面导航 | Codex 的全局／项目层级更适合完整工作台；默认可见入口采用当前克制原则 |
| 页面数量与发现性 | 常用入口容易找，高级工具收起；没有编制入口 | 编制、矩阵、事实、报价、实交等可直接访问；横向项目入口较多 | 日常突出资料、编制、评审、提交；其余分组或更多，避免手机靠连续横滑找功能 |
| 项目列表 | 风险、预测、状态和下一步同一行，适合批量处理 | 归档图有搜索框、阶段、资料和下一步，项目身份较醒目 | 当前行内风险效率，加 Codex 的搜索／身份能力；不同图的数据量不用于密度打分 |
| 报告首屏 | 结论、风险数、评分与主要下一步集中呈现 | 评审状态、当前稿身份、受检范围和历史表达更完整 | 当前结论排布，加 Codex 的当前稿与范围提示；详细执行说明折叠 |
| 主要下一步 | 已有主动作与剩余关键问题／其他建议折叠计数 | 有工作面级下一步、上下文导航和处理记录 | 两者已有共同设计，保持后端同源，界面一次明确一个主要动作 |
| 上传与用途 | 一批选择后核对用途、版本目标，上传和已上传分区 | 资料包／批次与归属确认较细，不同阶段入口能力不同 | 当前直观上传排布，加 Codex 的归属确认；按文件包而非最后一份正文组织 |
| 原件与证据 | 引文入口、就地展开原页、独立证据页及高亮 | 原件／解析文字并列大视图，抽屉或覆盖层保留原任务背景 | 核对时吸纳 Codex 并列查阅，保留当前精准引文定位；避免反复离开编辑位置 |
| 表单填写 | 常用字段少，更多信息按需展开，直接提交反馈 | 丰富对象和证据字段，能力更完整但长表单较多 | 当前默认简洁，加 Codex 的自动带入与有据字段，复杂选项折叠 |
| 下载与生成 | 报告 Word／批注 PDF 入口直接可见 | 生成用途、构建状态、保存版本、历史产物区分更细 | 普通下载采用当前直接入口；需要生成或选择稿件时采用 Codex 的明确状态 |
| 实交和成绩 | 复用当前稿身份，登记前检查可见 | 区分实交、检查、事实补录和来源状态 | Codex 状态模型为主，界面保留当前检查清单的简洁表达 |

## 4. AI 与编制交互

| 维度 | 当前 dev | Codex 分支 | 取舍建议 |
| --- | --- | --- | --- |
| AI 入口位置 | 报告侧栏的轻量卡片，内容多时栏宽有限；不是全项目持久工作台 | 各工作面可打开同一项目主会话抽屉，也有全页助手 | Codex 更适合持续工作；桌面建议可展开并排面板，手机使用抽屉／独立页 |
| AI 与正文空间 | 主任务优先，助手较轻；长回答和确认卡容易拖长侧栏 | 抽屉最大 760px 且覆盖背景，内容充分但会遮住任务 | 吸纳上下文和会话，调整布局；编辑时支持一边看正文一边看建议 |
| 连续讨论与草稿 | 单次提问，刷新清空；按钮快捷问答 | 主会话持久化、本地待发稿、回到最新、只保存讨论与实际请求分开 | Codex 明显更完整，保留“讨论”和“请求操作”的区别 |
| 来源选择 | 当前项目摘要、问题及规则上下文，用户缺少专门来源选择器 | 来源选择、用途和引用详情可见 | 优先 Codex；当前文件／版本显示保留，人读名称优先，内部 ID 放详情 |
| 确认卡 | 两类操作、勾选后正式执行，结构简单 | 动作状态、来源、版本、只读卡和后续处理更丰富 | Codex 的完整状态加当前紧凑卡片；执行结果以正式业务反馈为准 |
| 章节树与编写计划 | 自动章节用于评审，无正文编制工作区 | 树、编写计划、关联要求、模板和章节编辑 | Codex 交互基础更好；先收起新建／草稿管理区，让已选正文尽早进入首屏 |
| 局部修改与预览 | 问题级原文／替换建议，外部修改后重传 | 按节点和基准修订预览、应用／拒绝、恢复 | Codex 更贴合编写任务；差异要突出变化，不能只显示两大段相似文本 |
| 保存与冲突 | 普通业务表单有提交反馈，没有富文本保存流程 | 保存中／待确认／失败／已保存、本地恢复、服务器稿比较、合并 | 采用 Codex；复杂版本编号与技术状态可展开，保留用户需要的保存结论 |
| 文件与版本切换 | 上传稿、快照和本轮报告身份清晰 | 草稿、最新生成、当前评审、实际提交分开 | Codex 更完整；统一一处稿件切换，避免每块重复选择项目／草稿 |

## 5. 响应式与状态反馈

| 维度 | 当前 dev | Codex 分支 | 取舍建议 |
| --- | --- | --- | --- |
| 手机导航 | 源码为侧栏收起、顶部展开按钮 | 归档有顶部项目横滑导航，源码提示“左右滑动查看全部工作面” | 当前导航策略更省查找；整份工作台可用任务分组／更多，不能只靠横滑 |
| 手机编辑 | 当前没有可比较的正文编辑器 | 390 图中目录、草稿管理排在正文之前，页面很长 | 以 Codex 为能力基础，目录改抽屉／选择器，正文优先；不能据缺少编辑器判当前更好 |
| 长对话 | 当前单次回答较短，复杂持续任务承载不足 | 有“回到最新／继续提问”，但历史、状态和多块说明仍占较长空间 | 采用 Codex 续接；历史折叠，输入区与当前回复优先，控制重复状态提示 |
| 加载 | 骨架占位和状态文字 | spinner 与文字，复杂面板分区加载 | 当前骨架适合列表；保留 Codex 对每项实际任务状态的表达 |
| 空状态 | 图标、短说明、直接动作，重点较集中 | 有受限能力、无资料、无来源等更细的状态表达 | 当前视觉模板，加 Codex 的明确条件；不把空状态做成长期说明页 |
| 错误与恢复 | 统一错误提示、后续动作、重试，较紧凑 | 错误码、追踪编号、保留本地稿与恢复入口更细 | 采用 Codex 恢复能力，正常界面用简短业务解释，技术码与长原因放详情 |
| 折叠和说明 | 风险与其他建议区分，详情按需展开 | 状态限定充分，但部分截图连续多段说明、小灰字较多 | 保留必要状态，摘要说明影响与下一步；重复机制说明收起，不删除重要缺口 |
| 键盘与弹层 | Radix 对话框、焦点恢复、命令菜单；减少动态效果 | 抽屉有 Escape、Tab 焦点循环、关闭后焦点恢复；减少动态效果样式 | 两边均有具体实现，不按组件库直接判胜负；统一行为后实测读屏／键盘 |

## 6. 推荐的统一形态

桌面保留 Codex 的全局项目／档案／企业资料结构，进入项目后围绕资料、编制、评审、提交组织常用工作面。顶部项目身份紧凑显示，避免标题、返回、标签和说明连续占满首屏；以版本选择明确当前正在编辑、查看和评审的稿件。

编制时中间为正文，章节树按需展开，右侧 AI／原文查阅面板可收起或调整空间。来源与建议不迫使用户离开正文。报告时中间优先风险与主要动作，右侧助手默认较轻，长讨论可展开。手机采用一个主要工作面加目录／来源／助手的抽屉，避免把桌面多个栏简单上下堆叠。

视觉统一采用当前的中性背景、松绿主色、语义状态色、字体和按钮／卡片／表格令牌，吸纳 Codex 的工作区身份与更醒目的概览标题。色彩、间距和字体属于统一规范，不能按模块来源各保留一套。产品名称按整份标书定位统一，不继续使用“施组工作台”作为系统总名称。

这是一项设计取舍：交互能力采用 Codex 的完整性，日常操作采用当前的简洁表达。页面实现后还需按相同项目、相同窗口、正常／失败状态和桌面／手机完成整轮可用性核对。
