# 手动备份与隔离恢复早期架构审查

本轮未发现所审范围内的架构阻断，可以进入独立QA。通过范围限**手动开发环境快照、隔离恢复及只读检查的代码与机制**；没有宣布生产备份、真实OSS完整恢复或恢复写流量通过。

输入清单 `backup-recovery-development-checks/candidate.json` SHA256 `7401040e20e035d7140f95a5809869a0ab67aab92355f665f8815f7b7dcd2d66`。3源及3份storage运行依赖逐项匹配；开发result SHA为 `a99c824a…`，与候选引用一致。绑定信息在 `initial-inputs.json`，只读副本在 `observed-inputs/`。开发5项真实PG/OSS自测是开发证据，本轮没有将其改称独立QA。

## 关键边界判断

源数据读取使用非owner API LOGIN，拒绝superuser、BYPASSRLS及直接表owner。导出事务为REPEATABLE READ READ ONLY，inventory、blob引用清单及pg_dump共享pg_export_snapshot，转储在导出事务关闭前完成。完整数据库dump保留pgvector实际安装schema；没有借源库owner读取业务数据或为备份提升源角色权限。

数据库与对象采用同一快照的blob清单。对象只按清单GET，核实际长度与SHA；不列桶、不写源对象，不以ETag代替SHA。档案位于私有目录，目录700、文件600；dump、manifest及每个对象分别校验，拒绝symlink与路径/权限异常。manifest SHA明确仅检测意外损坏，不认证不可信dump；owner恢复仅面向操作员自己生成并保管的档案。

恢复始终创建新的随机数据库，不接收现有目标库名。初始化owner仅建库、pg_restore和新库权限收紧；恢复过程中未修改源库的表/函数权限。新库撤销应用能力角色写权限及函数执行，API仅保留SELECT，并设置默认只读；再用非owner连接关闭只读默认值执行实际INSERT拒绝探针。恢复对象写入新的restore-drills UUID前缀，逐个回读SHA，并将恢复数据库中的blob引用与档案清单逐项对照。没有启动API、relay或Kafka消费者，没有让历史操作自动重跑。

## 本轮独立验证

`probe_snapshot_restore.py` 在临时独立PG17执行真实pg_dump/pg_restore，使用非owner API读取源数据和检查恢复数据；owner仅用于新夹具初始化、建恢复库及权限配置。对象端口明确使用内存夹具，未连接真实OSS。

- 在导出快照之后，用另一非owner会话提交合成成员。源库能读到该提交；manifest及实际恢复出的数据库均不含它。
- 实际比较104张表及1个blob引用；对象通过独立演练前缀回读校验，源对象夹具未改变。
- 源API的INSERT权限在恢复前后均保持；新恢复库默认只读，关闭只读默认值后INSERT仍被权限拒绝。
- 不启动API/relay/consumer；临时PG及内存对象已随夹具清理。
- 档案损坏、对象损坏、symlink、公开目录权限4项离线测试通过；真实profile集成测试明确跳过，未读取用户凭据或实际私有档案。

结果为 `snapshot-restore-mechanism-result.json`。真实外部对象请求及收费调用为0。

## 后续验收范围

独立QA仍需绑定同候选，验证真实OSS隔离对象、实际source profile与恢复检查环境，不能直接沿用开发5项结果作为独立通过。当前工具没有生产RPO/RTO、WAL/PITR、静态加密、远端持久化/跨故障域保留或自动化调度的验收；也没有恢复Kafka offset、废止旧fence、Outbox重新派发及开放写流量的协议实证。

这些限制已在实现说明和开发结果中明确，属于后续生产恢复范围，不因未实现而记作本批手动隔离演练的代码缺陷。恢复收据中的数据库和对象前缀必须用于后续检查；不能拿这份离线恢复库直接恢复业务写流量。
