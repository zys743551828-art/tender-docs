## 代码差异与事务边界

fixture 补齐真实 review_inputs 的 evidence_manifest_blob_id、manifest_digest、as_of、evaluation_context_digest 四个非空列；均为明确合成恢复夹具，不构造正式评分资格。七个新 UUID 对象先将完整 key/SHA/size 清单写入不可覆盖私有文件，再调用对象 PUT；业务数据库 INSERT 仍在单一普通 API 事务内，失败自动回滚。对象写入与业务事务不是原子操作，未引用对象保留、不扫桶或删除。

seed_retry 只从受控私有原 attempt 读取原 plan、初始化和23502失败收据，核 baseline 摘要、固定源码、Docker 容器ID/label/image/端口/数据卷，以及真实 backup-reader 的身份和权限。全表逻辑行数须为空，仅 recovery_control.identity 允许一行，并要求原临时 DDL 角色已完成撤权标记；还执行真实角色权限探针。新 attempt 目录及输出使用新建不可覆盖私有文件，不修改原失败收据，不重新建库/初始化/改角色。重试仅执行 API 身份的合成 seed，随后用 reader 读取定义与摘要。

该入口用于当前独占、非公开的自有演练源，实际执行应保持这个独占条件。全空预检与 seed 不是一个事务，不将它解释为并发生产库的通用安全重试器。

## 串行演练边界

协议保留1600/900MiB门槛。源完整 snapshot/同快照 dump、全部对象字节及目录/ACL/角色/当前hash先落档；停止之前再次核当前源逻辑状态、PG system_identifier、资源label和原卷。只 stop/rm 已核准的自有容器ID，不带 -v，不删除卷、凭据、对象或档案。目标使用随机独立新资源，创建前再次核空间并等待 PM 窗口。

目标验证期间源离线，必须将 source-after-target SQL 核验标 pending。随后停止目标容器保卷，再从保留的原源卷启动同一PG集群，核 system_identifier/nonce/reader身份、定义及逐表摘要；记录新旧容器ID映射，不覆盖旧 receipt。完成此步骤之前不得写 source_after_target_verified=true。禁止启动消费者、续跑旧队列或重发未知费用调用；实际API验收只允许暂停封装器内单命令/单新UUID同步白名单。07固定范围不自动扩展到新评分/量尺/A2组合。
