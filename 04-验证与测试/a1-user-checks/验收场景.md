# A1用户任务验收场景

**状态：验收准备，A1新增路径均待实际执行。** 由用户视角角色独立准备，不修改产品规格，不把模拟角色当作真实投标人员，不沿用首个PDF资料切片的通过宣布完整A1通过。实际前端候选具备后，只对其已交付路径做浏览器走查并另存结果。

依据：[当前PRD](../../02-业务与产品/AI投标工作台PRD.md)第3.4—3.7、7、10.1—10.4、13.1、18.3、19.2节；产品Owner的[实现验收清单](../implementation-product-review/README.md)；原[13项应用任务](../design-remediation-checks/application-acceptance.json)。本文件只把这些约定转成可理解的用户任务，不另设业务门槛、状态枚举或审批。

## 1. 必须保留的最短流程

假设使用者已有市政投标Word／PDF，时间紧，先保住否决／强制项，再决定先改哪里。新手需要明白当前稿和下一步；熟手需要原件、旧稿和失败后继续工作。这些是假设，不是访谈结论。

**上传招标和现成正文PDF→只核影响本轮的身份／资料歧义→自动评审与真实进度→关键风险及一个主要下一步→核对两侧原页→外部改稿后上传PDF新版本并实际复检→提交前集中确认剩余阻断项→有据登记实交稿。**

这是一条业务路径，不是测得的点击数。无歧义时不插确认；不要求先建知识库、目录、模板、任务或在线章节。明确按钮不再重复聊天确认，评分不可可靠估分不单独增加核心登记阻断。实际交易平台提交由人完成，系统仅记录真实稿件、时间与凭据。

准备无敏感内容的合成招标、正文V1／V2与补遗，含两项可独立核验的关键问题、普通建议、纯评分缺口与明确原页；必要时由测试角色提供已知失败／未配置夹具。数据、模型适配及执行环境须标真实或测试，不能把脚本化判定说成真实检测效果。本角色不读取密钥、不调用付费模型、不变更服务配置；故障由测试／开发在独立夹具中注入。

## 2. 核心任务与观察点

向执行者给任务，不提示按钮位置；先记录实际动作，再检查下列观察点。表内预期是未来验收要求，全部待执行。

| 编号 | 任务及前置 | 必须能看懂并完成 | 不能出现的误认／额外负担 |
| --- | --- | --- | --- |
| AU-01 | 有招标及正文PDF，开始检查 | 直接上传，只集中处理影响结论的身份／角色歧义；本批成功资料保留，批次齐备按设置只受理一次 | 先配置知识／模板／编辑器；逐个文件重复发起模型评审；要求重传成功文件 |
| AU-02 | 评审已经受理，离开后回来 | 看到固定稿件及真实阶段；重开或刷新找回原任务／产物；未配置与失败给具体影响和下一步 | 文字停止即成功；重新打开造成等价任务重复；无模型时填充演示风险或分数 |
| AU-03 | 两项关键风险与若干建议，先处理最重要的一项 | 简洁结论及一个主要动作；全部问题和矩阵可找到，处理第一项后能发现第二项并区分普通建议 | 折叠后无法发现关键问题；只因提交最后拦住就判信息易懂；把任务结束当全通过 |
| AU-04 | 对某条风险有疑问，要查依据 | 切换招标原页与当前正文；看到文件／版本／物理页、实际检查范围；返回原问题保留位置 | 跳错新旧稿；缺失型问题伪造正文引文；强迫到全局聊天查依据 |
| AU-05 | 需要外部改稿，或认为该项是误报 | 可取修改依据、确认／暂缓／有理由驳回／重新打开并留真实状态；外部Word改后导出PDF回传新版本，复检后看到真实解决或未复检 | 采纳／说“改好了”或手动按钮直接标已解决；暂缓解除阻断；旧报告丢失；进入在线编制成为必经步骤 |
| AU-06 | 已完成核心核对，要登记确实提交的正文 | 提交前集中确认剩余核心规则／事实；指定稿件与评审身份明确；点击时重查；仅剩非阻断建议或纯评分缺口仍可按条件登记 | 重复聊天确认；把可登记当交易平台已交成功；用旧评审放行新稿；评分模型未验收变成投标人员必配步骤 |
| AU-07 | 线下已提交，但当时没有完整系统检查 | 独立有据补录，记录实际稿件／时间／来源／缺检查原因；持续显示未完整检查，之后可按范围补评 | 被迫伪造通过才能记事实；事后新稿取代实交稿；补造当时预测 |
| AU-08 | 要取得修改依据与投标正文 | 按用途取得评审报告、批注审阅稿和原正文，文件名／详情及版本可辨，实际下载字节正确 | 仅打开预览却说已下载；格式名代替用途；报告／批注当正文；额外泛化确认；A1被迫先有正文生成器 |

AU-08只对候选已声明支持的格式执行取件，未交付报告／批注不能沿用既有原件下载通过。DOCX输入／转换未接入时，应明确只支持PDF并保留外部导出路径；接入后执行下文AU-R06，不把Word当作快速PDF的前置格式。

## 3. 必须能继续工作的恢复反例

| 编号 | 具体触发 | 可见状态与最小继续方式 | 禁止结果 |
| --- | --- | --- | --- |
| AU-R01 局部失败／覆盖 | 必要页漏读、单条模型失败，或人工标注11项但只提取10项 | 成功部分保留；来源读取、条款提取、已识别核对、评分覆盖及人工确认分开；能打开失败／疑似漏提范围并恢复 | “10/10”宣称原文零遗漏；零条成功当满足；失败变0分／半分／旧分；无效引用成有效结论 |
| AU-R02 版本竞争／迟到 | 两个成员上传竞争稿，或V2／补遗到达后V1才完成 | 原件／草稿保留；冲突能核对新目标后继续，无需重传；旧结果标历史／过期，当前任务仍指向新输入 | 最后完成抢当前；旧卡覆盖新稿；让用户从头上传整批 |
| AU-R03 已知风险与开关 | 关键矛盾已发现，关闭可选检测并再评审 | 问题仍在统一清单和提交检查中可定位可处理，本轮写未运行；有效复核或有理由驳回后按真实状态结束阻断，留历史 | 关闭或零新发现洗掉问题；看不见的风险持续阻断；已驳回仍被该问题阻断 |
| AU-R04 人工补漏与存续 | 发现漏提，补充并确认；再提取时模型又漏掉；另造来源效力变化 | 一次明确补充校验通过后新包及人工确认，旧评审过期给复评入口；不代表正文满足。错误／歧义保留输入且不部分写。有效人工要求延续并去重；效力不明留待核验，有据替代可结束义务并留历史 | 二次确认／岗位审批；部分保存却称确认；人工要求静默消失；失效条款永久当有效阻断 |
| AU-R05 补遗关系 | 明确替代、局部变更、互相矛盾三组补遗 | 打开变化原页，定位影响及未知范围；仅确认有依据关系；不明时留待核实，保留人工修改 | 按上传顺序猜；把局部定位当整稿通过；要求用户配置通用规则引擎 |
| AU-R06 DOCX恢复（条件执行） | 已接收Word后解析／转换失败 | 原文件处明确原件已保存、对应检查未完成，能“上传此修改稿的PDF”；沿用项目／改稿来源，PDF独立版本及受检身份明确 | 重传招标；强制编辑器；不同格式强行同逻辑版本；同名即认证同稿；PDF通过等于Word交付已检查 |
| AU-R07 纯评分与核心混合 | 核心有效但纯评分失败；另一夹具中同条款兼有否决条件且其核心核对失败 | 前者保留评分缺口且按核心条件可登记；后者能定位核心阻断。A1、研究可运行、模型业务验收分别表达 | 评分失败一律阻断；核心失败当纯评分可忽略；模型未验收仍给正式预测区间 |
| AU-R08 断线／取消／重登 | 网络断开、会话过期或取消与完成竞争，由测试注入 | 任务与待输入保留、当前身份可恢复；未确认决定不自动重放；取消请求和真实终态分开 | 关闭助手或断流即取消；重登自动执行旧确认；永久转圈或重复新建评审 |

AU-R02／R08的用户角色检查可见任务、输入与恢复，不从页面推断CAS、幂等、事务原子性或fence已被正确实现；这些由测试及架构另给证据。上传分片／重授权按对应底座交付范围执行，旧单传资料切片结果不能替代。

## 5. 浏览器交接与实际记录

收到前端可运行通知后，先取得候选清单／提交摘要、部署地址、功能边界和合成夹具；本角色不读取供应商密钥或自行启用付费模型。PM／测试提供安全测试会话和失败注入方式。只写本角色独立项目，不改其他成员资料或应用源码。

至少在桌面、390px及键盘下核AU-01、AU-04、AU-05、AU-06关键动作；手机不靠横滑找关键入口，原页／助手不同时压成多栏，返回保留焦点与对象。记录页面真实字样与截图，不以自动化click自动滚动成功证明入口可发现。复杂原页可读性、中文资源和内网加载需在相应运行条件实测。

每次实际记录包含：场景号、实现与输入身份、适配器类型、实际动作、可见结果、所需提示／卡点、截图或录屏、状态（符合／发现问题／待执行及原因）、限制。可复现障碍及时交PM、产品及对应开发；不自行降低预期。无变化部分不重复全量走查，修复只补受影响路径并绑定最终候选。

本文件新增浏览器执行数、真实用户数及付费调用数均为0。模拟角色推演、智能体实际浏览器走查、真人任务观察、真实检测质量、评分效果及生产验收分别留证；原PDF切片与设计审查结果保持原样。
