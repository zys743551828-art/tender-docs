# 评分预测训练与验收方案

本方案采用用户提供的四层路线：大模型读取完整相关章节并做有出处的判断，统计模型学习正式技术分，比较式锚定作为受控对照。业务规格见[工作台PRD](../02-业务与产品/AI投标工作台PRD.md)，运行设计见[全新系统技术方案](AI投标工作台全新系统技术方案.md)，样本口径见[数据管理规范](../03-数据与案例/数据管理规范.md)。全新系统独立建设，不以旧特征pf-1或旧模型文件契约作为复用前提。本文维护评分方法、数据、实验和验收；机制实测见[技术方案验证与自审](../04-验证与测试/全新技术方案验证与自审.md)，真实正式成绩精度仍未验证。

## 1. 预测目标与验收

预测目标是正式公布的技术总分，保留技术满分与评委聚合方式。综合总分包含报价、商务等影响，不能直接用作技术分标签；正式结果没有公布技术分的案例保留为无标签资料。被否决但未打技术分的案例也不能填成技术 0 分。实际公布的 0 分保留，并核实其计分原因。

训练和评测统一使用满分百分制：技术得分率 = 100 × 技术分 / 技术满分。产品展示时换回原量尺。百分制误差 3 分，对技术满分 60 分的项目是 1.8 分，对满分 5 分的项目是 0.15 分。除了百分制汇总，还按评分办法、满分和工程类型报告原量尺误差。

建议的业务验收目标如下，属于待确认的目标，不是当前精度或效果承诺。目标应结合开发集分差、成绩精度与评委分歧确定，在打开最终测试成绩前冻结；最终测试不达标就报告未通过。

| 指标 | 建议目标（满分百分制） | 用途 |
| --- | --- | --- |
| 平均绝对误差 MAE | ≤ 3 分 | 总体接近程度 |
| 绝对误差 P90 | ≤ 5 分 | 控制大误差，约九成样本在 5 分内 |
| 误差在 ±3 分内的比例 | ≥ 80% | 直接展示有多少案例预测接近 |
| 平均偏差绝对值 | ≤ 1 分 | 避免整体偏高或偏低 |
| 相对历史基线的 MAE 增益 | 项目组级 95% 区间下限 > 0 | 避免只预测平均分也看似准确 |
| 同输入整轮复跑的波动 | 百分制分数极差 P90 ≤ 2 分 | 控制使用时的分数漂移 |

这些指标分别检验，平均误差达标不代表大误差或稳定性达标。样本成绩高度集中时，还要报告同场排序、入围边界附近的误判和相对同场中位数的误差，不能只凭分数相关性判断有效。

80% 与 90% 预测区间分别核对实际覆盖率及宽度，报告抽样不确定性。区间过宽即使覆盖率高，也不能当作精度达标；区间宽度的业务上限要在最终测试前确定。未知评分办法、资料缺失或解析失败的样本应提示不可可靠估分，并统计覆盖率和失败率，不能只对成功样本报告精度。评委分歧和未记录的评分因素会形成不可预测的残差，有评委明细时单独量化。

### 1.1 相对位置与入围概率的验收条件

绝对分误差是第一类目标，相对位置和技术入围是独立目标，各自需要数据与验收。跨项目的分数高低不能代替同场排序。

| 可取得资料 | 可以验证 | 不能据此声称 |
| --- | --- | --- |
| 本公司一份正文及其技术分 | 该稿绝对分误差、跨独立项目的稳定性 | 已能预测同场全部名次 |
| 同场成绩表＋本公司正文 | 事后按实际同场分布对照本稿预测分；核验分差和门槛 | 把事后同场成绩分布作为事前已知输入 |
| 同场至少两份正文和对应分数 | 对已配对稿件做排序相关、成对顺序准确率；保留并列与样本范围 | 没有全体正文就推定完整名次 |
| 入围规则、实际结果、合格事前特征与足够独立项目 | 技术入围事件概率、Brier／对数损失、可靠性图和基线对照 | 将技术概率直接叫中标概率或全流程入围概率 |

排序在整个未见项目组上评测，报告可评项目数、每场配对覆盖和实际同场差值；同场分数接近或并列时遵守官方口径。只有一家正文时不伪造pairwise或完整名次指标。

门槛已知时，可以估计条件概率P(技术分达到该门槛)。门槛依赖本场竞争且事前未知时，需要独立建模门槛不确定性；不能偷偷使用事后入围线。按排名取前K、报价或资格筛选的流程另行定义目标事件，不用技术分一项替代。

概率模型与概率校准只在开发／训练来源中拟合，最终独立项目检验概率是否可信，并与训练期基准入围率比较。80%预测区间不能直接推出80%入围概率；缺少完整负例、未知结果或存在只收集入围者的偏差时，不发布未经证实的入围概率。

## 2. 案例怎样提供

直接使用[样本登记表](https://github.com/zys743551828-art/tender-datasets/blob/main/入库模板/样本登记表.csv)和[分项得分表](https://github.com/zys743551828-art/tender-datasets/blob/main/入库模板/分项得分.csv)，字段定义见[入库模板说明](https://github.com/zys743551828-art/tender-datasets/blob/main/入库模板/README.md)。评分来源与标书正文分开保存，来源文件只供标签核验，不进入模型的预测输入。

每份有标签样本需要实际提交的完整技术标正文、最终生效招标文件及全部补遗、技术总分、技术满分、成绩来源与聚合方式，以及项目、标段、地区、工程类型、评分办法、提交时间与成绩取得时间。缺少原件出处的公司台账单独标记，待核验；官方标签主评测与含台账的探索实验分别报告，避免把来源可靠性混在一起。

逐项得分、各评委打分、同场其他投标人的正文和技术分是高价值补充，有则保留，没有不阻塞首版。正文必须是参加该次评分的实际提交稿，不能拿之后修改的稿件配旧成绩。

| 批次 | 建议资料 | 交付与决策 |
| --- | --- | --- |
| 首批试点 | 10–20 份，尽量覆盖至少 5 个独立项目和高、中、低分 | 核验成绩口径、解析质量、评分项与满分，估算调用量；不声称精度达标 |
| 第一版训练集 | 约 300 份，尽量覆盖至少 50 个独立项目 | 开发集比较方法，保留约 20% 的较新项目作最终测试；目标为至少 60 份、10 个独立项目组的测试证据 |
| 持续增量 | 按投标时间连续补充，每次积累一批新项目 | 检查新项目误差与分布变化，比较新旧模型后决定是否替换 |

上述数量是采集建议，不是达到精度的保证。仓库现有 30 份、10 个项目的最低检查仅用于避免明显不足的评测，不代表已经具备可靠上线证据。项目、模板相似与正文查重会降低有效独立样本数；300 份来自少数同模板项目不能等同于 300 份独立证据。优先增加项目、评分办法和分数分布的覆盖，并连续收集普通表现、未入围和低分案例，避免只收高分稿。

## 3. 四层评分路线

当前数据规模适合比较低维、强约束的监督模型；不以从头训练长文深度模型或大模型微调为起步路线。300份是采集规划，有效独立项目和标签质量决定能验证到什么程度，不能据此承诺精度。

~~~mermaid
flowchart LR
  A[生效招标与补遗] --> B[评分结构与档位]
  C[实际正文及图表] --> D[章节树与页级证据]
  B --> E[逐项完整章节包]
  D --> E
  E --> F[三次结构化判断]
  F --> G[分组训练的统计模型]
  H[已核验正式技术分] -->|训练标签，独立隔离| G
  G --> I[技术分与经实测的区间]
  J[仅训练来源的近邻与比较锚点] -->|受控对照，不默认启用| G
~~~

### 3.1 第一层：评分结构与章节准备

招标侧提取每项评分ID、原文、满分、计分方式、档位上下界及端点、要点、条件和例外。存在分档才按分档判断；客观计数或连续评分规则保留实际公式，不能强制套成优／良／中。满分合计不符先核对，不靠缩放掩盖。

“每份招标只算一次”指相同生效资料和方法可以缓存，不是永久只调用一次。缓存身份至少包含招标与全部补遗版本、解析配置、提取提示与模型版本；有变化则形成新结构版本。项目专属事实和适用时间仍需核实。正文章节树按每一份稿件版本独立建立，不能随招标缓存复用到新稿。

正文按目录、标题层级和实际物理页形成章节树，保留表格、图和附件。一个评分项可对应多个章节，一个章节也可服务多个评分项；映射记录依据与未确定部分，不能强行一对一。

### 3.2 第二层：按项读完整相关章节，重复结构化判断

RAG首先帮助定位相关章节和跨章引用，再由ChapterPackageBuilder组装完整相关章节及必要附表、图页和上下文。正式逐项评分不能只给固定5个片段。规则查证、一般问答可以检索片段，但不能将片段查证的范围冒充评分项完整输入。

章节超出上下文时，按可追溯子节拆分并维护覆盖清单，分别判断后做跨节一致性与汇总；保留原页引用。不能静默截断，也不能只给摘要就标整章已读。层级处理需与能够完整输入的案例对照，质量未验证或关键图页未读取时记录缺口，必要时拒绝该项或总分估计。

每个评分项以同一冻结材料独立运行3次，输出以下信息：

| 字段组 | 内容 | 约束 |
| --- | --- | --- |
| 档位判断 | 对应规则中的档位ID、档位边界、理由与引文；不适用则明确 | 不要求LLM直接报最终分数，不将档位中点当官方真值 |
| 要点覆盖 | 每个要点的已响应／未找到／矛盾／无法判断及出处 | 缺失型判断记录检查范围，不编造正文引文 |
| 针对性 | 具体工程、工况、工序和资源依据；模板残留或空泛的证据 | 不能只用出现项目名或关键词判为有针对性 |
| 具体性与有效性 | 数字、图表、措施及其与要求的相关性和一致性 | 数量多不等于质量高，错误数字／无关图表不作加分证据 |
| 质量与分歧 | 读取缺口、输出失败、证据校验结果、三次档位／覆盖分歧 | 未识别图页不是没有图；三次一致也不证明正确 |

所有判断绑定规则、正文版本和证据。记录采样参数、模型版本、调用尝试和有效重复数；重复失败不能冒充3次有效判断。三次结果可能高度相关，温度为0也可能完全相同；波动只是一项候选特征，不代表独立评委，也不作为最终预测区间。失分点和修改建议仍从本层产出，明确为系统判断，不能冒充官方扣分原因。

判断通过[模型适配契约](AI投标工作台全新系统技术方案.md#14-模型适配安全数据出口与观测)执行，同一评分方法固定profile、提示、schema与章节处理。超时重试保留逻辑判断身份，不增加有效重复数；故障不静默换模型、缩短正文或用0分补齐。供应商选择与方法调整在开发数据中完成。

### 3.3 第三层：由正式成绩训练统计打分模型

输入不包含目标提交的成绩、评委意见和事后整改。候选特征按定义版本化：

| 特征族 | 候选内容 | 控制条件 |
| --- | --- | --- |
| 逐项判断 | 档位及边界、要点覆盖、针对性、具体性、矛盾、分歧与失败标记 | 保留分项信息和分值加权摘要，不预设各分项固定贡献 |
| 正文结构 | 相关章节完整度、技术措施结构、必要表格／图页覆盖、事实一致性 | 页数、字数、图表数只作候选，防止奖励堆字和无关图表 |
| 背景 | 评分办法／量尺、地区、工程类型、规则条件 | 低维编码、稀疏类别收缩或回退；不靠项目ID记忆答案 |
| 历史近邻 | 相似正文／对应章节、训练来源近邻的正式分分布及支持数量 | 仅从该折允许的历史训练来源计算，时间和同源组隔离；相似不是质量的等价物 |

首先在相同冻结划分上比较历史均值、中位数、评分办法分组基线、可定义的原始档位估计、带正则线性／岭回归、保序校准，以及相似样本加权。保序只针对有稳定排序意义的输入使用，不强行将所有多维特征变成一个有序标量。填补、编码、标准化、特征筛选、正则参数和近邻权重全部在训练来源内确定。

第一条基线链先不加入带成绩近邻与LLM锚点，便于定位判断和尺度误差；随后做加入近邻的消融对照。统计模型由开发验证选择，最终测试不用于反复挑选。分项正式标签缺失时训练总分，不把总分复制到每个评分项。有真实分项与评委数据后再比较分项监督和聚合模型。

### 3.4 第四层：比较式锚定，按增益决定采用

从该实验允许的训练来源选同评分办法、条件可比且覆盖高／中／低分的锚点。LLM按对应评分项比较目标与锚点的内容，输出优于／相当／弱于／无法比较及双方引文；位置交换复测，检查先后顺序、文风、篇幅和模型自评偏好。

若锚点只有总分，比较结果只能与总分监督共同学习，不能直接把锚点总分推到某个评分项。参考和目标条件不可比时允许弃权；“比较比绝对打分可靠”在本领域是待验证假设，不是既定事实。

比较带来的特征交给统计模型或受控相对分模型，不直接按胜负次数换成任意分数。与无锚点方案使用相同独立划分，同时比较误差、排序、稳定性、失败覆盖及调用费用。只有确实改善且来源无泄漏时才启用；成本、调用数量和实际锚点清单全部记录。

## 4. 防止评测高估

同项目、同模板组、完全相同或近重复正文必须作为连通组划分。开发数据用于调提示词、选特征和模型；较新的项目组作为最终留出测试。训练侧剔除跨越测试时间边界的组，以及在测试起点尚未取得成绩的案例。最终测试的正文可以用于生成预测，但成绩、评委意见、公示与事后整改不得进入预测输入、提示、检索库或缓存。

近邻和锚点的已知分数都是监督信息的一部分。只排除当前目标项目或模板，不足以证明整个测试集成绩隔离；评测器读入预先生成的特征，也不能据此证明来源无泄漏。因此锚点实验必须额外保存锚点来源案例、成绩取得时间、训练组清单及其摘要，核对其与完整验证或测试集合不相交。

第一条基线在方法和特征两侧同时排除带成绩近邻与比较锚点；加入近邻和锚点分别作为受控消融。所有邻居、权重和标签只来自对应训练来源；内层调参、外层验证、校准和最终测试都使用各自正确的来源集合，不能全库预计算后切分。

锚点启用采用以下二选一方案：

- 固定一份仅由历史开发项目构成的锚点库。锚点库案例不作为被评测样本，全部成绩在测试起点前已取得，后续开发验证和最终测试均与它隔离。
- 每个训练折构建专属锚点包，分别重算该折验证样本的锚定特征；模型内层参数选择也遵守相同隔离，不能把全数据锚点特征预计算一次后反复使用。

缓存键和实验摘要需要包含锚点库、规则、解析、提示词与模型配置，避免命中来自其他划分的结果。某个样本排除了自己的成绩，不代表其他测试样本的成绩不会通过锚点泄漏。

最终测试只用于最终判断，不根据测试误差反复改模型、提示或验收目标。未通过时回到开发集分析，并使用新增项目建立下一次独立测试。方法选择后的交叉验证误差不是最终验收结论。

## 5. 错误分析与改进顺序

每份案例输出正式分、预测分、差值、区间、逐项判断、对应证据、运行失败情况以及模型与数据摘要。对大误差案例按以下顺序排查：

| 原因 | 修正方向 |
| --- | --- |
| 提交稿、成绩、满分或聚合方式配错 | 更正标签关联，保留出处与更正记录 |
| 最终补遗遗漏、评分项提错或合计不符 | 修正规则及版本处理，不用校准系数遮盖 |
| PDF、表格或图纸内容漏读 | 增加相应解析与图页证据，重算受影响特征 |
| 评分档位或覆盖判断有系统性偏差 | 用开发集的分项复盘修正判断提示，并固定对照 |
| 原始判断整体偏高、偏低 | 线性或保序校准，以独立验证确认有效 |
| 不同地区、工程或评分办法表现分化 | 分层报告；样本足够时使用分层模型，不足时限制适用范围 |
| 评委分歧或不可观测因素大 | 报告误差与区间，必要时拒绝给出窄区间；不把偶然波动记成规则 |

图纸及工程内容的复盘需要市政工程师核对。只修正文风、增加字数或复制模板的对照用于检查模型是否误把这些变化当作质量提升。全部失败、无标签、未给分和拒绝估分均列入批次报告；质量评分与废标风险分别处理。

## 6. 全新实现的职责与产物

| 模块 | 必需产物 | 验收重点 |
| --- | --- | --- |
| RubricPreparation | 评分结构、档位、要点及生效版本摘要 | 条款不遗漏，计分类型正确，缓存随补遗和方法变化 |
| ChapterPackageBuilder | 章节映射、完整章节／子节清单、图页、原页与缺口 | 不用top-k片段代替整章，不静默截断，不因摘要存在就标已完整读取 |
| ItemJudgment | 三次有效判断、引文、分歧和失败身份 | 不给未经监督的最终技术分，证据与缺失状态可复核 |
| FeatureBuilder | 版本化特征、训练内预处理、近邻／锚点来源记录 | 同一规则与输入可还原，线上与训练计算一致 |
| ScoreTrainer／Evaluator | 基线对照、分组时间划分、模型及区间报告 | 独立测试、项目等权、成功／拒绝覆盖、相对位置和概率的条件明确 |
| ModelRelease | 固定模型摘要、适用范围、验收与回退对象 | 不因在线配对数增加就自动发布，不沿用旧模型资格 |

旧仓库的pf-1、批量预测、校准和锚点工具只作参考行为与历史数据读取材料，不是新系统必需的代码、特征或接口。新产物契约按上述职责独立设计，任何实际迁入需核对原始来源和方法身份。

## 7. 执行顺序与交付

**案例到位前：** 固定数据模板和验收口径；补齐接近程度与发布指标；审计锚点来源隔离、模型范围及规则满分检查；用合成夹具验证评测程序的边界，不将合成误差作为真实精度。

**首批试点：** 先 dry-run 入库，核验 10–20 份样本的资料与标签；检查逐项评分和图页证据；估算模型调用量与费用，按授权范围跑预测；交付资料质量报告、大误差原因分类和首版实验配置。身份、版本、证据与用途隔离基础具备后可使用受控实验入口，与最小项目工作区并行推进，不等待完整聊天工作台或全量知识库；研究产物不具备模型业务发布资格。

**训练与独立测试：** 在约 300 份数据中完成分组、时间留出和开发对照；按资料条件增加排序与技术入围概率验收；冻结模型配置、数据划分与验收目标；只运行一次最终测试；交付逐案例误差表、总体及分层误差、命中率、区间、稳定性、失败覆盖、学习曲线和可部署模型。未达标则保留“未校准”，明确要补哪类数据或修哪段流程。

**投入使用：** 新模型先登记到 shadow，保留现用模型；在新投标项目上盲预测，正式成绩回来后配对核验。达到发布条件再切换业务模型，保留回退。后续每批新数据先检验当前模型，再重训候选模型；新模型不能只凭训练误差更低替换。

新代码与产物布局按[全新技术方案](AI投标工作台全新系统技术方案.md)实施。实验固定模型、提示词、解析、规则、特征、近邻与锚点来源，使用独立输出目录，保留训练数据、实际输入与评测摘要。业务方向来自四层方案，具体阈值与新增特征需在独立数据上验证。
