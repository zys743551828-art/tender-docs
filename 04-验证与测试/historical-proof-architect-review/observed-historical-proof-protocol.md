# 历史可见证明与回测输入协议

本协议落实[PRD第13.2—13.4节](../../../02-业务与产品/AI投标工作台PRD.md#132-严格样本准入fr-028)和“历史标书作为全新系统的新资料入库”。[研究Owner的可达性缺口](../../research-backend-checks/fr029-development-checks/历史资料新入库可达性缺口.md)指出，普通上传时间与offline_fact.review_id为空使合法历史路径无实际入口。不能要求用户改库、伪造当年标准评审，或放宽全部来源资格。本协议定义最小新增资源；研究03原候选及证据保持，尚未实际实现或验收。

## 1. 不可混淆的时间与资格

| 事实 | 记录原则 |
| --- | --- |
| 系统上传／created／解析／本次实际接收 | 永远记录现在实际时间，不倒造2019；document.obtained_at和原source.known_at不回写 |
| 该精确内容当时存在 | 独立有据历史事实；同名、PDF印刷日期、文件属性或当前用户填2019不能自行证明精确旧版本 |
| 公布／生效 | 分别记录历史公布和效力区间，不能从公布推出本方知晓或已取得 |
| 本方当时知晓／实际取得 | 针对真实主体、明确资料版本分别举证，可未知；和现在研究操作者取得该副本不是同一事实 |
| 官方成绩公布／实际取得 | 可2019公布、2026才实际取得；known_at仍2026，不因证明公布日更改标签取得或实验时间边界 |
| 本次确认／冻结／执行 | 全部现在，historical_as_of才是被研究的当年提交边界；今天确认当年事实不冒充当年做过确认 |

本回测输出始终prediction_timing=retrospective、execution_purpose=historical_backtest、research_only=true，不能回填成当年事前预测、标准gate通过或在线误差配对。data_origin另列real／synthetic／uncertain，model_eligibility独立判断：真实、有据历史案例仍可成为未来模型监督训练／评测候选；research_only不使真实历史数据永久失去未来模型用途。合成证据不能冒充真实历史依据，来源不明不能自动变real。当前正式模型资格仍unavailable。

## 2. 三个追加资源

字段名由actual契约唯一导出，以下语义必须实现。ID从可信选择投影取得，不让用户手填UUID，不创建假项目／假review。

| 资源 | 最小冻结内容 |
| --- | --- |
| HistorySourceClaim | id、bid_id、submission_id、精确document_version_id／blob_digest、适用主体／工程／标段轮次；facts[]各有fact_kind、claimed_at或unknown、必要valid_until、说明；每个事实关联proof_refs[]（证明文件版本／摘要、parse、物理页、evidence_id、逐字quote、支持哪个事实）；reason、data_origin、created_by／created_at、supersedes_id／有效头修订、人工核验决定及状态 |
| HistoricalSubjectAuthority | 指定原submission_id、actual_body_version_id／摘要、原提交时点、被证明的工程／标段轮次／主体；精确证据及所证明关系、当前人工确认人／时刻、原身份观察与差异、不可变新版本及有效头。不能默认用当前profile确认过去是谁投标 |
| HistoricalInputAuthority | id、submission_id／实交正文摘要、historical_as_of=submitted_at、明确当时material版本集合／规则与必要事前事实、上述两类有效头与digest、完整正文/章节及必要图表的parse/页范围/缺口、方法/模型/用途与输入digest、frozen_at现在；retrospective／research_only及data_origin固定独立字段 |

fact_kind至少区分content_existed、published、effective、known_to_bidder、received_by_bidder；unknown必须为null／明确未知，不能以“待填”转零时刻。每份正文、招标、补遗及必要事实分别证明所用精确版本，不能拿一份招标首页日期替全部资料背书。邮件附件、回执、正式档案／签收／公布材料等可作证明，但必须能对应所选版本与主体／轮次；机器核对字节、引用、归属及一致性，不宣称自动完成真实性或法律结论核验。人工明确判断支持何种历史事实并留限制。

## 3. 用户一次有据确认与缺口

历史导入预检查／实交详情给“补充历史依据”，预填原实交、正文、项目与已知缺口，不要求重新上传已收原件。用户只补确实有证据的时间事实和历史身份；可点“保存待核验”，不强迫填完。资料齐备后同一卡给“确认历史事实”，展示原件、原页、所支持事实和当前影响；一次明确提交追加证明及人工决定，无岗位审批或第二张重复确认。

原件日期、公开可得和本方实际知晓分别表示。只有公开日期证据，只能确认公开／存在；不能自动满足既有“本方提交前已知”的严格条件。默认沿用原研究协议的可见要求，缺其必要证明保持pending。将来若另采用“公开可得重建”探索口径，须独立冻结该协议／用途并单独报告，不默改现有known资格或主验收口径。

有据历史主体确认追加独立authority，读取时展示“历史身份已补充核验／确认于现在”；原offline_fact.evidence、review_id、submitted_at、旧身份快照和审计不改。证明发现实交稿本身记错，应走既有有据实交更正，新记录关联旧记录；不能在本接口偷偷换实际稿。

样本归组、主体和工程／标段／轮次比较使用该历史authority的精确快照，不能再以今天的bid_profile替代；当前项目改名或改主体也不能静默重写历史分组。

写入统一认证、CSRF、幂等、当前对象强If-Match；整笔非法拒绝并保留输入，pending不自动得到confirmed。确认只承诺人工有据解释，不把客户端confirmed布尔值当核验。更正追加新版本/有效头，旧证明及旧冻结输入可还原；新冲突不回退旧confirmed冒充当前可用。

## 4. 不需要当年review_id的专用冻结入口

提供从实际历史submission发起的“冻结回测输入”：选择当年生效招标／补遗版本、必要事前事实、已核历史可见证明和历史主体；正文固定为该实交真实字节，不能选当前改稿。API只创建现在的HistoricalInputAuthority与完整章节包，不要求submission.review_id非空，也不修改它。

评分规则可在现在从这些已证明历史版本提取及有据确认，parse／模型／方法也如实是当前身份；不能声称这些派生物或方法在当年已经存在。历史内容可见证明只用于判定原内容在historical_as_of是否可用，当前派生处理时间另存。必要图表、完整相关章节、评分结构和合法引用仍完整核验，不以top-k或摘要代替，缺口拒绝完整评分。

建议最小实际命令是历史来源证明保存／确认／追加更正及查询、历史实交身份authority保存／确认及查询、历史输入冻结及查询；可嵌入已有导入详情／实交详情，技术Owner确定路径和Schema后统一导出，不先承诺未注册operation。批导入行可引用已有authority或在导入完成后按缺口补，不因批量路径缺identity永远不可达。

## 5. qualifier严格分支与失效

研究Owner新增显式historical_backtest分支，以HistoricalInputAuthority对应原实交和完整包，替代“所有历史样本都必须硬连submission.review_id”的结构假设。现有当前项目／在线正式用途仍按原review、事前时点及来源资格执行，不把空review一概放行。

历史分支至少重核：当前有效实交及正文真实字节／摘要、正确历史主体与当前有效authority、当时版本与生效范围、满足冻结协议的历史知晓证明、当前可核验parse／页／引用和全部祖先、干净输入与分组／时间协议、官方技术标签及口径。后录只在这一受限分支解释历史内容时间，不改source.known_at、不对普通RAG开放时间豁免，不把证明文件登记成prebid正文。

后来有新补遗／新版本，不自动使旧版本变成当年从未有效；只有该精确旧版在历史时点确有有效证明才可冻结其历史适用范围。当前已知内容错误、撤回、权限禁止或证明冲突不能被历史声明绕过。到底是合法历史替代，还是材料已不可信，必须有明确依据；不明保持pending，不用一个“忽略当前head”开关解决。

冻结、预览、领取、执行、发布前及读取当前资格时重核authority有效头和来源。证明／身份／实交／parse／分组改变使旧输入stale，待重新冻结；既有结果保留历史，未解决冲突不能被旧admitted或缓存洗掉。并发核验与冻结须原子取一致版本，研究角色只拿被授予的最小执行authority，不能从客户端claim ID绕过可信绑定。具体受限SQL与角色由架构静审后落地，不直接放宽研究03函数。

## 6. 模型输入与标签隔离

authority分两份：审计／资格清单可含证明位置、身份、时间、官方标签核验身份；模型content manifest只含已允许的历史招标评分要求、实际正文完整章节及必要事前事实。证明原文、官方成绩、评委意见、标签摘要、主体核验附件、聊天和混合派生来源全部不进入模型提示／RAG片段／缓存／锚点。

官方标签实际取得现在就记现在，公布日可另有证明。冻结实验分别保存提交时间、标签公布、标签实际取得、冻结时间和切分协议；不能用历史可见authority把2026取得标签改成2019已知来满足既有训练／时间留出边界。将来使用真实历史数据训练未来模型，仍按对应独立协议冻结组／时间、标签监督与测试隔离；回测输出不能参与正式在线误差，20配对监控门槛也不改变此限制。

## 7. 完成边界

本协议解决“合法路径缺入口”的设计问题，不宣称证据已经取得、当前资料已经准入、模型可训练或系统已通过。旧研究03合成PG正例不能替代普通当前上传→历史依据→确认→回测authority→完整包→研究的真实API长路径。

当前StageA实际API仅支持synthetic软件研究；新增历史proof本身不开放real执行或正式模型资格。真实历史数据可作候选，但需要实际实现对应受控数据／执行入口、冻结协议并完成独立验收，不能在客户端切data_origin就调用原StageA分支。

下一步：研究Owner给actual Schema/追加表及受限函数草案→架构静审用途／来源／角色与不可变约束→fresh非owner API/Worker及反例→浏览器就地补证与恢复→真实资料/独立模型验收。模型调用和browser均留后续，本轮无凭据／收费调用。[验收任务](acceptance.json)全部pending_application；未知缺证据可以继续档案和其他软件开发，不能用假历史时间换绿标。
