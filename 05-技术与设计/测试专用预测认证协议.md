# 测试专用预测认证与发布协议 /1

本协议依据用户批准“仅测试、永远不能晋升生产”的方向实施。它用于验证工程成功链，不是 FR-002 正式模型认证，不修改准确性门槛，不制造真实业务资格。正式认证仍要求原协议的真实评估、live 观察和回退证据。

## 两个永不互换的通道

| 边界 | 测试专用 | 正式业务 |
|---|---|---|
| 数据库 | 已有 test_environments 登记的临时隔离库；额外显式安装 prediction-sandbox.sql | 原安装计划；不包含测试 SQL |
| 资格 | prediction_sandbox.certificates，schema prediction-sandbox-certificate/1 | package_model_admission.certificates；原权威函数不变 |
| 结果 | prediction_sandbox.results，schema prediction-sandbox-result/1；test_only=true、production_eligible=false | package_prediction.results；不接收测试证书外键 |
| 入口 | 独立 create_app 工厂及 /test-only 前缀，或显式 CLI | 原 /api/v1 及统一报告/Word、模型登记消费者 |
| 恢复 | 原样复制仍绑定原 DB OID、名称、集群系统ID和 postmaster 起始时间，换库/实例失效 | 原隔离只读恢复，不通过测试协议授予恢复上线资格 |

不能把测试 namespace 改名、将 source.mode 改成 live、上传 verified=true 或复制结果，来满足正式认证。测试应用不由 apps.api.main 导入或注册；没有业务 UI 的正式结果卡、正式导出或模型发布入口。测试结果本身也不能通过 registry artifact 校验。禁止将其误标为正式报告。

## 来源、事务与持久任务

1. 宿主只注入现有 API 角色连接、私有 S3 Objects、原 Executor 和冻结本地 /3 CAS/index。不接收口令参数、不替换认证权威函数。HTTP 沿用 Cookie/CSRF 和成员状态检查；CLI 是持有既有测试 API 连接的运维消费者。
2. 颁发测试证书前，原 Executor 实际加载原始材料、输入摘要、模型 artifact 和特征，source 必须 synthetic，来源 bid_id 必须等于测试项目。证书固定 source_ref、packet_digest、scope、方法摘要和显式有效期；期限大于服务端当前时间且至多一天。重复命令内容相同返回原证书，漂移拒绝。
3. 申请/发布复用项目锁及原 91143 锁，再取得测试协议事务锁。计算和对象读取在短事务之外；正式方法摘要与测试 /1 方法摘要分别固定，既有冻结方法没有偷偷改写。
4. 入队沿用 package-prediction/1 handler、原 command/audit/outbox、Worker lease/fence/retry 和私有结果对象。测试协议不创建新队列，不授予 Worker 测试证书或分数表读取权限。
5. API 消费器复验原步骤终态、输入/结果引用、方法/材料和独立重算一致性，再在锁内复验资格、取消及操作回执，只插入测试结果。所有测试回执显式标 test_only；原任务的 prediction_ready 保持 false，不发正式 published 审计。
6. 测试撤销为追加的终态记录，可幂等重放；失效重读不返回数值。发布前取消使发布拒绝；已测试发布须撤销而不能删历史。API/Worker 进程重建不改数据库环境绑定；数据库实例重启或恢复到其他库会使整个原测试环境绑定失效，须用全新登记的临时库重建本轮测试，不能重写环境行来复活资格；仅方法变化时也使旧证书失效，需按原命令隔离规则重新建立测试资格。

所有测试 SQL 表禁止 UPDATE/DELETE，现有 tender_api 只有受控函数执行权，tender_worker 无 schema/表/函数权。测试专用安装不是迁移，禁止将 deploy/sql 按字母全量执行。

## 实际入口与复验

在应用 workbench，用已有隔离注入运行：

```sh
.venv/bin/python -m packages.prediction_sandbox.cli --help
.venv/bin/python deploy/prediction_native_acceptance.py --seaweed-archive /已校验的/seaweedfs-4.48.tar.gz --output /新的/隔离证据目录
```

CLI 只支持 issue/submit/advance/read/revoke/cancel，必须显式传测试 actor/bid/command；任务还需固定 certificate/scope。issue 必须明确 source-ref 与 valid-until；revoke 必须给理由。source-ref 是已有私有 S3 JSON 对象的摘要，不是客户端路径或资格证明。输出不是业务分数。

独立 HTTP 应用由 `apps.api.prediction_sandbox.create_app(sandbox)` 构造。默认 sandbox=None 拒绝；宿主显式注入同一 Sandbox 才可使用。端点：POST /test-only/bids/{bid}/certificates；POST certificates/{id}/revoke；POST tasks、tasks/advance、tasks/cancel；GET tasks/{command}?scope_id=...&certificate_id=...。DTO 禁止额外字段；复用登录/CSRF，回执 private,no-store 且 X-Prediction-Test-Only=true。不提供公开部署或真实凭据配置步骤。

原生套件使用固定 PG17+pgvector、Kafka 镜像及官方 SeaweedFS 4.48 摘要，临时测试凭据和容器退出清理。额外 CI job 自动运行同一入口，不用默认 pytest 的 skip 冒充原生通过。测试覆盖实际数据库资格装配、原 Worker 计算、API/Worker 进程重建、CLI重放、丢ACK、正式API/JSON/Word拒绝、取消/撤销/过期、跨成员/范围、实际 dump/restore 跨环境拒绝。架构测试约束生产代码不依赖测试协议及默认安装/恢复计划不含测试SQL。

这些证明工程隔离与恢复，不证明真实模型质量、生产资格、真实评估数据、线上流量、实际生产恢复或 Word03 转换。测试结果没有晋升接口；后续真实认证仍须独立满足全部正式证据。

## 同步校验锚点

TEST-PRED-APP：测试应用用例与原生成功链。TEST-PRED-HTTP：独立HTTP入口及默认禁用/封闭DTO。TEST-PRED-SQL：环境绑定、不可变资格及结果数据库装配。TEST-PRED-BOUNDARY：生产依赖与registry/恢复计划隔离。四项纳入implementation-trace额外支持检查，不替代40FR条目，不将acceptance改为已验收。
