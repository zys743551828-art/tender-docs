## 2. 结论

以 `main` 为最终形态的基线，`workbench/` 不整体合入，`handoff/2026-10-17` 分支保留为存档。

理由：本系统是公司内部长期维护的工具，最终价值取决于真实标书读得准、风险查得全、技术分预测得准。`main` 已形成可部署的完整闭环，规模适合少量人员维护；Codex 一版的单个模块质量不差（如检索的分块与引用），但流程负担与范围扩张使其没有收敛为可运行的整体。两版对评分采用同一条四层路线（用户提供），`main` 已经实现。

## 5. 统一实现方案

### 5.1 产品与运行边界

唯一运行入口沿用 `tender-app/frontend`、`backend`、`deploy` 和 `contracts`。保留 PostgreSQL 16、Kafka、OSS、DeepSeek 适配器、登录会话、CSRF、冻结输入、证据、幂等和审计。文件走同源 API 分片上传。`workbench` 的资料用于设计与算法参考，不复制其数据库、服务进程、任务平台或留证目录，也不建立第二套项目身份。

默认流程为上传资料 → 自动评审 → 报告 → 对照原文处理问题 → 上传改稿复评 → 登记实际提交与结果。报告、上传资料、处理问题是三个常用导航；依据、报价、提交与结果、检索、设置放在“更多功能”，直接访问时自动展开。命令菜单仍能直达所有已启用功能。

页面优先呈现当前最重要的动作，其余待办可展开，折叠标题显示剩余关键问题与其他建议数量。关键问题和规则核对可能指向同一条款，数量表示各待办的处理项数，不把合计称作去重风险数；全部问题卡片继续按后端分类显示数量。关闭模块仍按项目设置裁剪，核心检测与提交闸门持续生效。

### 5.2 核心质量的接入方式

| 模块 | 接入现有位置 | 输出与约束 | 退出条件 |
| --- | --- | --- | --- |
| A1 文档解析 | `backend/src/bidwb/parsing.py` 与解析任务 | 文字层、OCR、表格和图页都绑定原件版本与物理页；按页记录成功、失败、未识别与不支持范围。不能把空文字页自动当作无内容 | 用 3—5 份真实标书比较候选解析器，含扫描页、跨页表、旋转页、图页；记录质量、耗时、费用和失败恢复后选型 |
| A2 完整章节输入 | `ai/sections.py`、`ai/predict.py` 与锚点包构建工具 | 保留任意实际标题层级；从相关章节展开子节及必要附表图页，建立覆盖清单。超长时逐子节读取后跨节汇总，记录每块阅读状态与原页引用；关键内容缺失不得标整章已读 | 构造后半章节含关键措施／矛盾的回归；逐块无遗漏，拆分与整章输入结果对照，模型中断只使相关范围不完整 |
| A3 评分验收 | `tender-research` 的冻结协议、评测报告与模型登记 | 采用第 5.3 节门槛；评测与业务发布分别验收，未通过保留未校准。合成数据只验证程序 | 冻结独立项目与时间划分；所有指标可计算且满足门槛，检查来源隔离后先影子运行 |
| A4 判断维度 | `ai/prompts.py`、逐项输出与特征构建 | 保留档次、要点、针对性，增加具体性与有效性、前后矛盾及双侧引用；区分缺失、矛盾和无法判断。字数、页数、图表数量不直接加分 | 同内容扩写、错误数字、无关图表、跨节矛盾对照；输出经证据校验。特征定义变化须同步研究端和模型适用性，旧校准模型不得静默复用 |
| A5 混合检索 | PostgreSQL 的证据索引、`retrieval.py` 与检索接口 | 项目／快照／用途过滤 → 中文词法与编号数字精确通道 → pgvector → RRF → 可选重排；各通道均继承访问控制与版本过滤 | 先建立有参考引用的查询集，比较关键词基线；验证跨项目隔离、编号数字召回、失效版本、向量失败降级和恢复，再移除部署中的 Milvus |

A5 采用 PostgreSQL＋pgvector 的目标架构，实施时扩展 PostgreSQL 16 镜像及迁移；不同时升级 PostgreSQL 主版本。向量模型及维数要随索引记录，模型变化建立新索引并验证后切换。供应商、模型、生产镜像和召回质量未验证前，运行态仍使用现有关键词检索，不宣称已经具备向量检索。

### 5.3 评分方法与验收

沿用四层路线：生效评分结构 → 完整章节上的重复逐项判断 → 正式技术分训练的统计模型 → 独立对照的比较锚定。每个条款保留三次逻辑判断的身份、有效次数、失败、模型、提示词、采样参数和费用。三次一致不等于正确，复跑波动不等于正式预测区间。完整章节读取、解析覆盖、结果成绩和实际提交稿身份分别校验。

训练与评测以 `100 × 技术分 / 技术满分` 为统一量尺，展示再换回原满分；综合分、预测分和未打分不充当正式技术分。首批 10—20 份验证入库和方法，再扩大至约 300 份，样本量本身不保证精度。

| 指标 | 一期目标（百分制） |
| --- | --- |
| MAE | ≤ 3 分 |
| 绝对误差 P90 | ≤ 5 分 |
| 绝对误差 ≤ 3 分的比例 | ≥ 80% |
| 平均偏差绝对值 | ≤ 1 分 |
| 相对最佳历史基线的 MAE 增益 | 项目组级 95% 区间下限 > 0 |
| 同输入整轮复跑极差 P90 | ≤ 2 分 |

以上是开发与验收目标，不是已取得精度。协议在看最终测试标签前冻结，缺少数据或复跑时相应指标标“不可评价”，不能因为其他指标达标就总评通过。原量尺误差、80%／90% 区间的覆盖与宽度、失败与拒绝率、工程类型和评分办法分层同时报告。

同项目、模板和近重复正文连通成组，较新项目作时间留出。填补、标准化、特征选择、校准、近邻和锚点仅来自该折允许的训练来源；正式成绩、评委意见与事后整改不进入预测输入或检索缓存。无锚点基线先跑通，锚点以同划分的增益、费用与失败覆盖决定是否启用。

### 5.4 交互与版本闭环

主要动作的统一目标顺序为：①资料身份／生效关系歧义；②必需解析、核对失败或关键覆盖未完成；③当前有效轮的关键风险；④提交检查中的事实与关键规则核验；⑤技术评分缺口与改稿；⑥合格提交或非阻断建议。未开始与处理中分别显示补资料／开始评审与进度，防止重复启动。实现须由后端事实决定，不在前端另造风险或放宽提交条件。

补遗显示变更条款及其影响规则和章节；无法确定替代关系时就具体条款发起核实，不按上传顺序猜测。外部 Word 改稿按文件版本转换为 PDF，失败在该文件上提供补交 PDF 的入口；不要求整批重传。轻量 AI 输入只围绕当前项目解释或提出建议，确认卡点击后才调用现有正式操作接口，保留会话身份、幂等、版本校验和审计。

成绩登记复用当前提交的项目、轮次、正文版本，只核对差异；未知和待核验明确保存，不把预测分或综合分补成技术分。评审报告下载与批注审阅稿分别命名；没有正文编制能力时不展示“导出投标正文”。
