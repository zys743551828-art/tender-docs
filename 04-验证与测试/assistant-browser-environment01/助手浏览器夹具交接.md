## 稳定运行和控制

截至交接的 API PID 为 2775635，Worker PID 为 2775642，publisher PID 为 2775687，UID 均为1000；会话分别为98721、85780、71102。停止时必须再次核对 PID、UID、完整 argv，然后优雅 TERM。不要据本文件中的旧 PID 盲目结束进程。

控制使用固定脚本（工作目录 `/workspace/tender-workbench`）：

```sh
.venv/bin/python /workspace/tender-docs/04-验证与测试/assistant-browser-environment01/facility-candidate02/runtime/launch.py control --config .local/assistant_ui01-fixture04final.json --response hold --scope global
```

模式可选 `answer`、`knowledge_action`、`unknown`、`hold`；范围用 `--scope global` 或 `--scope project`，可重复。知识 Action 需要真实选择同项目的 project 和 document 来源。取消用例先 hold，经真实 API 请求取消后再释放执行，确认没有 Mock 请求。unknown 后不能以新 nonce 自动再次请求模型。

仅在无人运行浏览器测试的明确窗口升级产品候选：先 `rebind.py` 使用新的候选路径、新配置文件和新证据目录（拒绝覆盖），保留现库、成员、原件、会话；再核对/TERM旧三进程，从固定 `launch.py` 以 `api`、`worker`、`publisher` 各启动一个进程。不要重新 seed。每个进程启动前会逐项核对新候选所有源。对新证据目录运行固定 `readback.py --actual <新actual文件> --evidence <新目录>`，它只读，不改变控制模式。需要重跑 smoke 时另指定全新 `--output`，且提前取得前端对控制权的交还。
