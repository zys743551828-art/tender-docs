# Rejected high-level qualification and normal restart

This iteration passed ordinary Desktop preparation/startup, chosen synthetic admin login (HTTP200), status and the normal PDF/Kafka verification. Real Word upload then reached `WORD_CONVERSION_RESULT_MISSING`. PAGE/RICH Worker computations returned internal complete, but their renderer identity differed from the installed profile, so this iteration does not qualify those outputs or the normal business export path. The existing PostgreSQL integrity trigger requires the frozen renderer identity and was retained.

The producer had recomputed the former image/adapter identity while the versioned profile also included the PDF inspector. The corrected producer copies the already validated identity into the result; the new assertion failed before that fix. See the separate final targeted regression.

Normal stop also caught a Worker-exit race as tmpfs invalid, leaving normal restart rejected. The correction rechecks the same exact peer ID; only a confirmed stopped peer can be classified as peer exit. An active peer, different ID or unavailable inspection remains a failure. The manager admission rules were not relaxed.

The screenshot records the actual failing synthetic Word state. Its unsupported claim that conversion had not run was identified during pixel review; a separate small frontend wording correction is verified independently. Both QA containers and this iteration's 16 containers, 2 networks and 14 test volumes were removed. These failures remain failures and are not rewritten by later results.
