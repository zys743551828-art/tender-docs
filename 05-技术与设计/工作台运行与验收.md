# 工作台运行、数据库与验收

## 选择源码与配置

当前审查分支为 tender-app `render-acceptance-20261026`；fusion分支和历史Windows宿主有各自固定证据，不能交叉声称运行了新代码。主源码在 workbench，根 backend/frontend 为历史供体。要求Python3.12、Node24和Docker Compose；依赖按 requirements.lock.txt 和 apps/web/package-lock.json，禁止随意升级替代验证。

默认只运行本地机制检查。`.env`及私有profile由授权操作者注入、忽略且权限600，不打印、不提交；缺配置拒绝启动。不得因非owner业务权限失败改用初始化owner。不要为了跑测试连接已有未知数据库或读取其它会话secret。

## 数据库初始化与变更

这是全新系统，既有需求不要求旧部署数据迁移。`deploy/schema_plan.py`、`deploy/fusion_full_init.py`和相应固定环境清单定义各自初始化范围；不能将 deploy/sql 按文件名排序全执行，也不能把早期19SQL清单当所有新增功能的完整安装器。

预测/认证相关 deploy/sql 为可选、fresh-only扩展，必须在空隔离库按文件声明的依赖装配并核对角色/摘要；例如 package-prediction-selection.sql 在 package-formal-prediction.sql 之后，结果插入guard负责固定计划约束。通用初始化成功不表示这些扩展已安装。当前尚无整条新增SQL原生联合验收，不能直接给现存库套补丁或重封存guard。以后若有已安装部署升级需求，另做有版本的迁移与回退评审。

## 可执行检查

从应用 workbench 运行（原生测试默认skip，不代表通过）：

```sh
.venv/bin/python deploy/ci_checks.py --suite unit --report-dir .local/ci/docs-sync
.venv/bin/ruff check apps/api apps/worker packages deploy tests
.venv/bin/ruff format --check apps/api apps/worker packages deploy tests
.venv/bin/mypy apps/api apps/worker packages deploy
.venv/bin/bandit -q -ll -r apps/api,apps/worker,packages,deploy -x packages/parsing/qa
```

前端在 apps/web 依次 format:check、lint、typecheck、test、build。不要并行多轮全量争抢CPU；代码冻结后取最终回归，保留首轮失败日志。部署结构检查使用 deploy/check_compose.py；缺 `.env` 是配置阻塞，不是业务回归通过。

原生入口包括 tests/test_slice_integration.py（PG/S3/Kafka）、test_word_intake_integration.py（独立PG及可选真实renderer）、各 *_pg.py。先核对每个显式RUN开关、准确SQL和角色要求，再对临时隔离资源运行；禁止盲目一次启用所有集成开关。固定Word profile/镜像/字体/隔离条件必须齐全；系统LibreOffice或合成PDF不能代替Word03验收。

## 运行与恢复边界

API/Worker/协调器须分别装配受控依赖。新预测 API 宿主使用 package_prediction_pipeline.composition.api；协调器使用 composition.coordinator；Worker使用 package_prediction_tasks.composition.compute。这些是现有任务执行器的装配接口，不是新长期服务的自动启动许可。缺依赖返回不可用，默认不调用真实模型。

故障先查原command/operation、租约代次、发布/取消标记和费用账本；丢ACK先恢复，未知费用不能重发。不要删除审计来“重置”任务。健康检查、备份/恢复及清理按 deploy/backups 与 deploy/application_recovery 固定程序；隔离恢复成功不等于生产RTO/RPO或生产恢复验收。

## 外部验收条件

隔离PG17+pgvector、S3、Kafka及准确角色/扩展SQL；指定Word03镜像与字体；真实配对和参考标注；真实合格模型/执行证据；整包标准提交、完整UI用户与容量验收。生产部署/恢复、真实付费调用和签发认证不在当前执行授权内。每次记录实际可用条件，不能把旧受阻结论当新探测。
