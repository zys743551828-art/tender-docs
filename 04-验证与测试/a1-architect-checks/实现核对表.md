## 2. RAG最佳入口与写入顺序

推荐固定管线：已核验document_version＋不可变parse／evidence→source_nodes及祖先图／head→chunks→固定embedding_profile的embeddings→eligible_chunks允许集→词法和向量召回／RRF／重排→trace和合法引用。索引阶段经已有Outbox接续，不在API请求或业务事务中等待模型。

| ID | 冻结契约入口 | 实现条件与最小反例 |
| --- | --- | --- |
| RAG-01 来源身份与归属 | retrieval.source_nodes／source_heads；design.parse_runs／evidence_blocks；当前handlers.publish解析结果 | 先固定来源用途、known_at和来源文档，再校验parse属于该文档、evidence属于同parse／原页，text／digest能回原文。现有外键不完整证明这些交叉关系，应用必须逐项验证。官方结果不能只因已上传就标prebid_content；不能人为回填known_at让未来来源通过。 |
| RAG-02 祖先图后发布 | lineage_edges、source_ancestors、no_lineage_cycle；源head | READ COMMITTED事务先单独取得图锁pg_advisory_xact_lock(90127,1)，后语句写边并核环；祖先关系完备后才能published。已发布来源不得悄悄加新父源改变语义，需新身份或明确受控影响协议。并发反例：两事务互插反向边、派生源祖先含标签／未来来源。 |
| RAG-03 分块及索引身份 | chunks的UNIQUE(parse_id,ordinal)、evidence_ids、physical_page、chapter_path；embedding_profiles | 首批固定chunk参数及tokenizer，ordinal在整份parse内唯一，不是每页从0重置；保留页／证据／章节边界。变分块方法不能原位改chunks，现有唯一键也不能靠覆盖绕过；需要新可追溯分块／解析身份时先作最小协议收口。解析partial仍可索引可靠范围，但返回缺口，不把有一条向量当全份可用。 |
| RAG-04 真Embedding与中文词法 | embedding_profiles 1024／cosine／normalized；embeddings；chunks.lexemes／lex_tsv | 固定BGE-M3模型／权重和预处理摘要；验维度、有限值、非零及L2范数，按(chunk_id,profile_id)幂等。中文先固定预分词再写simple FTS；直接整句to_tsvector('simple')不能冒充中文检索。未配置资产显示unavailable／partial；合成向量只进显式测试，不能作为业务Embedding。 |
| RAG-05 权威用途过滤 | eligible_chunks(allowed_sources,as_of,excluded_groups,formal_score)；目标RetrievalRequest／RetrievalResult | 公开POST retrievals只收query/context/bid/limit；purpose、allowlist、profile、as_of和排除组服务端决定。所有召回先限定同一允许集，祖先任一未发布／撤回／未来／禁止组均排除。反例：最相似的另一项目正文或官方标签必须仍被拒；其他项目参考不得成为本项目已响应证据。 |
| RAG-06 召回与重排 | eligible_chunks→embeddings同profile余弦；允许集lex_tsv；retrieval_traces | 小允许集保证精确排序；HNSW候选不足回允许集内精确路径，不能扩大来源“补召回”。50／50→RRF60→20重排→最多8包为起始参数，不是效果门槛。记录profile、策略、允许集、候选排除和最终命中。缺Embedding或reranker时明确降级范围，不标完整混合链路。 |
| RAG-07 立即撤回与迟到结果 | source_heads、source_ancestors、citations及source_revision；目标withdraw／source-impacts | 查询前过滤，模型完成／新增引用／应用前再读并锁必要祖先head。撤回立即阻止新应用，不依赖Kafka清理或缓存过期；旧报告保留失效提示。反例：先检索，再撤回父源，再完成模型，不能发布为当前有效引用或补丁。 |
| RAG-08 字节定位与provider | blob→原件locator、parse配置、source digest；provider独立配置约束 | 新OSS环境不能用全局backend重新解释现有S3 object_key；新环境隔离或先实现持久storage profile。原页取件与模型输入核实际字节摘要，签名URL不是来源身份，不能写进语义摘要或日志。 |

## 3. 正式评分与研究隔离

| ID | 现成入口与边界 | 必须满足的检查 |
| --- | --- | --- |
| SCORE-01 受限读取 | score_input_sources、score_context_chunks、formal_score_context(review_id)、tender_score_read及独立DSN | 冻结白名单由服务端写，评分构造器只收到受限读取端口，不得附带API／Worker宽权限连接。视图已用review_inputs.as_of，不能回改frozen_at。该视图excluded_groups为空，实验fold／模板／近重复分组须先由服务端在白名单和方法manifest排除，不能把只读角色当全部防泄漏证明。 |
| SCORE-02 完整范围及三次判断 | chapter_packages、item_judgments、ScoreInput、ChapterPackage／ItemJudgment | RAG只定位，随后扩展完整相关章节、跨章引用及必要表图；超长可追溯分包并记录未读，不能top-k／摘要替代全范围。三次replicate同一冻结包且互不看输出；错误／缺份不填0或半分，不声称三份有效。 |
| SCORE-03 标签与发布 | samples／experiments／model_artifacts／model_acceptances／routes；研究Worker及受控导出 | 官方成绩／评委意见／事后知识不进线上输入、prompt、向量邻居或缓存。模型发布另经独立验收＋人工路由命令；DeepSeek连通、研究运行成功、样本数足够都不授正式资格。 |
| SCORE-04 缓存与回流 | ReviewManifest三种摘要、模型profile、fold／锚点及闭包摘要 | 缓存包含用途、完整输入／parse、规则事实、方法、replicate、profile及fold／锚点／来源闭包。实际提交前盲预测固定，事后成绩不能挑最近的一次回填。更正标签与撤回来源要标影响，不静默复活旧结果。 |
