# A1.3 可运行实现的产品核对输入

以下是实现候选，不替代产品Owner决定。现有目标契约/SQL保持冻结；新的只读投影登记在实际OpenAPI。

1. **提交依据附件**：`SubmissionRequest.evidence_ref` / `OfflineSubmissionRequest.evidence_ref` 明确指本项目已核验 `document_version_id`。选择卡从 `GET /bids/{id}/submission-documents` 取得真实文件、用途、摘要，用户不输入UUID。服务器回读实际稿及附件真实字节核SHA。用户可引用实际稿本身作为声明依据；此时仍只属于人工登记，`platform_submission_verified=false`，不会冒称交易平台回执已经核验。待Owner确认是否需要进一步限制独立回执。
2. **事前检查与事实时间**：标准登记要求当前完整核心评审、实际受检PDF、明确主体及核心人工确认均不晚于用户声明的真实提交时点；晚于实际提交的补做检查不能回写成事前通过，返回 `SUBMISSION_CHECKS_POSTDATE_FACT` 并指向独立事实补录。所有登记拒绝未来时间。评分缺失不单独阻断完整核心；已解决/有理由驳回的问题不继续阻断。待Owner核对此边界和文案。
3. **主体**：未明确主体仍可保存资料、运行普通评审及据实补录；标准闸门保留 `BID_IDENTITY_UNCONFIRMED`。新记录冻结 `evidence.identity`，不按今天的公司身份补填旧记录。待Owner核对交互负担。

标准登记重算当前资料/正文/规则/事实/方法/来源效力与解析身份、三层核心覆盖、人工确认和所有已知未解决关键问题。它不执行平台提交，也不把普通核心核对授予正式评分资格。已存在当前实交时只能显式更正；更正追加新记录、理由和依据并CAS移动head，旧事实不改。错传报告/批注副本不能标准登记，但已发生错传可以线下补录，明确“未经过系统完整检查”。

风险快照分两部分：`registration_blocking_findings`包含完整当前闸门问题；FR011 `open_risk_snapshot`仅否决/强制义务根问题，并标范围。只有提交时点之前存在服务器观察且上下文一致才重建已知计数；依据不足为unknown/null，不用今天补0。无合格事前预测则不产生误差配对。

报告从 `GET /reviews/{id}/report-context` 读取受检稿和真实展示/来源修订，用户选择格式后一次生成；`POST report-exports`用该资源强ETag。支持Word/PDF评审报告与PDF原页文本批注，暂不支持DOCX批注。PDF批注只标物理页，不假高亮；无法定位正文时置于首页问题索引并说明缺口。四层覆盖、人工状态、历史受检身份、已知未解决关键问题、不可用/隐藏预测均如实展示。报告或批注始终不是提交正文。展示或来源变化后迟到产物拒绝发布，可以按新context重新生成；历史文件继续可取件。

本批开发自测使用真实非owner PG、S3、PDF解析/LibreOffice与显式Mock模型，真实模型付费0。尚待独立架构/测试/产品/用户验收；FR004跨章节矛盾、FR005范围残留独立检测和完整两轮比较尚未实现，不以开关、通用核心核对或报告生成代称完成。
