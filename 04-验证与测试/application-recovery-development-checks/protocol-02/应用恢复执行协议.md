## 2. 资源和权限：新独立PG集群，拒绝任何原地恢复

选择独立 PG17+pgvector 容器和全新 volume，避免在现有PG集群改全局角色/成员关系。镜像用 `deploy/compose.external.yaml` 固定的 digest，新增自有 compose 文件不改原件；loopback空闲端口由plan预先指定并探针，不复用55439/55441或现有broker端口。集群、volume、容器和数据库均含随机 recovery UUID，保存 Docker 实际ID、PG `system_identifier`、新库OID与新库UUID收据；只允许工具本次自己创建且身份一致的资源。容器名/前缀本身不构成恢复授权。起容器前发现同名资源或非空卷立即拒绝，不使用外部已有卷。源owner DSN不提供给恢复目标工具，源备份读取仅使用本次自有新源集群初始化时建立的专用 backup-reader 只读身份；业务API不扩权。

独立新集群 bootstrap owner 使用全新随机口令，仅私有600文件持有；所有连接在首DDL前验证 `current_database/current_user` 和本次cluster身份。DSN复用fresh02的严格libpq身份规范化策略：拒query/fragment/多host；不得靠URL替换path声明目标。容器 `PGPASSWORD` 仅继承子进程环境，不进入argv/日志；私有配置不进入导出。

完整恢复前先审查源快照角色标签、ACL和对象owner：只接受固定能力组 `tender_api/tender_worker/tender_score_read/tender_research_read/tender_research_worker/tender_model_train/tender_model_evaluate/tender_model_score`，以及清单明确列出的源对象owner标签。另允许本次源初始化已登记的唯一 backup-reader NOLOGIN 组标签（受控UUID格式，精确来自manifest，不能任意provider文本）。全部在这个新集群建立为 **NOLOGIN、非super、无createdb/createrole/replication/bypassrls** 的角色；不恢复任何旧LOGIN口令、原LOGIN成员关系、cluster globals或外部连接。源owner标签仅用于保留对象归属和 SECURITY DEFINER 的权限关系，绝不继承源owner的super属性。若标签撞上本次bootstrap owner、PUBLIC以外未知ACL grantee、扩展owner不支持或角色依赖不闭合，预检失败，不自动放宽。

`pg_restore --exit-on-error --single-transaction` 在本次随机新库执行，保留原schema、函数定义、对象owner、ACL、column ACL和default ACL；不能用一轮 `GRANT ALL` 代替原权限。允许source owner标签在新集群存在，故无需字符串替换pg_dump SQL。恢复owner是本次新bootstrap账号，普通API/Worker不成为对象owner。扩展必须与清单版本/namespace一致。完整恢复后以目标专用备份身份核全目录/行摘要，API仅验证其合法应用可读范围；再核 `pg_get_functiondef`、SECURITY DEFINER/search_path、trigger、constraint、index、type、sequence定义及ACL；ACL的owner身份标签可以保留，LOGIN替换只发生在新集群的角色成员绑定。

随后只在这个新集群创建全新随机受限业务LOGIN。新API仅加入 tender_api，新Worker仅加入 tender_worker；研究/训练/评估等分目的新LOGIN可验证后保持不交付runtime。记录各新LOGIN当前DB/user/flags/继承角色/非owner。撤销PUBLIC对目标DB的CONNECT；最小验收仅给API CONNECT，其余LOGIN不发给运行harness且不能CONNECT该目标库。API正向登录/工作与DDL、角色管理、owner SET ROLE负向都要真实验证；不能将 `default_transaction_read_only=on` 当权限隔离。

源SQL是来源和审查身份，不在已恢复schema上再次执行。15份SQL用于创建另外自有的“空白参考库”，比较已知schema的结构/权限口径；不会在已有源库或旧readonly恢复库跑补权DDL。完整归档额外schema照常保留，无法解释其角色/函数依赖则拒绝应用可用标记。

## 3. 同一快照、完整档案和引用闭包

新 snapshot 入口独立实现，复用冻结 generic 的纯目录/摘要/对象校验函数，不修改旧实现。使用独立 BACKUP_DATABASE_DSN（不得借名输出为 API_DATABASE_DSN），以专用备份 LOGIN 开 `REPEATABLE READ READ ONLY`、`pg_export_snapshot`；目录、每表摘要、引用清单、ACL/owner、typed blob FK关系和队列分类都在同一事务读；pg_dump以同一专用备份 LOGIN `--snapshot`，保持快照事务直至完成。源保持在线，不停服，不用事务开始时间冒称单调业务时序。

档案是完整用户schema目录、dump、逐表行数及摘要、完整 `design.blobs` 精确key字节与SHA/尺寸；所有非系统schema均发现。原有模型artifact、模型response、chapter输入包、模板/方法原件及其审计/登记关系全部保留；依据实际FK目录列出 `blobs` 的直接及多跳引用，而非只认document_versions。专用备份身份对任何表不可读、RLS/FDW/外部依赖不受控、blob缺失或SHA不符立即失败。新增typed blob例：model_artifacts、模型响应证据、章节输入包、模板方法原件至少各一条自有样本，独立回读关系和值，不能仅用空表计数证明其正确性。

未正式登记的 uploads/provider multipart 暂存不通过桶LIST发现；从快照的登记key逐项分类为 `registered_complete` / `registered_staging_unqualified` / `provider_upload_pending` / `key_missing_or_unknown`。本片保证正式blob字节完整；暂存不完整则在收据中明确不能续传/不能恢复在途，不隐去丢失。未知providerID不重建远端init，不清理原用户对象。

全档案目录700、文件600、排除Git；报告只出数量/哈希/合成UUID，不出正文、口令、签名URL、nativeUploadId。数据中本来存有的session/credentials/调用审计等仍属于私有dump，公开报告不能枚举这些值。备份上限沿用当前开发工具，超过限制明确失败，不能称容量验证。

## 7. 失败与恢复CLI契约（拟实现）

命令统一 `python -m deploy.application_recovery <command>`；公开参数只允许plan/归档路径/receipt路径，不接受任意target DSN或existing DB。私有base/credentials只能路径输入，不echo。

- `plan --baseline <json> --assets <json> --output <private-dir>`：无远端写，验证输入字节、角色/权限allowlist、资产、空间预算和目标计划；无秘密的public-plan可供审查。
- `snapshot --plan <private-plan>`：专用受限backup-reader同快照新档案；并发插入反例证实快照后提交不进dump/manifest；所有objects严格精确key。
- `restore --plan <private-plan> --archive <private-dir>`：先完整本地校验和源身份拒绝，再创建自己全新PG cluster/volume/DB/LOGIN/targetprefix；逐阶段不可覆盖receipt；失败不产runtime可用标记。
- `verify --receipt <private-receipt>`：先DB/用户/cluster/locator身份，再以目标专用备份身份核全目录/摘要/关系/对象/权限（不能要求API越权读certifications）；只有全部符合才可进入app check。
- `application-check --receipt <private-receipt> --credential-file <private-file>`：仅固定根白名单ASGI，无模型/consumer，产明确分能力结果。
- `inspect-queues --receipt <private-receipt>`：只读状态分类/数量/摘要，不reset/replay。

任何目标复用都拒绝，工具失败后不自动DROP/删对象。重试根据自己创建resource-ID收据，仅允许从明确阶段续**校验**；不能重放未知CREATE/PUT/restore。阶段不明给安全失败收据，保留新资源给人工审查。清理如未来需要只接受精确本次resource IDs，单独显式命令且不列桶；本片默认保留全部已引用对象和恢复库。

### 9.1 一次初始化与固定对象权限

本片完整开发正例使用自己新建的独立源PG cluster/volume和15份固定SQL。**只有该次初始化尚未发任何运行profile时**，bootstrap owner在目标cluster/system_identifier和随机DB身份核对后，创建 `twb_backup_read_<32hex>` NOLOGIN组与 `twb_backup_login_<32hex>` LOGIN。标识符由工具生成、不接受调用者任意角色名。LOGIN INHERIT、NOSUPERUSER、NOCREATEDB、NOCREATEROLE、NOREPLICATION、NOBYPASSRLS；只加入该唯一backup组，无ADMIN OPTION，不加入tender_api/worker/research/model任何组、pg_read_all_data、pg_read_all_settings、pg_monitor、pg_execute_server_program、pg_read_server_files等预定义角色，不可SET ROLE到owner或用途角色。

全部15份schema完成后，按已固定catalog逐对象 `GRANT USAGE ON SCHEMA ...`、`GRANT SELECT ON TABLE ...`、`GRANT SELECT ON SEQUENCE ...` 给该NOLOGIN组，安全Identifier引用schema/名称。包括model_release.certifications、封存label/export表和未来被计划明确纳入的score schema；它们的完整备份读取权不授给业务角色。序列仅SELECT，不授USAGE/UPDATE（不得nextval/setval）。不授INSERT/UPDATE/DELETE/TRUNCATE/REFERENCES/TRIGGER、schema CREATE、数据库CREATE/TEMP、业务函数EXECUTE、large-object写等。所有权限依据实际已初始化对象逐项生成并冻结到private permission manifest，不设ALTER DEFAULT PRIVILEGES自动全读；初始化后新增表一律使完整snapshot预检失败，需下一份完整fresh计划，不能按碰到42501临时补权。

专用备份组无任何显式function EXECUTE。对所有非extension用户函数（尤其SECURITY DEFINER、purpose RPC、历史资格封存/任务领取/模型开封/发布/费用等），以has_function_privilege核备份LOGIN的**有效**EXECUTE为false，不能用直接REVOKE忽略PUBLIC继承。若基线遗漏PUBLIC撤销导致有效EXECUTE，停在预检并给具体函数/DDL反例交审，不能静默修改PUBLIC/业务角色ACL来使测试通过。仅允许extension自带、已绑定extension/version/函数签名与定义身份的纯类型/运算支持函数通过PUBLIC保留；这不是放行用途RPC，也不按provolatile标志自动判定任意函数安全。系统catalog内pg_dump必需的读取/pg_export_snapshot保持PG标准能力；pg_catalog内危险函数需核真实ACL，特权角色成员与服务器文件/程序执行均不得获得。

数据库PUBLIC CONNECT/TEMP在该新源初始化时撤销，分别显式给该backup LOGIN和独立API等预定角色CONNECT；backup LOGIN只CONNECT自己的新源DB，default_transaction_read_only=on与statement_timeout作附加约束，但真实权限负例在关闭read_only的连接里执行。数据库owner及所有业务/函数/sequence对象owner都不能由该备份身份直接或间接继承。新集群其他DB无该LOGIN CONNECT能力（postgres/template的PUBLIC CONNECT也需在这个新集群初始化内限定，不碰既有集群）。

### 9.2 读取与恢复路径

source snapshot的目录、逐表摘要、typed blob/FK关系、ACL、队列分类、pg_export_snapshot和pg_dump全部用这个相同专用LOGIN与同一RR快照。预检逐表SELECT与逐序列SELECT，pg_dump实际读全表（certifications即使空表也必须成功），任何不可读对象均失败，不能交付“完整”manifest。若源含large objects、外部表/RLS、subscription/FDW或其他未受控对象，本片拒绝并报具体未支持，不授广域特权绕过。

归档保存该NOLOGIN backup组的标签和精确SELECT ACL作为源权限证据，但不保存其LOGIN口令/成员关系，不把任意源LOGIN作为允许恢复标签。目标新独立cluster仅重建这个受控NOLOGIN组来保留ACL；建立全新随机目标backup LOGIN加入该组，只用于恢复完整校验、不是模型/Worker身份。目标backup凭据不能因为API看不到certifications而加入API配置。目标业务API在恢复后仍只能读原业务ACL允许对象，API对certifications真实SELECT应继续42501。

### 9.3 用途隔离和配置生成

备份配置独立600文件，只含BACKUP_DATABASE_DSN、源/目标receipt身份和必要对象访问配置；无API/Worker/研究/训练/评估DSN、无远端模型key。PG dump子进程以环境PGPASSWORD传递，不能DSN进argv。模型/Worker普通runtime profile采用**正向字段allowlist**重新构造，不复用仅剥OWNER的旧helper：显式拒BACKUP_DATABASE_DSN、backup口令、owner/purpose DSN进入API/Worker、研究CPUlauncher、provider process环境。启动harness也采用env允许集合，不能从ambient环境重新继承备份DSN。public manifest只含role名和权限摘要；完整数据/封存labels和dump均私有。

snapshot工具必须校验该LOGIN有且仅有登记backup组、受限flags、非owner、有效DML/函数/特权拒绝，且cluster/database/LOGIN匹配新初始化收据；不能靠变量叫BACKUP_DATABASE_DSN信任一个API或owner连接。对既有环境若没有这次初始化创建的backup身份，命令拒绝且报告“需要已审独立备份授权/新fresh”，不自行创建/补权，不退回owner取数。

### 9.4 必测新增接受条件

1. 15SQL完整新源下，业务API对certifications为42501；backup LOGIN同表SELECT成功，完整pg_dump/所有表摘要成功，不漏空表。
2. sealed label/export可被backup完整读取，但业务API/训练/评分/Worker权限保持原ACL；真实模型/CPU白名单不含backup DSN。
3. backup关闭read_only后INSERT/UPDATE/DELETE/TRUNCATE、nextval/setval、CREATE TABLE/ROLE、SET ROLE owner/任意用途角色均拒；专用purpose RPC至少claim_job/read_final/seal_input及全部用户函数有效EXECUTE拒绝。
4. 检出PUBLIC间接EXECUTE、预定义宽角色继承、owner间接继承、未知直接LOGIN ACL、初始化后新表、伪receipt/旧集群/旧库时0补权/0备份成功。
5. 目标完整恢复并以新backup身份全表校验；新API真实登录与同步新工作成功，同时certifications读拒；旧queue/unknown fee和原历史行不改。
6. 生成profile与启动子进程env逐项负查，不出现BACKUP DSN/role/password或owner/purpose/model key；报告不输出这些值。
