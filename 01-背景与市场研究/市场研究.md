# 背景与市场研究

文档编号：RES-001  
类型：市场研究、选型依据与来源记录  
研究范围：公开资料；产品实测、正式询价及真实业务效果不在本文范围，尚未验证

## 1. 研究结论

**系统是公司内部的投标系统，目标是中标。研究围绕三件事展开：投标文件会不会被淘汰（废标／否决项、强制性要求）、技术分能拿多少（评分条款）、价格分与技术分如何换算（评标价规则）。一期的两个 P0 是废标／否决项检测与评分预测，指标口径见[统一指标](../02-业务与产品/一期方案与验证计划.md#7-指标与验收口径)。**

| 研究判断 | 证据及可信程度 | 对本项目的建议 |
| --- | --- | --- |
| 废标、否决是真实且常见的淘汰原因 | 第 3.6 节：一份道路项目评标表在 208 家投标中列出 20 家否决及依据，涉及主要管理技术人员配置、项目经理或其业绩等资格要求；只是单个项目，不能外推比例 | 废标／否决项检测作为 P0，登记提交前设闸门；规则的性质（否决、强制、评分、建议、例外）必须区分 |
| 合肥公开项目存在不同评标、定标办法，不能把同一流程用于全部市政投标 | 第 3.4 节官方公告与完整招标、补疑对照；道路和园林配套的实际路径已核实，其他项目未取得的条款保留未知 | 先识别采购对象、项目标段与规则版本，再核对技术标；补疑变化后自动重新评审 |
| 技术分改善后仍受报价衔接、异常低价澄清与定标条件影响 | 第 3.4 节：技术评分合理价格法在技术入围后按价格区间推荐，园林配套项目以技术、商务、报价等级组合形成候选 | 报价模拟只计算评标价规则下的价格分与风险提示，并说明技术分与报价的换算；不替代对评标办法的判断 |
| 市场已经覆盖生成、审查、查重、模拟评审、企业资料管理等环节，单纯生成正文的供给重叠较多 | 第 5 节供应商公开说明；证明公开定位，未证明实际质量 | 不做自动编标；系统的价值在于“是否会被淘汰、哪里会丢分”的核对与预测 |
| 采购端 AI 评审与投标人自查是不同市场，平台产品不能直接视为企业提分工具 | 国家政策分别设置两类场景；新点、优质采、用友公开方案主要面向采购评审 | 明确购买对象、具体模块及可获得的服务，接触平台供应商不等于获得官方评分模型 |
| 模拟分数与真实技术分、技术入围之间的关系尚未获得本项目验证 | 已有供应商宣传模拟评审，本研究未取得独立市政评测集及对应官方成绩 | 评分预测只作研究用途并标注“未校准”，用已登记的官方技术分配对校准，配对不足 20 组不给误差 |
| 数据是瓶颈 | 公开评标公示只披露部分成绩且不含正文（第 3.6 节） | 公示用于规则与阶段观察；预测的校准依赖公司自己的完整提交正文与官方技术分，历史标书与官方成绩依赖公司提供 |

以上为研究判断，未形成供应商质量排名、采购决定或中标率提升承诺。现有 CASE-001 保持为样本之一，本研究不以单个案例解释市场需求或评价竞品。

## 2. 研究范围与方法

研究站在本公司投标人的角度，面向中国招投标工具与服务供给，重点检查安徽、合肥及市政施工场景。覆盖商机与项目筛选、技术标编制、审查修改、模拟评审、企业投标协作、采购端评审平台、通用 AI 与定制建设方案。研究用于解决实际投标障碍及选择公司可用能力，不开展本系统的销售市场、客户增长或软件盈利研究。

公开资料核实日期为 **2026-10-06**。采用政府及交易机构信息、供应商产品说明、技术项目官方文档；通过横向比较形成研究判断。产品按市场路线选择，属于有目的的代表性扫描，不是随机市场抽样或全量厂商名录。

| 证据类别 | 本研究如何使用 |
| --- | --- |
| 官方发布事实 | 政策、项目说明、交易统计；注明地区、项目类型、日期与统计口径 |
| 供应商公开声明 | 记录功能与定位；不据此确认准确率、客户规模、提分或入围效果 |
| 本项目实测 | 须有输入版本、软件版本、输出、人工复核和结果 |
| 研究判断 | 写成建议或假设，说明用什么证据检验 |

不采用商业榜单中的市场份额、宣传排名、匿名好评或未经说明的效率百分比作为选型事实。没有公开说明的功能记为“需要验证”，不推断产品不具备该能力。公司资料未上传至这些供应商，本研究没有注册采购、付费试用或供应商访谈。

### 3.3 公司适用范围与取舍

业务数据引用[业务输入](../02-业务与产品/一期方案与验证计划.md#12-业务输入)。工程成交金额与供应商用户量只作背景，不用于推算本系统的收入。取舍先看是否改善当前中标障碍、效果能否用真实结果复核；系统不管投标人的内部成本，也不比较人工制作标书的成本。供应商的 SaaS 套餐、许可及结果收费不是本系统的目标。

## 8. 公司投标能力与验证重点

以下是市场比较形成的能力优先级，与[业务需求说明书](../02-业务与产品/业务需求说明书.md#5-业务需求与优先级)一致。每项能力对应具体中标障碍，不能仅因竞品有该功能就列入范围。

| 优先级 | 企业能力 | 需要实测的差异 |
| --- | --- | --- |
| P0 | 废标／否决项检测 | 招标补遗、否决、强制条件正确关联；违反与无法判断都被看见；补遗变化后可重新评审 |
| P0 | 评分预测 | 评分条款分值提取；失分点与人工复盘的一致性；与官方技术分配对后的误差；综合总分不作技术标签 |
| 辅助 | 响应矩阵 | 满足、违反、无法判断、检查失败；满足必须有正文依据 |
| 辅助 | 前后矛盾与范围残留检测 | 数值矛盾召回与误报；模板残留对象的覆盖 |
| 辅助 | 报价模拟 | 评标价规则表达的覆盖；基准价取法；风险提示 |
| 辅助 | 评审报告、导出、规则与事实、结果登记与校准 | 报告与页面一致；批注版 PDF 原位标注；结果与提交版本配对 |

这不代表其他产品都缺少这些能力。建设理由应来自同任务对照后的实际缺口。

## 9. 候选验证与参照

### 9.1 候选分组

按比较目的选择候选，不按宣传排名。先验证主要痛点，再扩展其他能力。

| 比较组 | 优先候选 | 选择理由与进入条件 |
| --- | --- | --- |
| 综合检查 | 广联达清标、筑龙标事通 | 比较响应、资格、格式和企业流程；确认可用模块与试用资料条件 |
| 施组编制与审校 | 爱标书、钛投标 | 比较从招标到施组及工程输入、补遗处理 |
| 专业／模拟评审 | 天幕慧眼 AI | 比较工程证据和模拟结果；无法提供规则依据与可核验结果时仅评价检测 |
| 单项检查 | 比对汪 | 建立格式与版本比对参考，不与综合核对混算 |
| 人工流程 | 现有 Word／WPS＋工程师 | 作为对照基线，判断检测结果与人工判断的差异 |

智标 AI、蝉标、筑巢等作为替补或专项对象。候选不满足输入、资料、输出要求时替换。尚未对外联系供应商。

### 9.2 参照的用法

| 参照 | 用途 |
| --- | --- |
| 商业产品的公开定位与演示 | 对照各环节的做法与输出形式，发现系统遗漏的检查项 |
| 官方评标表与候选人公示 | 观察否决原因与阶段结果，不用于训练预测 |
| 人工审核结论 | 作为废标检测与失分点的参考标准 |

参照不构成采购决定；系统沿用既定技术栈建设，不在本研究中讨论技术取舍。

## 10. 同任务比较方法

### 10.1 同任务比较

初步功能验证建议 6—10 个完整市政项目，覆盖管网改造、道路和综合市政，以及文本 PDF、扫描件、表格、图示和补遗变化。数量用于暴露边界，不能支撑市场总体准确率或提分效果结论；现有单个案例不承担整个比较的参考答案。

| 任务 | 比较证据 |
| --- | --- |
| 规则与废标条款提取 | 关键废标、否决、强制条款及评分分值、补遗冲突、来源及定位；按文件类型统计遗漏 |
| 逐条核对 | 工程师先建参考判定；记录违反、无法判断、漏报和误报 |
| 评分条款评估 | 失分点与人工评分复盘比较；有官方技术分时比较预测误差 |
| 前后矛盾与范围残留 | 植入与自然存在的矛盾、残留对象，统计召回与误报 |
| 报价与价格分 | 评标价规则的表达覆盖，基准价取法，风险提示 |
| 报告与导出 | 问题与报告一致、Word 可编辑、批注版 PDF 原位标注 |
| 资料导出 | 项目、问题、来源位置与结果的批量导出和停用取回 |

固定任务、参考标准、输入和设置，记录产品及可取得的模型／规则版本。尽可能向复核人员隐藏工具来源和历史成绩，争议项由第二名工程人员复核。保留失败和未检出项。指标定义引用[一期验证计划](../02-业务与产品/一期方案与验证计划.md#7-指标与验收口径)，不另设含义不同的准确率。

评分预测纳入核心研究，可靠性单独评价：只纳入完整正文、真实技术总分、满分及规则可核实的项目，按项目／模板分组保留样本，检验误差与不适用情况。没有官方分项不阻止总分建模；对照试验见[一期方案第 8.3 节](../02-业务与产品/一期方案与验证计划.md#83-评分预测的对照试验)。真实入围还取决于同场竞争，不能只由绝对技术分推断。混合成绩按[数据规范](../03-数据与案例/数据管理规范.md)处理，不反推官方分项或扣分原因。

### 10.2 评标价规则与报价参照

报价模拟的输入是招标文件的评标价规则，本节记录第 3.4 节已核实的公开信息与系统可表达的范围。

| 项目与办法 | 已核实的价格相关规则 | 系统的处理 |
| --- | --- | --- |
| 技术评分合理价格法（SRC-035） | 技术入围后，报价评审通过的 S 家按价格从高到低排序，S 为奇数取不低于第 (S+1)/2 个价格者，为偶数取不低于第 S/2 个价格者，在该范围内按价从低到高推荐；同价优先技术分高；报价评审不足 3 家否决所有投标；推荐前有异常低价澄清与履约风险评审 | 这是推荐规则，不是价格分公式。系统用最高限价、异常低价线提示风险，不模拟推荐名次 |
| 定性定量评审＋票决定标（SRC-041） | 技术、商务、报价三环节组合成好、较好、一般等级形成候选；候选直接票决，最高同票时低报价优先 | 同上，不计算价格分 |
| 综合评估法（SRC-036、037、038、042） | 公告确认方法名称，具体权重与阶段尚未取得第三章 | 公告不足以确定完整计分公式，保留未知；取得后系统按招标文件预填评标价规则，由人核对 |

系统的评标价规则参数包括：价格分满分、高于基准价每 1% 扣分、低于基准价每 1% 扣分、可选最高限价和异常低价线、基准价取法（固定值，或竞争对手报价的平均值／去极值平均值乘以系数，可选把己方报价计入平均）。招标文件采用这种“基准价加线性扣分”形式的评标价规则时，可以直接建模；采用分档、区间推荐或其他计分方式的，需要先由人确认能否用上述参数表达，不能表达的不给出价格分。

### 10.3 统一演示问题

按相同范围比较：市政项目、招标补遗、技术标、图纸清单、重复修改。

1. 产品、模块、版本是什么？哪些面向投标人，哪些仅供平台或采购人？
2. 能否演示管网、道路、综合市政的完整任务及条款正文原页证据？哪些判断需要人工？
3. 补遗、扫描表格和图纸清单怎样处理？大小、页数、附件及并发上限是什么？
4. 如何区分否决、强制、评分与建议条款？无法判断的条款怎样展示？
5. 宣称模拟官方评分时，依据、授权、版本、独立样本及适用范围是什么？需要保留失败案例。
6. 报价功能按什么规则计算价格分？基准价取决于他人报价时怎样说明？
7. 能否批量导出项目、问题、来源位置、修订和结果？

## 12. 结论与依赖

公开研究明确了评审环境、代表性规则路径、淘汰原因的公开证据、投标工具与服务路线，为[BRD](../02-业务与产品/业务需求说明书.md)提供立项依据。未发现可凭公开宣传确认“企业工具模拟分等于青天官方分”或“提高模拟分必然提高中标率”的证据。一期的两个 P0 是废标／否决项检测与评分预测，评分预测只作研究用途、标注“未校准”；技术方法与对照试验见[一期方案](../02-业务与产品/一期方案与验证计划.md#83-评分预测的对照试验)。

| 依赖 | 取得前可以开展 | 取得后才能作出的结论 |
| --- | --- | --- |
| 公司正式结果记录 | 规则研究、输入治理与任务设计 | 公司的入围率、中标率、主要淘汰原因占比 |
| 合肥综合评估法全文及目标项目全套生效资料 | 已取得路径的解析验证，补遗冲突与例外识别 | 新路径的可执行规则、完整响应核查；不能套用外地权重 |
| 多类型完整提交、工程师参考标准与官方技术分 | 建立已有规则的原文参考清单 | 废标检测的召回与误报、预测的误差与校准 |
| 服务器与数据环境 | 公开规则对照与代码层面的自动化测试 | 端到端真实环境跑通与真实数据评测——依赖服务器与数据，尚未验证 |

正式导则、暗标要求和规则时效作为持续跟踪项；实际投标前按项目重新核实。公司资料依赖统一由[决策与依赖](../00-项目管理/决策与依赖.md#2-业务依赖)记录，市场结论不替代能力验证或业务效果验证。
