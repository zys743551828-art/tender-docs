# 功能保留对照证据

业务结论唯一维护在[GitHub实现功能保留对照](../../02-业务与产品/GitHub实现功能保留对照.md)。这里保存对照身份与可重复执行的静态引用核对，不是应用功能验收。

| 文件 | 内容 |
| --- | --- |
| [retention-matrix.json](retention-matrix.json) | 26组功能、目标设计落点、10项待办、75处固定提交的代码／测试位置、文件SHA-256及排除的未提交文件 |
| [check_preservation.py](check_preservation.py) | 从相邻tender-app／tender-research仓库读取固定Git对象，核对摘要、行号、引用和目标章节 |
| [result.json](result.json) | 本次静态核对结果和所读取目标文档的摘要 |

在tender-docs根目录执行：

```bash
python 04-验证与测试/feature-preservation-checks/check_preservation.py
```

要求相邻目录存在两个代码仓库及清单中固定的Git提交；读取`git show`，不切换工作区、不执行被读取的代码。检查只证明所引用内容与固定提交一致、设计落点和报告引用存在，不能自动证明人工比较结论完整、软件行为正确或模型有效。

本次没有重新运行应用、研究、浏览器、对象存储或真实模型测试。清单中的25组测试定位是已有测试定义；主题偏好未找到专项测试。75处包含实现、测试和边界反例，不能称为75项通过的功能测试。历史运行证据保留原身份，本目录不改写其结果或绑定摘要。

比较针对产品能力保留；全新系统仍独立建库、独立实现，没有旧系统迁移或兼容要求。本目录的分类和输入摘要保留对照时身份；十项细节的当前协议落点和独立检查见[开发准入检查](../development-readiness-checks/README.md)，不得从历史pending标记推断当前设计或软件完成情况。
