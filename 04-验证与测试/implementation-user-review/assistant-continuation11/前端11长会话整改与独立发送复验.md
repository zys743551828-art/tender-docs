PM 明确移交唯一 Mock 控制窗口后，先用两个登记成员读取全部可见项目会话的 jobs，排除 queued／running／cancel_requested 及待核账的项目任务；未触碰全局 unknown。正规新建一个自己的合成项目并设 `auto_review=false`，项目 ID `ed37a263-1675-4fbe-b1fe-ff7e5317bc41`。未上传资料、不进行正式评审、不执行操作卡。

在 UI 新建并继续这个项目主会话，手工输入一次中文问题，明确只讨论如何查原文、采纳修改，不做正式判断。仅临时把原控制文件改为 `answer`＋`project`，保留原 marker；**仅一次 POST turn，返回 202**。原固定 Worker 产生 **恰好一条 `mock_request`**，对应 job `8bb30eda-c4f2-4e5a-83b0-7a3dfeaa177b`；原 API publisher 形成 `published`。完成后立即恢复原 `hold`，控制 JSON 与进入前相同。

界面显示这个新问题及显式合成参考回答；刷新同一主会话后，两条新消息仍在，问题只出现一次，输入清空。390 px 再续谈时输入框可见、无横向溢出。未重试 turn，未执行新任务、模型 consumer 或 Action。

## 保留边界与工具失败

第一份正向脚本在旧项目设置预检断言处停止，未拿到可用准备状态，**不能据此断定旧项目开关为 true**。第二份正规创建项目并 PATCH 成功后，脚本把 `SettingsView.settings.auto_review` 误读为顶层字段而停止；两次均为 0 turn、0 Mock、0控制变更，原结果和截图保留。随后仅复用同一个已创建项目，修正读取，才执行本轮唯一新 turn，没有重建项目或盲重发问题。上述都是测试脚本准备错误，不列为产品缺陷。

最终只读回查两个成员的全局 unknown 及其对应调用账仍存在、仍为 unknown、仍要求核账且不授权自动重试；旧项目合成成功调用账与本轮新成功调用账均可从真实 job API 读回。未清除旧账或改动终态。固定 API／Worker 的 317 个产品源、12 个设施源和前端 11 全部源／资产逐字未变，前端 10 的 128 源／215 资产与原 P2 证据保留。服务进程 UID／argv 与已交接的固定运行身份一致，未重启服务。
