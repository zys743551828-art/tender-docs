# 数据与事务实现规约

本规约给出全新建库、领域写入和并发实现条件。业务行为见[详细设计](../AI投标工作台详细技术设计.md)，字段和约束以SQL为主，不另维护一份容易失真的字段表。

## 1. 初始化顺序与表责任

在空数据库依次执行[core.sql](core.sql)、[domain.sql](domain.sql)、[retrieval.sql](retrieval.sql)、[worker-functions.sql](worker-functions.sql)、[roles.sql](roles.sql)。任一脚本失败停止，不使用忽略错误继续建库。生产schema名可在正式契约冻结时统一改为app；设计脚本固定design和retrieval，不接触任何旧库。

逻辑文件／上传分片、fact head／更正链、规则决定沿用、matrix checks、拒绝明细及研究批次14张支撑表也在domain.sql初始化；全库共104张表。其事务及CAS按[保留功能实现规约](保留功能实现规约.md)执行，不能只根据SQL外键推断全部业务检查。研究执行统一使用reserve_research_call固定入口原子预留预算与model_calls，底层reserve_research_fee不作为远程调用授权；账单结算及预算暂停仍须在应用事务协调。

## 2. SQL类型、JSON与更新规则

UUID由应用生成；TIMESTAMPTZ存UTC，API使用带时区ISO 8601；Decimal经字符串交换，拒绝非有限值。JSONB只用于有Schema的可变结构：编辑器文档、条件／例外、页质量缺口、冻结manifest、模型结构化结果。外键、状态、金额、修订号与可检索键均为独立列，不能藏在JSON中。

`core.sql`与`domain.sql`内的不可变触发器拒绝UPDATE／DELETE；运行账号不拥有表，也无TRUNCATE或DDL权限。新判定、更正、撤销和重生成建立新行。messages允许补齐流式assistant parts，但完成后只能追加更正消息；完成保护由MessageService的状态检查实现，不能让模型任意覆盖用户消息。

数组形式的evidence_ids、rule_ids、source_version_ids须在写入事务逐项核验真实存在、版本和归属。数据库复合外键约束关键主关系；JSON和UUID数组的语义由用例层验证，不能因SQL可插入就认定业务合法。

创建空草稿时，在同事务写draft revision=1、各节revision=1、空文档JSON和首份完整快照；保存后才返回编辑器。修改目录和正文均产生新的draft_revision；未改变章节仍引用旧section_revision，不复制字节。

## 3. 锁序与事务边界

统一顺序：命令幂等占位→bid头→按全局ID排序的领域head→operation→step／action→来源图锁→stream头→Outbox。研究调用在step之后锁research_run，run调度/取消事务只锁run并写样本取消意图，不在持run锁时反向锁bid；跨bid逐个短事务处理。取消、正常完成与对账也遵守该顺序；已经持operation锁后不能反向锁bid。无bid的全局知识命令跳过bid，源head按ID排序。

来源图写入在READ COMMITTED事务中先单独执行`pg_advisory_xact_lock(90127,1)`，再插边，确保等待后使用新语句快照检查环；触发器是第二道保护。所有图写入遵守同一协议，不允许绕过它并发批量插边。大批索引生成在事务外，图边与正式引用只用短事务提交。

### 3.1 命令幂等

1. 计算规范请求摘要，包含命令、目标、If-Match、正文及明确的rerun_nonce。
2. INSERT commands，唯一键为actor、command_kind、target、Idempotency-Key；冲突等待对方事务完成，再比较request_digest。
3. 摘要不同返回409；摘要相同且response非空，返回已保存状态码、响应与必要对象ETag；不重复运行用例。
4. 同事务写最终response。暂时性数据库错误整体回滚，可以同键重试。业务拒绝要保留审计时，独立短事务追加拒绝记录，错误返回不能回滚它。
5. 幂等记录作为业务审计引用保留，不由短期缓存TTL删除；登录失败等非业务请求另有限流日志。

### 3.2 提交资料批次

锁bid和batch→确认所选uploads已verified、同bid、摘要一致→解析用户明确的资料角色与顺序→建立material_snapshot与assignments→更新bid.material_revision和current_material_id→写materials.committed事件与自动评审意图→提交。部分失败必须显式选定成功集合；同名补遗不自动覆盖生效顺序。

人工漏提更正使用POST rule-set-corrections，原子追加新包及本次新增规则的人工确认，移动current_rule_set_id并使旧评审过期；精确事务及字段验证见[保留功能规约第3.1节](保留功能实现规约.md#31-人工补充并确认漏提条款)。该命令由tender_api执行，普通Worker只读更正审计；禁止Worker替用户确认。

### 3.3 保存与应用AI补丁

锁bid、draft和目标sections→比对draft ETag及各base_section_revision→Schema与图片资源验证→追加section_revisions→复制未变章节引用组成全量快照→移动section和draft头→写审计与stream→提交。

应用补丁还锁action与来源head，验证before_digest、稳定节点ID、事实与规则revision；任何一个过期都不执行半份补丁。Undo以明确base_revision应用反向补丁并追加新修订。一次保存最多100个改动章节，单节JSON起始上限2MiB，超过返回413；上限统一配置并记录在环境清单。

### 3.4 评审发布

模型调用与产物上传先完成；事务内锁bid、operation、step和所需来源head，重查fence、输入digest、取消、来源有效性；追加结果与effect_receipt。只有目标输入仍等于当前有效输入，才能移动current_review_id。旧输入结果仍保存为历史，不能仅按完成时间更新当前。

跨对象一致条件不仅是material_revision：还包括正文版本、规则／事实包、解析配置、方法、启用的内容检查。展示预测开关不制造新评审。发布前后相同来源被停用，以head锁与impact事件确定先后，不靠缓存传播速度决定。

### 3.5 标准提交与成绩更正

预检GET只给说明。登记事务重新锁bid和所有gate所读head，查询当前正文、完整核心覆盖、最新有效人工决定与资料一致性；确认后追加submission_records并移动submission_heads。原始预测与实际提交前合格盲预测ID固定保存于evidence/gate_snapshot，后续成绩不能重选预测。

标准提交的正文种类与评审正文一致性另有数据库触发器。其余gate条件仍由领域策略执行，不信任客户端上传的gate_snapshot。线下补录不调用标准gate，不伪造正常放行；score样本准入在结果核验后重新检查，不能用补录类型直接判全部有效或全部无效。

成绩更正在同事务追加outcomes、核验决定、移动outcome_heads、标记受影响样本／模型及发事件。未知值与0分不同；value存在时maximum必须存在且有限。模型路由发布同事务检查acceptance.model_id与目标model_id一致、accepted、scope与回退对象合格，不能只验证外键存在。

## 4. 查询与分页

列表使用`(created_at,id)`降序稳定游标；游标为签名JSON，含资源类型、筛选摘要、时间与ID。页面大小默认20、上限100。更换筛选丢弃旧游标，分页不返回精确总量时使用has_more，不虚构total。查询可用REPEATABLE READ保持单次页面跨表投影一致，避免长事务跨用户翻页。

响应矩阵按全部生效规则左连接本轮判定，未判定行不能消失。问题列表按severity序与稳定ID分页，unknown coverage单独返回。数值隐藏在序列化前执行，不把隐藏预测留在未显示字段、图表数据或下载URL参数。

对大原文和向量设置查询超时；API查询起始statement_timeout=3秒，检索=5秒，worker元数据=10秒。批处理显式拆页，不调高所有API超时。索引命中、锁等待和连接池均需真实压测。

## 5. 权限与数据可见性

[roles.sql](roles.sql)提供不含密码的NOLOGIN能力角色；部署时创建独立LOGIN并只授对应能力，凭据从密钥服务注入。应用角色无建表和改schema权限。API服务承接人工决定；worker不能直接写标准提交、官方成绩、人工决定或模型路由。普通Worker和研究Worker领取／完成事务均先调用lock_worker_bid(uuid)，再以自己的能力连接锁operation／step；该固定SECURITY DEFINER函数只取得已存在bid行锁，不返回资料、不改业务字段，固定search_path并撤销PUBLIC执行权。函数owner为建库所有者，运行LOGIN不是owner、superuser或schema拥有者。研究Worker负责research topic上的样本operation，拥有step/effect/model_calls、run/attempt和审计/SSE能力；普通Worker不执行研究预留，研究Worker不发布业务predictions。评分输入通过固定用途的`formal_score_context(review_id)`读取，不授予成绩、对话和任意检索函数权限。

评分只读连接与领域提交连接分开注入，评分输入构造器只收到只读端口。通用聊天工具无法取得SQL连接或更换数据库身份。数据库角色是代码用途隔离的补充，不能替代来源闭包、时间、样本分组和模型验收。
