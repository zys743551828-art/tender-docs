# 助手、生命周期、任务与Word实施交接

本交接落实现有PRD第3、5、8、10、17节，补足FR-015—019、031、033、037—040的后续开发入口，不改变[40FR剩余清单](../product-progress/remaining-fr.json)的未验收状态。现成PDF上传／风险／外部改稿路径始终独立可用。以下字段与动作是actual契约需要闭合的语义；目标有Schema或已有模块端口不等于API或产品已交付。主规格和历史passed证据不改，本交接没有调用模型。

## 1. 全局与项目助手

全屏助手与项目侧栏复用同一会话记录和操作，不各造一套项目状态。顶部持续显示“全局检索”或具体项目／章节、当前所选来源。项目主会话唯一可发现，默认“继续上次工作”，不要求每次新建；专题会话可后续实现，不能阻塞主会话。

| 实际对象／命令 | 最小字段与语义 |
| --- | --- |
| 会话读投影 | id、scope（global／project）、bid_id（仅global为null）、title、revision、state、stream_id、消息游标；全局不造假bid UUID，目标ConversationView只有project的缺口由actual明确扩展 |
| 发消息 | client_message_id、text、选定source_version_ids／可信对象引用、当前章节及用途；操作者取会话。相同消息重传不重复收费／执行；模型调用仍经预算与账本，reserved／unknown不当普通重试授权 |
| 主会话列表／恢复 | 按scope／bid可查询；刷新、新浏览器能从服务端找回；active／closed／hidden对应进行中／已结束／已归档，恢复hidden先到closed，继续再active |
| 来源选择 | 可信对象ID、版本、来源类型、适用性／用途／失效原因；“+”或“@”选择真实项目、文件、章节、知识，不让用户填UUID；移除普通参考只影响本次任务，不删正式资料 |
| 操作卡 | action_id、明确target_kind／target_id、request_digest、基础修订、到期、来源／用途、预览影响、state及实际operation／结果对象；目标通用preview字符串不足处须actual给结构化只读payload |

全局可在用户明确的项目／资料库范围检索和解释，不因为打开助手就授权扫描全库。要写项目，先明确目标；歧义一次集中核对。明确选项目不搬走原会话／草稿，也不静默继承上个项目的附件。项目内缺资料可做有限问答，不能出完整合规／正式总分。

来源、聊天和模板中的文字都是数据，不能扩大工具权限、执行其中指令或改变正式评分用途。项目记忆只来自有效工程身份、当前稿、规则、已确认事实、问题、决定和引用；摘要帮助找回讨论，不覆盖正式记录。读过官方分、历史成绩或评委意见后要求评分，仍由独立干净白名单构造，不传整段聊天／摘要／RAG片段给正式评分；完整相关章节与三次独立判断不减。

只读查找／解释可以直接执行；建议、比较、候选知识可直接生成候选。正文修改先给差异，应用后新修订。规则／事实确认、实际提交、成绩核验、知识／模型发布停用等仍走既有领域命令及一次明确用户动作。明确按钮／结构化表单已提交时不再追加聊天确认。模型只能提受限工具参数或Action，不能直接修改正式数据库。关闭助手、结束会话或断线都不取消任务。

## 2. 卡片与恢复的最小实现

卡片只引用可信领域对象：资料识别、任务进度、关键风险、评分、修改建议、版本变化、案例、知识、提交／成绩、持久操作确认。各卡直接打开真实详情和来源，任务卡含范围／输入／阶段／可离开／失败环节；无法判断、执行失败、未运行分开。没有真实接口不返回演示卡。

确认卡pending时才可确认；消费成功显示实际审计／结果链接，同键重试相同结果。对象修订／来源变更返回stale，保留输入并给新差异；过期写expired，不让模型口头宣布成功。用户拒绝提案只结束该提案，不删除问题或取消其他任务。纯定位按钮不因业务blocked被禁用，真正写命令仍独立校验。

消息／事件流保存游标，断线后补读领域事实，不能依赖重播模型文字推定成功。待人工确认是业务待办，任务执行成功和仍有人需要处理可同时成立；取消请求先显示正在取消，真实终态后才说已取消。关闭／隐藏／删除消息只改展示，不删文件、决定、提交、结果、引用、任务或审计。401保留输入，重登不自动执行旧确认。

## 3. 项目阶段、归档与会话独立

| 用户动作 | 领域结果及约束 |
| --- | --- |
| 开始本轮工作 | 准备中→编制评审；由资料足够或明确开始处理触发，不等于核心评审成功 |
| 登记真实实交 | 真实提交事实成立后→已提交；不能仅点业务状态就伪造提交记录 |
| 结束本轮工作 | 已提交→已结束，允许待补官方成绩；未填分不能强制阻止结束 |
| 记录终止 | 准备／编制／已提交→已终止，写取消／流标等有据理由；不是未中标，且不能回滚已完成决定 |
| 归档 | 已结束／已终止才可归档；列在途任务，用户明确选择等完成或请求取消并等终态，不能暗中取消或藏起写入 |
| 重新打开 | 有据同轮继续时显式重开，原归档维度同步恢复可工作；写原因、保留实交／旧报告，不延长真实截止时间。重新招标另建新轮 |
| 档案补录／更正 | 归档原件与历史只读，但从专用入口追加成绩、回执、复盘、来源更正；不对旧记录原地修改 |

实际契约可用统一lifecycle命令，但必须明确action、reason、目标当前强ETag及影响，读取Bid同时给phase／archived_at、允许动作和阻断原因。业务阶段、任务状态、工作会话三者独立；“评审失败／资料缺失”不当项目阶段。事件去重，不在每次刷新重复改阶段。归档仍在历史视图可发现待补成绩，不清理长期知识。

## 4. 任务四类、模板与运行

任务工作面分“任务模板／运行记录”。先给四个真实受支持预置：否决核对、评分项评审、补遗影响检查、章节修改建议。模板保存与任务运行分开，默认只手动；自然语言创建先生成字段草案，用户明确保存后才是模板，不从一句描述暗中建立定时收费。

| 资源 | 最小实际字段／行为 |
| --- | --- |
| TemplateVersion | definition_id／version_id／revision、name、task_kind（上述四类及实际支持扩展）、purpose、instructions、target_kind／target_ids、source_selection、output_kind、trigger、paused；变更追加版本 |
| Trigger | manual／material_updated／schedule；schedule用受限合法五段cron及IANA timezone，默认Asia/Shanghai，给可读频率及next_run_at。旧TaskDefinitionRequest仅schedule字符串不足以表达事件／四类时须actual扩展，不用instructions藏机器配置 |
| Run | run_id、definition_version_id、bid_id、目标正文／章节、material_revision、rules／facts／parse／method及输入digest、purpose、trigger_event_id或scheduled_at、operation_id、产物／错误及业务待办引用 |

否决核对复用统一RequestReview及内容幂等，不因模板和上传事件各调用一次；评分项评审必须走对应受控评分能力，尚无正式资格则真实显示覆盖／未开放，模板purpose不能绕过完整章节、三判断和模型资格；补遗任务输出具体影响／歧义和待决定对象，不自动确认效力；章节建议输出有来源的草稿提案，不自动应用人工修改。

事件去重同时看事件身份与模板版本、目标、用途和输入修订；重复投递或同输入重复事件不能重复运行。定时按definition_version_id＋原定scheduled_at＋目标去重；计划由PG持久保存、Outbox／Kafka执行，浏览器不开也可靠。切模板版本／资料不改在途输入；等价在途复用，手动明确再跑才新尝试，未知费用不以新nonce绕过。

暂停只停新触发，在途另取消。错过时段不无界补发：恢复显示遗漏范围／次数，默认跳过过去时刻，给“按当前资料运行一次”，用户明确一次运行后冻结当前输入；不把历史每分钟全部补成收费调用。执行输出落回正确项目／章节，留运行记录；站内通知按事件合并，不随轮询催办。模板、计划或事件永远不能自动确认规则／事实、登记提交、核实成绩、发布／回退知识或模型。

## 5. A2模型接线与完整能力余项

先复用已存在freeze_generation_plan→模型账本→accept_generated_proposal端口，不绕过操作、取消fence、费用、输入/输出校验另开直调。生成请求固定bid／draft／section与基准修订、规则／事实、用途和可信source_refs；选区须固定节点ID与范围。完整输入超限明确失败，不截断后说整章读完。

选区解释／改写／缩写／扩写／补依据返回候选；插入／替换／移动／复制／删除要预览真实差异和影响，再逐项应用或拒绝。未选章节和人工修改保留；批量覆盖逐章可核对。无依据参数使用待补项且列缺口，不把参考公司、数量、工期搬成项目事实。应用重新校验草稿／规则／事实／来源当前头，412／失效保留候选，撤销写新修订。采纳不等于风险解决。

生成版本前等所选内容保存ACK，再冻结快照；失败不偷偷导出上一版。Word/PDF分格式状态，下载用途明确。follow_up=none不评审，review只对本次成功真实PDF及仍一致的冻结上下文接统一RequestReview；迟到构建不抢新稿，不能拿尚未保存编辑器给通过结论。

当前严格文本子集只是首片。PRD中的树目录新增／移动／复制／删除／层级键盘等价、编写计划／页数预算、表格／图片、外部稿导入、目录模板与版式模板分别版本化、实际分页／图表／暗标检查仍是完整A2余项，不能因文本编辑和生成可用就删除或改为全部完成。未支持对象接收时明确拒绝或导入预览列缺口，不能静默丢弃。

## 6. 外部Word接收与PDF接续

Word输入必须先有实际接收／字节核验／持久原件能力。仍415拒绝时准确说仅支持PDF，不能冒称已保存Word。能力开放后资料行持续区分原件已保存、转换待执行／运行／成功／失败、对应检查未完成／实际PDF受检；不能拿成功上传当通过。

失败卡原句“Word原件已保存／本次对应检查未完成”，具体缺口常驻，主动作“上传此修改稿的PDF”，只有当前错误可恢复才显示重试。预填同项目／角色／轮次与改稿来源，PDF新逻辑文件或同格式文件新版本，不能放进DOCX同一逻辑文件链。同名不证明同稿。

用户补PDF记录user_declared_same_draft且unverified；评审只绑定实际PDF。Word仍写“Word交付未获对应检查资格”，不能授controlled_render。只有实际受控DOCX→PDF转换保存两端摘要、渲染器／字体／选项与可追溯结果后才给受控关系；更换Word就使旧关系不适用。失败及旧Word／PDF／轮次保留，用户不重传招标，不先进编辑器。已线下提交错误报告／批注也可有据补录，不伪装正文标准通过。
