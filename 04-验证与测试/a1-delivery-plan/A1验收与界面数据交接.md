# A1验收与界面数据交接

本文件落实已批准PRD的A1行为，供前后端按实际契约联调；字段名来自目标Schema，动作白名单由产品Owner与后端收口。以下接口是下一批目标，不能当作当前PDF切片已实现；前端以本批实际OpenAPI生成类型。没有新增审批、先建知识库或先进入编辑器的条件。

## 1. 默认路径、落点和主要动作

现成招标／正文PDF→集中核对有影响的身份／角色歧义→批次完成→按auto_review自动评审或明确开始→风险结果→两侧原页→外部改稿PDF新版本→有效复检→提交前集中确认→真实实交登记。规则确认后置，事实库不是首次评审前置；直接按钮已经明确提交时不再聊天确认。

从项目列表进入，优先恢复有效位置；无位置而有当前review则进简洁结果；正在运行显示真实进度，其余进概览／资料。明确资料、问题、历史报告链接打开其指定对象版本，不能无声换为最新。完整章节编制仍按需，不把A2菜单塞成A1向导。

`Bid.next_action`／`ReviewView.next_action`提供统一`action/reason/target_url/blocked`。优先顺序固定：

1. 项目、目标正文、生效资料存在影响判断的冲突：一次集中核对，保留成功资料。
2. 必要解析／核心核对失败或关键覆盖未完：给受影响范围与恢复动作，不能先报旧风险结论可提交。
3. 当前有效轮次或保留的未处理关键风险：进入严重性最高问题及两侧原页；同级稳定按原条款顺序。处理第一项后显示下一项，其他关键问题数量始终可见。
4. 用户已进入提交检查才集中处理关键规则／必要事实；不在普通浏览时强迫全确认。
5. 用户请求改稿且无更高优先事项：进入对应评分缺口／建议，模型未验收不是投标人员必须完成的配置任务。
6. 只剩非阻断建议且gate满足：可登记提交。运行中不重复启动，评分不能可靠估分不单独阻止。

### 1.1 规则尚未准备完成时的一键接续

缺规则包时，`requestReview`可先受理持久准备请求与operation，不能伪造缺ID的ReviewManifest或提前给ReviewView结论。具体资源形状由A1实际契约导出，界面按以下语义执行：

| 状态 | 文案及动作 | 对象边界 |
| --- | --- | --- |
| 要求准备中 | 正在准备本轮要求，完成后自动开始评审，可离开 | 显示本轮正文与生效资料，不向用户暴露prepare／intent术语 |
| 规则准备成功且head未变 | 准备完成，正在评审〈实际文件〉 | 同一次请求自动冻结真实review并接续，无第二次开始按钮 |
| 准备失败 | 要求准备未完成：具体范围／原因；重试并继续评审 | 资料和输入保留，只重试受影响步骤，不把失败当没有规则 |
| 生效关系有歧义 | 核对生效要求：具体条款／补遗问题 | 只集中处理这次歧义，不让用户配置通用优先级或重传整批 |
| 尚未冻结时新资料到达，auto_review开启 | 资料已更新，正在准备新版〈文件〉 | latest-only归并当前新版意图；原准备运行留历史，迟到不能抢当前 |
| 尚未冻结时新资料到达，auto_review关闭 | 资料已更新，原请求已过期；使用当前稿开始评审 | 不把原V1人工请求悄悄换成对V2的收费评审；用户可明确发起新版 |
| 已冻结review后有新稿 | 该轮对应旧输入，当前资料有更新 | 原review身份不改；按开关另行处理最新请求 |

## 2. 页面与真实数据

| 工作面 | 首次读取与字段 | 必须呈现的状态／动作 |
| --- | --- | --- |
| 简洁结果／概览 | `Bid.current_body_id/current_review_id`；`ReviewView.id/current/operation_id/input_digest/manifest_digest/risk_count/core_coverage/coverage_layers/prediction/next_action/source_impact_revision`；冻结`ReviewManifest` | 一句关键结论、受检文件／版本、依据是否更新、关键风险及一个下一步。risk_count未知不可填0；历史current=false明显标历史／过期；任务结束不代表通过 |
| 响应矩阵 | `MatrixView.review_id/rows/coverage_layers`；`MatrixRow.rule/verdict/check_status/error_code/evidence_ids/finding_ids` | 未开始／运行／成功／失败／取消与业务判定分开；成功但证据不足是无法判断。行可打开要求原页及正文响应，缺失型只列已查范围；默认优先否决／强制、失败、无法判断，全部行可查 |
| 规则 | `RuleSetView.id/revision/material_revision/coverage/rules`；`RuleView.kind/statement/conditions/exceptions/scope/maximum/bands/evidence_ids/confirmation/decision_revision/carryover/origin_kind/manual_origin_rule_id/provenance_status` | 核心／评分／建议分类，原页与条件例外可展开；已沿用说明原决定身份；人工补入及待重新核验不被普通“已确认”绿标掩盖。空包不等于无规则 |
| 事实 | `FactSetView.id/revision/facts`；`FactView.subject/scope/name/value/unit/evidence_ids/confirmation/decision_revision` | 空集id=null、revision=0可以开始评审；主体／单位／适用范围／原页都可看，历史事实不冒充本项目当前可用事实。补替撤后旧轮过期，旧依据可回看 |
| 风险详情 | `FindingView.id/category/severity/verdict/statement/evidence_ids/searched_ranges/decision/decision_revision/origin_review_id/retained_known_critical/detection_run_state/lifecycle` | 风险、判定、执行与人工决定分开；误报驳回与有效复检解决分别表达；可回来源轮次，不因关闭卡片消失 |
| 提交检查／实交 | `GateView.allowed/bid_revision/body_version_id/blockers`；`SubmissionView.id/kind/body_version_id/review_id/submitted_at/gate_checked/evidence_ref` | 明确选哪份正文、哪轮核对及真实时间／回执；阻断按code/object_id/message定位修复。标准和线下事实两个入口，补录始终标未经过完整检查 |
| 报告／批注 | `ReportRequest.artifact_kind/format/presentation_revision/source_impact_revision`；`ArtifactView.id/artifact_kind/state/sha256/gaps` | 下载评审报告（Word）、下载批注审阅稿（PDF），正文独立入口；生成失败常驻，不返回空文件。隐藏预测及来源影响采用当前展示规则，原评审及旧产物不覆盖 |

四层`ReviewCoverage`分别用`CoverageLayer.state/planned/completed/denominator_basis/gaps`：source_scope必要来源范围，core_extraction提取计划与已知缺口，judgment已识别生效核心规则，scoring评分分值；`human_confirmation_pending`另列。展示“已识别核心规则核对10/10”，不写“原文规则100%无遗漏”。`extraction_quality=not_measured`显示检测质量待验证。当前解析partial不能被前端直接换算为核心核对complete；必要范围或图表是否影响核心不明确时必须保留缺口。

## 3. 明确操作、对象白名单与请求

下表是本批批准的对象动作映射；目标通用`DecisionRequest.decision`为string，后端须将对象级白名单落实实际契约／验证器，前端不得自由发送新值。所有写入仍携CSRF、幂等键及对应对象强If-Match；操作者只取服务端会话。

| 对象／界面动作 | 请求与唯一decision | 实际效果与禁止事项 |
| --- | --- | --- |
| 单条规则确认／驳回／暂缓 | `decideRule`＋`DecisionRequest`：`confirmed/rejected/deferred`，携`reason/evidence_ids` | 追加人工决定，不改旧包；驳回可能改变当前包有效内容并需复评，确认不等于正文满足 |
| 明确选中待处理规则批量确认 | `confirmPendingRules`＋`BatchRuleConfirmationRequest.items[]`的`rule_id/expected_decision_revision`，规则集ETag | 最多500，原子CAS；仅pending变confirmed，已confirmed/rejected/deferred返回skipped；不默认全选、不覆盖旧决定、不增加审批 |
| 已有pending事实确认／驳回 | `decideFact`：`confirmed/rejected`＋理由及原页证据 | 仅单条，无批量事实契约；未核实不伪装已确认，不要求先填满事实库 |
| 人工新增／替换事实 | `changeFacts`＋`FactChangeRequest.fact`及`replaces_fact_id`；已核对来源时按钮“保存并确认事实” | 该明确提交本身作为人工确认；同事务新集／新事实及人工确认和审计，服务端返回confirmed后才显示。缺依据／效力歧义不确认并保留输入，不再另走确认卡或岗位审批 |
| 撤回事实 | `withdrawFact`＋`ReasonRequest`，使用事实所属bid的facts head ETag | 形成新集，全部撤回也保留非零历史修订；旧评审过期，不能删除旧证据 |
| 问题确认待改 | `decideFinding`：`confirm` | 仍属open，显示已确认待修改，不自动变已解决 |
| 误报驳回／暂缓／重开 | `decideFinding`：`dismiss/defer/reopen` | dismiss须明确非空理由，可补依据，结束该问题阻断；defer仍未处理；reopen恢复待处理并留旧决定。服务端拒绝人工resolve／resolved_by_recheck绕过复检 |
| 请求建议、复制或采纳建议 | 读取／建议走项目会话及可预览Action边界；已有直接按钮同样可达 | 缺参数保持待补，不编造工程量；采纳是决定，不改原PDF、不结束问题。最小PDF路径允许复制建议到外部Word，无需先有章节编辑器 |
| 上传修改稿并复检 | 上传／commit后统一`requestReview`：`body_version_id/material_revision/trigger` | 同输入等价在途复用；明确同稿复跑才用rerun_nonce；有效新稿复核结果才可写resolved_by_recheck，旧报告保留 |

手工事实保存并确认是A1实际领域处理器需要闭合的语义，不把普通保存ACK当成已确认。若服务端不能原子完成，不能先摆承诺“保存并确认”的按钮；由开发／架构补齐事务，不让用户补一次重复确认。范围仍是已有事实确认能力。

## 4. 两条不可丢的不变式

**已知关键风险。** 统一风险清单／gate／报告并入本bid既有、尚未有效复核解决且未有理由人工驳回的关键风险（含待复核）。`retained_known_critical=true`且`detection_run_state=not_run_this_round`显示“先前检测发现，本轮未运行”；origin_review_id打开真实旧轮。关闭可选检测、新轮零发现不能洗掉问题；有据驳回／有效复核可结束该项阻断，历史保留。普通非阻断旧建议可折叠，不新增闸门。

**人工补漏。** “补充并确认条款”调用`correctRuleSet`，`RuleSetCorrectionRequest`含当前base_rule_set_id、reason、additions；`RuleAddition`明确性质／原文／条件／例外／scope／maximum／bands／evidence_quotes。合法来源逐字证据通过后原子新包＋新增confirmed，不重复确认；失败不部分写入且保留输入；旧轮过期、给人工重新评审入口。重提取必须保留来源仍有效的人工条款，与等价提取合并不重计；效力不明保留待核验／影响，有据替代／适用判定／人工更正可结束当前义务。不能用模型输出决定人工要求是否存在。

## 5. 必须闭合的实际读模型／命令

这些是现有产品行为的实现对接点，不增加业务步骤，也不代表目标技术方案或当前API已具备入口。开发／架构在A1实际契约给唯一形状，前端据此生成类型；本计划不凭空宣布新operation已存在。

| 必需信息 | 目标已有依据 | 本批实现必须提供 |
| --- | --- | --- |
| 历史轮次受检稿／要求／方法身份 | 已有`ReviewManifest`完整字段，`ReviewView`仅有manifest_digest等引用 | 可读取冻结manifest的投影或入口，不能用Bid.current_body_id冒充历史review正文 |
| 评审与实交记录刷新后可发现 | `getReview/getSubmission`为单对象读取，Bid仅有current_review_id | 本项目评审历史及实交记录的可恢复查询；不能只靠localStorage记住以前ID。沿用资料片真实历史入口的完成标准 |
| 单条决定的条件令牌 | Rule／Fact／Finding有decision_revision；集合读取有集合ETag | 每个可写决定对象必须取得明确的强ETag，或实际契约固定可验证的读取方法；不拿集合ETag写单项，也不让前端猜令牌拼法 |
| 补遗生效／取代关系的决定 | PRD7.5、SourceRef／source impacts与规则条件，U04要求有据核验 | 具体对象／来源／证据／当前修订的受理命令，可复用Action/决定机制但须明确领域动作；不能只有“待核实”文字无提交入口，更不能按最后上传猜 |
| 问题建议的直接操作 | 现有会话messages／actions和局部建议产品语义 | 从当前finding携固定项目／正文／来源发起建议并返回产物；不要求用户先创建通用任务、先用编辑器或输入技术命令 |

## 6. 提交／导出／错误验收

标准入口先`getSubmissionGate`，再`registerSubmission`提交`SubmissionRequest`：body_version_id、review_id、material_revision、submitted_at、evidence_ref；服务端重新校验，不把预检页面当授权。只剩评分未验收或非阻断建议不阻止；当前来源／核心缺口、未确认核心规则（除显式按原文接受）、未处理关键问题仍阻止。

线下已发生事实用`recordOfflineSubmission`＋`OfflineSubmissionRequest.actual_document_version_id/submitted_at/evidence_ref/explanation`，独立显示“未经过系统完整检查”；不能换干净稿伪造实际提交、不补造当时预测。提交后产生的回测不冒充事前预测。

`createReport`首批分别取`review_report+docx`及`annotated_review_copy+pdf`，`authorizeDownload`取真实文件，校验用途／版本／摘要。复用已验收直接取件能力，不回退新标签打开冒充下载；批注不可选为标准正文。完整正文生成仍属A2，不能为下载上传的实际正文而强迫先生成。

失败统一：401保留输入，重新登录后核对对象再继续；412保留表单及已核验字节，刷新当前对象差异；409说明阻断与原页／对象修复入口；422字段级错误不清空；503／429明确失败范围和可恢复条件，不把模型错误变0分或半分。关闭面板不取消后台任务，请求取消先显示正在取消，以真实终态为准。

## 7. 原13项的执行方式

[13项执行数据](a1-acceptance.json)保持原ID，所有项仍pending_application；由测试执行API／Worker与浏览器，用户角色观察理解，真人要求另留证。PPR-AC-05必须有真实完整章节三次判断研究产物，不能拿静态卡片替代；U02／U05随对应真实能力执行，PPR-AC-06在官方材料不足时也能验证交付说明诚实，但不授模型精度资格。原历史状态不覆盖。
