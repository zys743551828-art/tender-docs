# RAG初始化权限补充复核

真实BGE接线发现Worker无法执行pgvector函数，这是合法路径权限缺陷，不能用owner业务连接或改成假向量绕过。

根因与证据范围：实际 `initialize_database.py` 在同一连接依次执行5份SQL，core中的 `SET search_path` 保持到retrieval创建扩展，pgvector因此位于design；roles随后撤销design全部函数的PUBLIC执行权，Worker只拿到显式业务函数。此前本目录的独立并发夹具每份SQL使用新psql会话，扩展位于public，因此只能证明其明确报告的来源/并发机制，没有证明真实初始化后的pgvector合法调用权限。原证据保持不变，本补充明确这个差异。

已用新的同连接隔离初始化独立复现Worker插入42501。只对Worker授予以下三项精确EXECUTE后，真实PG中的1024维列插入、范数CHECK及cosine查询通过：

- `design.vector(design.vector,integer,boolean)`
- `design.vector_norm(design.vector)`
- `design.cosine_distance(design.vector,design.vector)`

768维向量仍以22000拒绝，零范数以23514拒绝；Worker读取outcomes或修改model_artifacts仍42501，score/research角色未新增向量函数能力。owner只用于全新夹具初始化、角色及这份明确授权，不执行业务向量写入。

已只读核查PM新增 `deploy/sql/vector-runtime-grants.sql`：实际语句与独立实证的三函数授权等价，未授EXECUTE ALL、表owner或其他角色能力；初始化入口在roles撤权后、创建LOGIN前执行。摘要绑定在 `extension-grant-source-review.json`。

脚本 `probe_extension_grants.py`，证据 `extension-minimal-grant-result.json`。测试向量明确为合成单位向量，只证明权限和PG约束；真实BGE写入、实际API检索与最终RAG候选仍需独立验收，本补充不宣布RAG最终通过。
