# AI 投标工作台 PRD

文档编号：PROD-002  
类型：产品需求、交互规则与业务验收

## 1. 文档用途与规格边界

本文定义公司内部市政工程 AI 投标工作台的目标产品，供产品、设计、开发、测试和投标团队共同使用。将上传即评审、风险优先、直接操作和评分闭环作为产品骨架，以GovDash公开界面和操作方式完善项目工作区、章节编制、来源联动、版本导出与随页AI助手。目标是降低废标／否决风险，帮助完成有依据的编制改稿，并让技术分预测在独立真实项目上接近正式技术成绩。

本文中的“应”“必须”是目标产品的验收要求，不代表功能已经实现。界面原型中的项目、成绩、知识和交互均为演示。真实模型质量、生产性能、评分精度和中标效果必须分别验证。

## 2. 目标、用户与范围

### 2.1 用户要完成的工作

投标人员需要回答：本次投标是否存在否决风险；哪些评分项有缺口；先修改什么；修改是否有效；最终交了哪一稿；正式成绩与当时预测差在哪里；过去的资料如何可靠复用。

| 使用者 | 主要工作 | 系统如何支持 |
| --- | --- | --- |
| 投标编制人员 | 上传资料、理解要求、编制章节、处理问题、生成评审稿 | 资料包、响应矩阵、章节编辑、就地AI辅助、证据与复检 |
| 市政工程师 | 核实工况、资源工期和措施可行性、复核关键问题 | 原文对照、事实确认、争议记录；不以 AI 文案替代工程判断 |
| 公司负责人 | 查看关键风险、提交与结果、判断评分改进价值 | 项目摘要、正式结果与预测对照、真实范围和证据 |
| 数据与系统维护人员 | 导入历史资料、核验成绩、维护知识和模型、恢复运行 | 异常队列、来源核验、受控发布、影响追踪 |

以上是工作分工，不是权限角色。沿用登录成员可以查看全部项目并执行操作的约定；审计记录实际操作人。一期不建设租户、套餐、项目成员权限或审批流配置。

### 2.2 成功标准

| 目标 | 判断证据 | 不能替代它的证据 |
| --- | --- | --- |
| 识别关键风险 | 对有专业参考标注的实际正文评价漏报、误报和证据准确性 | 代码测试通过、报告没有风险 |
| 预测接近正式技术分 | 固定独立项目测试、基线对照、误差与预测覆盖、分层结果 | 训练误差、合成数据、少数高分例子 |
| 改稿有依据 | 同规则和同方法下实际跑过两轮，能定位修改和判断变化 | 点击采纳、聊天说已改好 |
| 降低学习成本 | 投标人员完成关键任务的观察记录，明确卡住的步骤 | 聊天数量、页面访问量 |
| 业务价值 | 有分母的入围、中标、否决与正式成绩记录；说明样本和归因限制 | 高分就中标、预测涨分就代表正式涨分 |

业务效果指标沿用一期方案的唯一口径，不增设聊天数、上传量等经营看板。任务耗时、错误码、链路状态用于技术诊断；可用性试用观察用于产品验收，均不充当中标效果。

### 2.3 范围

| 交付层 | 范围 |
| --- | --- |
| 核心 | 当前项目页面与随页助手；章节编制、修改预览、模板及版本导出；文件版本；否决／强制核对；响应矩阵；逐项评分判断；评分预测边界；证据；修改复评；实际提交与正式结果 |
| 评分数据闭环 | 历史案例导入、配对核验、数据质量、独立评测、模型观察与受控发布、错误更正 |
| 可靠复用 | 历史项目档案与比较；企业知识候选、确认、版本、适用性、停用、引用追踪 |
| 辅助 | 前后矛盾、范围残留、报价试算、报告导出、提醒和项目设置 |
| 范围外 | 无人核验、自动完成并宣称可直接提交的整份编标、无依据填充企业业绩或设备、自动代提交交易平台、内部成本利润管理、对外 SaaS 经营、复杂岗位分权 |

允许依据已确认目录逐章起草并汇编人工维护的全文；逐章建议仍需核对，汇编不等于具备可提交资格。章节编制与局部修改由投标人员确认和维护；原上传件不变。实际生成或外部上传的新PDF是对应复评对象，不能把编辑器保存视为整稿已通过。

## 3. 产品结构与入口（FR-014）

### 3.1 全局侧栏与项目列表

采用GovDash式浅色固定侧栏、分组导航、顶部操作区、筛选与表格。业务对象放在中央，AI助手可在每页打开。具体布局见交互主规格。

| 分组 | 入口 | 默认内容与动作 |
| --- | --- | --- |
| 投标工作 | 投标项目 | 在办项目表格；按阶段、截止、风险和资料状态筛选；新建／上传；打开项目工作区 |
| 投标工作 | 历史项目 | 默认归档视图；可筛全部项目；搜索、比较、选参考、批量导入、补成绩 |
| 投标工作 | 企业知识 | 可直接搜索、核对来源与适用性、选用和维护；与资料库中的知识入口指向同一条目及版本 |
| 工作平台 | AI助手 | 全屏对话与历史会话；显式显示当前项目或全局检索范围；可跳回关联对象 |
| 工作平台 | 任务 | 任务模板与运行记录；启动、暂停、查看结果、处理失败 |
| 工作平台 | 资料库 | 文档、企业知识、公司事实、模板；保持独立对象及用途 |
| 工作平台 | 业务复盘 | 入围、中标、否决闭环及有资格的预测误差；沿用唯一业务指标口径 |

历史项目是同一项目记录的查询视图，不复制另一套档案。企业知识在主导航独立进入，也可从资料库进入，两处读取同一记录。项目列表顶部展示即将截止、待处理否决风险、等待复核、资料有更新等当前工作状态摘要；不引入收入、销售管道额、平均回复时间或聊天量看板。无数据不展示演示指标。

### 3.2 项目工作区

进入项目后保留全局导航与项目菜单，中央落点统一按第3.5节确定。概览突出身份、截止、资料变化、关键风险和下一动作；完整报告从“评审与评分”打开。

| 项目页面 | 中央工作面 | 就地操作 |
| --- | --- | --- |
| 概览 | 项目事实、进度、风险和待办 | 进入当前对象，恢复未完成工作 |
| 招标资料 | 招标、补遗、图纸及清单的资料包 | 上传、分类、原文、补遗影响 |
| 响应矩阵 | 要求原文→响应章节→判定→处理状态 | 定位原页、关联章节、核验或转为编写任务 |
| 章节编制 | 树形目录、编写计划、章节正文、引用 | 新增／移动章节、局部修改、AI草稿、预览差异 |
| 评审与评分 | 当前否决风险、覆盖、评分项和报告 | 问题复核、完整章节评分、修改后复检 |
| 版本与导出 | 草稿快照、已生成Word/PDF、评审与提交关系 | 生成版本、版面预览、对比、下载、发起评审 |
| 提交与结果 | 提交检查、实交稿、正式结果及核验 | 标准登记、有据补录、成绩回流 |

参考资料与公司事实、报价和项目设置放在项目菜单辅助区；关闭报价时入口和动作同步隐藏。章节详情同时显示正文、编写计划、对应要求和来源，可在同一详情切到上一章／下一章。AI助手停靠右侧，支持收起和全屏；查看原文时同一右侧区域切到来源，不叠加多层窄栏。

项目名称、标段／轮次、当前草稿、评审稿及资料是否更新始终可识别。草稿正在编辑不等于已生成新评审稿；查看旧轮次固定提示“历史评审”。手机以全屏页面承接编辑器、原文与助手，返回保留滚动、未发送内容和当前对象。

### 3.3 操作入口与上下文

上传、新版复评、看问题、看原文、版本比较、提交登记、成绩登记和知识维护均有直接按钮。AI可在全屏助手、页面侧栏或选中文本后发起相同业务动作，不要求记住命令。

助手顶部显示当前项目／章节及来源范围；“+”选择文件或来源，“@”引用有身份的项目、文件、章节和知识。来源面板列出本项目资料、选定参考、企业知识及选择理由，可以移除普通参考。打开页面不等于授权助手读取全库，切换来源产生新的任务输入。正式评分从白名单构建输入，不接受通过来源选择器加入成绩或事后信息。

全局会话可以检索，项目写入必须先确定目标项目。助手建议跳转时给出目标页和打开按钮，不自行带离尚未保存的工作。跨项目切换显示新上下文，原草稿和任务保留原归属。

### 3.4 首次使用、空结果与受限状态

| 场景 | 页面行为 |
| --- | --- |
| 没有项目 | 主动作是上传资料；可先创建简短项目，不要求完整表单 |
| 项目未评审 | 显示已收资料、缺口或真实处理任务，不展示演示报告 |
| 历史库或知识库为空 | 可以导入或上传；当前项目仍可开始 |
| 搜索没有匹配 | 显示没有找到及可放宽的条件，不用不适用材料充数 |
| 章节没有可用依据 | 可保存人工草稿，AI标记待补事实，不编造参数或标已响应 |
| 尚未生成可评审版本 | 保留编辑内容，给生成评审稿动作，不沿用旧报告冒充当前草稿已通过 |
| 原件不可用或服务失败 | 与没有结果区分，保留输入和已完成工作，提供恢复动作 |
| 请求不明确 | 对影响对象、版本或范围的歧义集中询问；能安全完成的读取与草稿可先进行 |

新用户不需要配置模型参数、索引或知识分类。未配置真实模型时说明评审不可运行，不能用原型结果填充真实项目。

### 3.5 两条路径与默认落点

有现成招标和正文时，拖入后按自动开始设置直接评审，完成进入关键风险及结果；无需先选目录模板、编写计划或创建任务模板。只有招标时保留补正文入口，也可从要求生成候选目录开始编制，不自动生成未经核对的完整标书。

入口落点按下表确定。最近工作位置只保存页面、对象和滚动，不改写当前评审稿或正式提交身份。

| 入口／情况 | 默认落点与要求 |
| --- | --- |
| 明确的原文、问题、历史报告或通知链接 | 打开所指对象及版本；历史身份、失效影响始终可见，不替换为最新对象 |
| 列表进入在办项目 | 有可恢复的有效工作位置先恢复；没有时，有当前评审结果进入结果，已有编写内容进入对应章节，其余进入概览 |
| 首次上传完成并受理自动评审 | 显示该轮真实进度；用户仍在当前流程时可进入结果，已转去编辑则只给通知 |
| 已结束或归档项目 | 打开只读档案或上次只读位置，补录／更正从明确入口进入 |
| 最近位置所指对象已删除、停用或不可继续编辑 | 解释原因并回到项目概览或仍有效的对应列表；不恢复过期可执行按钮 |
| 后台任务完成、补遗到达 | 提醒相关对象及变化，保留当前编辑；用户选择后再跳转 |

项目菜单始终可直接进入任一工作面。

章节编制的默认生成按钮随自动开始设置命名：开启时为“生成并评审”，一次受理固定草稿快照，生成可用PDF后接续评审；关闭时为“生成版本”，只生成文件，完成后提供“开始评审”。不能显示承诺评审的按钮却只生成。用户通过按钮或对话明确要求生成后开始评审时属于人工请求，可按明确范围执行，无需重新开启自动开始；关闭自动开始只约束无人发起的自动衔接。用户仍可单独生成、下载或上传外部Word修改稿，已有审查与提交条件不放宽。来源面板和助手按需打开，不能让多栏布局挤压正文或阻挡快速检查。

### 3.6 简洁默认与逐步展开

默认结果页先给一条关键结论，区分否决／强制风险、无法判断或检查失败，再显示评分适用性与覆盖。主要动作只指向当前最重要的一件事，其余待办可展开；完整问题、响应矩阵、原文与完整报告始终可进入。没有发现风险不等于零风险，执行结束不等于检查通过。

只做评审的用户无需进入章节编制、模板或任务页；不填公司事实、不先建满知识库也可开始，相关缺口按实际需要提示。结果页保留直接可见的简短AI输入区，可问“先改哪项”“检查新版”；发送后复用项目主会话并按需展开助手，不另造重复任务。直接按钮与对话可以完成相同操作，一次明确的按钮提交不重复聊天确认。沿用项目功能开关；关闭可选模块时导航、助手建议和普通模块催办一致隐藏；已有关键风险继续按第7.4节在统一风险清单、提交检查和报告可见，不放宽核心检测或提交条件。

从快速评审进入章节工作区时沿用项目、问题、引用和版本，修改后的新稿重新评审；返回结果保留先前位置和处理进度。导入外部Word修改稿也沿用同一链路，不要求迁入在线编辑器。风险闭环、评分验证和现成PDF使用不等待完整编辑、模板或任务平台交付。

### 3.7 主要下一步的选择规则

页面、结果卡、助手建议和完整报告使用同一当前对象与待办分类。主动作按以下顺序选择；全部问题仍可查看，不能因仅展示一项而漏报已确认关键风险。

| 顺序 | 条件 | 主要动作 |
| --- | --- | --- |
| 1 | 项目／目标正文／生效资料有影响当前判断的歧义或冲突 | 定位一次集中核对；保留已收到文件，不能请求重传整批 |
| 2 | 当前输入必需解析或核心核对失败、存在未完成关键覆盖 | 补对应资料、查看失败范围或重试受影响任务；当前结论标不完整 |
| 3 | 当前有效轮次存在未处理关键风险或否决／强制问题 | 进入严重性最高的问题及两侧原文；同类按原条款顺序稳定显示 |
| 4 | 用户已进入提交检查，存在依法需核验的工程事实或待确认关键规则 | 集中核对剩余阻断项；按原文接受的显式开关只影响原有规则确认条件 |
| 5 | 用户请求改稿或完善技术评分项，且没有更高优先事项 | 进入对应章节、评分缺口或参考；模型未验收不变成投标人员必须完成的配置任务 |
| 6 | 提交条件满足，或只剩非阻断建议 | 可登记提交；建议按需查看，不要求全部完成 |

未开始评审时主动作是补资料或开始评审；正在处理时显示进度与可离开状态，不重复启动。存在多项同级问题时保留稳定顺序，用户可手动选择其他问题。评分不能可靠估分不单独阻止提交；只有对核心规则造成实际判断缺口时，按缺口处理。普通浏览不提前强迫逐条确认所有规则。

## 4. 业务对象、归属与唯一性

### 4.1 核心对象

| 对象 | 必须表达的信息 | 归属与约束 |
| --- | --- | --- |
| 项目 | 工程身份、标段、投标轮次、主体、地区、工程类型、截止时间及依据、业务阶段、归档状态 | 一个项目工作单元对应一个标段下一个主体的一次投标轮次；工程名称不是唯一键 |
| 会话 | 项目或全局范围、主题、消息、操作卡、状态、上下文指针 | 项目会话只属于一个项目；全局会话的每个业务操作固定目标；不得搬移正式操作记录 |
| 文件与文件版本 | 原名、角色、内容摘要、取得时间、文内时间、来源、解析状态 | 原件不可覆盖；同一内容可被多个对象关联，关联身份分别保留 |
| 章节与草稿 | 稳定章节身份、目录位置、编写计划、内容修订、引用、保存状态 | 与原件、评审稿分开；并发不覆盖他人编辑；AI建议先预览再应用 |
| 导出版本与模板 | 草稿快照、目录与版式模板版本、Word/PDF产物、页数和生成状态 | 原件和已生成版本不可覆盖；正式评审绑定具体生成文件 |
| 任务模板 | 任务说明、来源用途、触发方式、产物类型、启停及版本 | 每次运行固定模板和输入身份；不能授权自动作人工正式决定 |
| 评审轮次 | 正文版本、生效招标／补遗、规则包、事实集、引用清单、模型与提示等方法版本、运行结果 | 输入冻结；事后更正不改写旧轮次 |
| 问题与决定 | 规则、原文、判定、严重性、状态、人工决定与理由 | 绑定对应轮次；不得把 V1 的解决状态直接套给 V2 |
| 实际提交 | 项目、实际提交正文、提交时间、回执、对应评审或缺失说明、更正链 | 事实登记与系统检查结论分别表达，见第 10 节 |
| 正式结果 | 提交对象、阶段结果、成绩目标、分值、满分、聚合口径、来源、发布时间、取得时间、核验、更正链 | 技术分、综合分和未知分分别保存 |
| 历史案例 | 项目档案的查询呈现及材料完整性 | 不另造一份独立的项目事实；外部案例保留原企业身份 |
| 知识条目与版本 | 内容、分类、来源位置、适用性、主体、有效期、状态、确认人 | 公司级条目；项目引用指定版本；候选不自动成为项目事实 |
| 引用 | 来源对象及版本、使用目的、目标项目／轮次、摘录与适用说明、产生时间 | 普通参考、规则依据、项目事实证据、评分锚点用途分开 |
| 评分样本 | 实际提交、核验后的技术标签、资料版本、去重分组、准入结论 | 项目归档不自动产生合格样本；样本合格不自动进入某次训练 |
| 模型及实验 | 数据划分、方法版本、适用范围、独立评测、发布状态与审批决定 | 业务模型切换不追溯覆盖旧预测 |

“工作会话”指项目或全局助手中的对话，“登录会话”指认证身份，二者没有相同生命周期。关闭工作会话不退出登录，登录过期也不删除工作会话。

### 4.2 相似但不能混同的概念

1. 项目业务阶段、归档状态、资料完整性、评审任务状态、提交检查结论分别保存。
2. 正在编辑的草稿、生成的Word/PDF、当前浏览稿、评审稿、实交稿分别显示。
3. 聊天记录是过程记录，项目事实和正式决定来自带来源的业务记录。
4. 参考案例分数不能转移给当前项目；引用了某措施不证明当前正文已经响应。
5. 项目可查阅、知识可参考、事实可确认、样本可训练分别判断。
6. 统计有足够配对数、某模型通过独立验收、当前项目适用该模型是三个判断。

### 4.3 标段、轮次与主体（FR-034）

同工程不同标段分别建立项目工作单元。重新招标建立关联的新轮次，允许显式引用旧资料，但规则、提交和成绩独立。相同项目不同投标主体的历史案例分别保存；公司主体与外部主体不能因名称近似合并。

项目身份不明确时先保存待归组材料，不自动合并。合并或纠错需展示将影响的文件、提交、成绩和引用，保留原身份映射。实际案例编号不复用。

### 4.4 草稿、文件与当前结果的关系

| 层次 | 何时成立 | 可以做什么 | 不能据此认定 |
| --- | --- | --- | --- |
| 本地待保存内容 | 用户在编辑器修改但服务端未确认 | 继续编辑、重试保存、恢复待提交内容 | 服务端已保存或新稿已生成 |
| 服务端工作草稿 | 保存成功并返回修订 | 基于明确修订生成版本，继续编辑新修订 | 当前PDF已变化或旧问题已解决 |
| 生成／上传的具体文件 | 字节接收或生成校验成功 | 下载、预览，并按用途选择本轮目标 | 仅同名就与Word对应或已通过评审 |
| 当前评审及结果 | 固定正文、招标补遗、规则、事实和方法 | 查看对应结论；质量满足时进入提交检查 | 最后完成就等于当前，或历史结论适用新输入 |
| 实际提交文件 | 用户有据登记具体文件及时间 | 绑定正式结果和合格事前预测 | 等于最新草稿或截止后新稿 |

“当前”必须说明所指层次：最新草稿、最新生成、当前评审、实际提交分别标记。新生效资料或本轮目标正文变化会使旧评审失去当前资格；未生成的草稿编辑不改写既有PDF结论，结果页显示草稿有修改、该结论只适用于原PDF。

如决定实际提交仍未改变的已评审PDF，登记卡须清楚显示该文件，并说明未包含草稿修改；只按原有核心闸门校验，不能悄悄替换成未评审的新草稿。已有新目标正文或生效补遗时，旧PDF结论不能继续取得当前资格。切工作面、关闭助手或导出报告都不改变这些指针。

## 5. 项目、会话和知识生命周期

### 5.1 项目业务阶段与归档维度（FR-015、FR-031）

| 业务阶段 | 进入条件 | 可执行动作 | 离开条件 |
| --- | --- | --- | --- |
| 准备中 | 创建项目或首次上传 | 补资料、核身份、查看单份文件；资料不足也能问答 | 所需资料和身份足以开展本次评审后进入编制评审 |
| 编制评审 | 具备所需招标及正文，或人工明确开始处理 | 多轮评审、复核、修改、比较、报价 | 登记实际提交；或明确取消／流标 |
| 已提交 | 已登记至少一条有效提交事实 | 查询冻结稿、补回执、登记结果、复盘；可补传文件但不改提交稿 | 人工结束本轮工作，可保留待补成绩；或按更正／新轮次处理 |
| 已结束 | 人工结束本轮工作 | 查阅、补结果、更正、提炼经验 | 需要继续编制时显式重新打开并记录原因；新一次投标建立新轮次 |
| 已终止 | 人工记录取消、流标等原因 | 查阅、补证据、复盘 | 招标恢复且仍属同一轮时显式重开，否则建新轮次 |

归档是独立维度：在办项目默认不归档；已结束／已终止可归档；缺成绩不阻止归档。历史资料导入可直接建立对应已结束／已终止的归档记录。归档不隐藏待补成绩。

归档后的冻结文件和历史评审只读；允许从明确的补录／更正入口追加成绩、回执、来源和复盘，不对原记录就地修改。重新打开恢复工作能力，但旧提交与旧报告仍冻结。

“评审中”“失败”“待补资料”“问题待处理”作为工作状态展示，不再承担项目业务阶段。归档、关闭会话与取消任务是三个不同动作。归档时存在运行任务，须选择等待完成或请求取消并等待终态；不能留下无处展示的后台写入。

### 5.2 会话（FR-016）

| 状态 | 含义与操作 |
| --- | --- |
| 进行中 | 可以发起任务与业务操作；一个项目默认有一条主会话 |
| 已结束 | 暂停讨论，不取消已启动任务；可回看并继续，继续后回到进行中 |
| 已归档 | 从日常会话列表收起；仍可查询与恢复；恢复到已结束后可继续 |

关闭浏览器不改变会话业务状态。项目内的主会话提供“继续上次工作”；不要求用户每次新建。专题会话为后续增强，若提供，必须同样绑定项目并共享正式项目记录。

删除消息或隐藏会话只能改变展示，不能删除已生效操作、引用、文件、正式结果与审计。界面明确说明范围。项目已归档时可进行只读问答，产生写入时指向补录入口或重新打开项目。

### 5.3 知识条目（FR-024、FR-025、FR-027）

| 状态 | 进入与离开 | 新任务使用规则 |
| --- | --- | --- |
| 候选 | 上传或从项目提炼，编辑后送确认 | 可查阅并标候选；不进入正式建议的自动参考集合 |
| 待确认 | 已有内容与来源，待核实主体、条件、有效性 | 可补材料；不伪装为已确认事实 |
| 已发布 | 人工确认当前版本且来源、适用性齐备 | 仍需通过本任务适用性与有效期检查，才能引用 |
| 已停用 | 来源撤回、内容错误或主动停用 | 禁止新增引用，启动影响检查 |
| 已失效 | 超出有效期或被适用规则明确替代 | 禁止新增引用，仍保留历史来源 |

“已发布”是版本级状态。发布新版本后，旧版标记被替代，不再进入默认新引用；可查看历史。草稿更新期间当前有效已发布版继续可用；旧版已发现错误时立即停用，不等待新版发布。

停用／失效后不直接恢复原版本到已发布，应创建经复核的新版本。项目旧报告保留原引用并附后续失效提示；在办项目列入影响复核，已提交项目不得因此被静默重写。

知识库集合长期存在，不随单个项目归档清空。删除来源的展示关联不应破坏已发布知识出处；确需物理清理时按第 17 节处理。

### 5.4 评审任务

任务经历排队、运行、成功、失败或已取消。失败可重试，重试建立可追踪的尝试记录。请求取消不等于已经取消；执行器确认终态前显示“正在取消”。

新资料到达时，旧任务可以完成并成为历史轮次；最新结果指针按输入版本判定，不能由完成时间决定。系统合并同一批上传的重复触发；是否重用已有结果由冻结输入和方法配置共同决定。

### 5.5 状态转换约束

下表限定同一对象的转换。创建历史归档对象是明确的导入行为，不通过伪造中间评审或提交来补齐状态。

| 对象 | 允许的主要转换 | 必须满足的事件条件 |
| --- | --- | --- |
| 项目阶段 | 准备中→编制评审／已终止；编制评审→已提交／已终止；已提交→已结束／已终止；已结束／已终止→编制评审 | 分别对应资料可工作、真实提交或终止、人工结束、有依据的同轮重开；重新招标创建新轮次 |
| 归档维度 | 未归档→已归档；已归档→未归档 | 结束／终止后归档且运行任务已达终态；重新打开需明确决定 |
| 工作会话 | 进行中→已结束／已归档；已结束→进行中／已归档；已归档→已结束 | 明确结束、收起或恢复；恢复后可继续 |
| 同一知识版本 | 候选→待确认；待确认→候选／已发布；已发布→已停用／已失效 | 编辑、送确认、人工确认或有据停用／到期；停用失效版本不能直接重新发布 |
| 同一次任务尝试 | 排队→运行／已取消；运行→成功／失败／已取消 | 执行器记录；失败或取消后的重试是新尝试，不改原终态 |

“已发布”与“已被新版本替代”分别表达，新发布会更新条目的当前版本指针，不把旧版本内容原地修改。归档维度和项目阶段须一并检查，不能把仍归档的项目恢复为可写编制状态。

## 6. 端到端操作路径

### 6.1 首次投标

1. 用户拖入招标、补遗和施组；系统先保存上传，自动提议项目名与文件用途。
2. 对明确身份直接建档；标段、轮次、主体或版本有影响结论的歧义时用一张卡集中询问。
3. 自动解析；资料足以评审且自动开始开启时，接续评审。缺资料时保留已上传内容并说明缺口。
4. 完成后优先展示必须处理的风险，再展示评分覆盖和建议先做的一件事；原文按需打开。
5. 用户在章节编制中编辑或请求AI修改，预览差异后应用到工作草稿；原上传件不变，问题仍待复检。
6. 生成并检查Word/PDF版本，或上传外部修改稿；基于该具体文件建立新评审，展示实际跑过的变化。
7. 登记实际提交稿，保存提交检查结论；交易平台操作由人完成。
8. 上传正式结果并核验，查看可比预测差异；归档与知识提炼按需进行。

### 6.2 历史与知识复用

用户在项目里问“参考类似道路项目的交通导改”，系统检索适用内容并提供匹配原因与差异。用户可打开完整档案，也可直接要求草拟建议。引用清单留在当前项目。查看案例成绩与进行正式评分使用不同用途通道，见第 13 节。

用户直接进入历史项目或企业知识时，支持搜索、筛选和详情；选用时明确目标项目。查看和搜索不要求先进入某条会话。

### 6.3 大批历史资料

拖入压缩包／资料批次或提交现有登记表 → 系统预览分组与缺口 → 用户只处理不确定项 → 确认入库 → 分别查看可查询档案、核验成绩配对、样本准入及待补列表。导入不触发整批模型预测或训练。

## 7. 文件、规则、评审与结果（FR-001—FR-005、FR-008、FR-012、FR-013）

### 7.1 文件接收与版本

PDF为正式评审的页级证据格式；首批Word导入与导出明确为DOCX，旧DOC可保存原件并提示转换，不声明已经可靠解析。DOCX可作为章节编制的导入与导出格式，须先检查结构、表格、图和模板转换质量。不能可靠导入时保存原件并说明缺口，可继续上传PDF评审。其他格式可保存原件，但必须标记是否具备可靠解析能力；扫描件、加密件、损坏文件、缺字体或图页无法识别时显示具体缺口。研究侧 OCR 能力未经产品验证不能宣称已接入。

上传前展示当前部署的文件类型、大小和批次限制；超过限制在上传前或校验时明确拒绝，不丢失同批已成功文件。身份明确的文件自动归类，疑似正式成绩不得进入事前评审资料。压缩包预览要识别无效路径、重复包和异常展开规模。

同一内容重复上传不生成独立文件内容或独立样本；保留来源与关联记录。新内容即使同名也建立新版本。用户可以明确某文件是参考资料而非当前正文；多个正文候选需选择本轮目标，不按文件名“最终”猜测。

上传支持仅补传缺失分片及短期授权刷新；刷新页面后的恢复须重新核对所选文件和服务端上传状态。用户明确选择“新文件”或“作为此文件新版本”，并发新版本冲突保留核验结果供重新选择，不能由迟到回调抢占当前稿。

### 7.2 自动评审与规则

自动评审条件：项目身份足够明确；生效招标与所选正文可解析；已知补遗及版本冲突已处理；自动开始开启。没有补遗文件不等于已证明没有补遗，界面提示核对补遗完整性；只有正文时可做有限内容问答，不输出完整合规结论或技术总分。

同次多文件上传以批次和项目资料修订归并：文件可逐个解析，待该批明确完成或用户结束本批、必要资料角色与版本明确后，对满足条件的输入只发起一轮自动评审。非必要文件失败不撤销已成功内容，是否影响本轮范围要说明；用户无需重新上传成功文件。“非必要”须依据本轮任务和生效要求确定，不能仅按文件名或用户暂不处理就忽略可能必需的图纸、附表。可先形成已有范围的部分结果；受理成功与完整结论资格分别判断，关键范围不明时不得宣称全稿通过。

评审进行中资料更新，已冻结运行继续保留原身份；同项目合并一个“最新资料待评审”请求，尚未受理的中间修订可被更新修订取代，已受理运行不被改写。输入身份除文件字节外，还包括项目、目标正文、招标补遗及角色归属、规则与事实、解析配置和方法；同文件重新归类可能改变评审语义，须形成新资料修订。自动触发、按钮和对话对同一输入与方法的等价请求共用在途运行；用户明确要求同输入复跑才另建尝试并显示范围。生成并评审与文件完成事件不能各自重复调用模型。关闭自动开始时只更新资料与过期提示。

废标／否决、强制、评分、建议、例外分别处理。规则记录原文、页码、条件、例外和依据版本；评分项记录分值及计分方式。规则冲突或各评分项满分与技术满分不一致时，先提示核验，不通过缩放消除矛盾。

废标／否决／强制类规则默认在标准提交登记前人工确认；“按原文接受”的例外沿用既有开关，报告仍显示依据未确认。规则驳回或事实更正创建新包／集，并提示现有评审过期，人工决定复评。

允许批量确认明确选中的待处理条款，不覆盖已驳回或暂缓的决定。重新提取时，仅在条文、性质、条件、例外、适用范围和生效来源关系均可证明等价时沿用人工决定，并显示原决定来源；变更条款重新确认。事实可补充、替换或撤回，追加新集保留旧依据；全部撤回也保留历史，相关旧报告标过期。

### 7.3 判定、证据和覆盖

响应矩阵保留满足、违反、无法判断、检查失败四类。满足必须有当前项目证据。缺失型问题可引用要求原文和已检查范围，明确没有找到所需内容，不能编造一段正文证明缺失。

证据校验至少确认文件身份、版本、页码、摘录真实存在。引用不合法的输出不得成为有效结论；说明受影响规则是否仍有有效判定，无法判定则记检查失败。没有报出问题不能自动标为通过。

覆盖详情按四层展示，人工确认另列，不合并为一个“完成百分比”：

| 层次 | 显示内容与分母 | 不能据此宣称 |
| --- | --- | --- |
| 来源范围（source_scope） | 本轮生效来源、已读／未读／失败的页或结构范围，必要图表及未知范围；来源清单可以展开 | 全文已读就代表条款已全部提取或内容已满足 |
| 核心规则提取（core_extraction） | 已识别核心条款数、已处理的提取来源范围、已知提取缺口与待核验段落；来源冲突、疑似漏提及人工补充均可定位 | 已识别N项就是原文只有N项，或提取任务结束就是零遗漏 |
| 规则核对（judgment） | 对当前已识别且生效核心条款，分别列未开始、运行、成功、失败和取消；业务判定另列满足、违反、无法判断 | “已识别核心规则核对10/10”代表原文全部规则无遗漏，或10条执行完成就全部满足 |
| 评分覆盖（scoring） | 按第9.2节显示有效评分项对应满分／技术满分，以及关键评分项缺口 | 核心核对通过就能可靠预测总分，或纯评分失败就必然不能登记提交 |

人工确认显示当前核心规则的待处理／已确认／已驳回／暂缓及沿用来源；不是全文处理、条款提取或规则满足的替代证据。任务成功只表示执行结束。未运行的可选检测标“未运行”，不计为满足。

全文读取、候选条款清单、规则判定和真实检测质量分别判断。覆盖中的分子／分母来自本轮实际计划与结果，不借未知的原文规则总数计算“提取100%”。已知来源缺口、疑似漏提或新增核心规则进入复核和新包复评，旧评审失去当前资格。首轮试点用有专业标注的代表性招标与正文报告漏提、错提、漏检及误报；未经真实标注评测显示“检测质量待验证”，不以运行覆盖替代质量结论。来源核对按实际缺口集中处理，不新增全员逐页签字的默认前置步骤。

人工发现漏提条款时，可从来源核对或当前规则页使用“补充并确认条款”，一次明确展示原文、页码、性质、条件与例外、适用范围及影响后提交；合法生效来源、逐字依据和必要字段均通过校验才原子追加新规则包及新增条款的人工确认决定，沿用可证明等价的原决定，原条款不被改写。缺依据、尚未校验或条件有歧义时不得确认或部分写入，保留输入供修正；确认仅确认条款解释，不代表正文满足，旧评审标过期并提供按新包重新评审入口，不重复要求第二次确认或新增岗位审批。

人工补入的核心要求保留可追溯的人工来源身份，不以后续模型提取清单决定其存续；重新提取或补遗重建时，来源仍生效且条件／范围未变的要求继续纳入新包并沿用确认，与等价提取项合并而不重复计数。来源变更且不能证明等价、或效力／适用关系不明时，保留待核验项与影响提示，不静默消失或冒充仍有效；有据的生效替代、适用判定或人工更正可以结束当前义务并保留历史，不新增默认步骤或岗位审批。

每条矩阵行分别表达执行状态和业务判定，区分未开始、运行、执行失败及成功后无法判断。AI引文或工程断言被拒时保留字段级原因与影响范围，不静默删除后报完整成功；工程量核验包括主体、单位、范围及中文数字，来源出现同一数字不代表该断言成立。

### 7.4 功能开关

保留七个项目级开关与既有默认值：自动开始、前后矛盾、范围残留、显示预测分数、报价、结果提醒默认开启；规则按原文接受默认关闭。放在次级设置，不占主流程。核心否决检测、响应矩阵、证据与提交闸门无关闭入口。

关闭前后矛盾或范围残留检测，只停止此后新轮次的该项执行及普通模块催办；已经记录、尚未通过有效复核解决且尚未被有理由人工驳回的关键风险继续在统一风险清单、提交检查、完整报告及新导出的报告问题清单中可见并可处理，显示“先前检测发现，本轮未运行该检测”。待复核的关键风险也不能因关闭而隐藏。关闭开关、重新评审时未运行该检测或没有新发现，均不能将其自动改为已解决；新稿有效复核或有理由人工驳回后按真实状态处理。与否决／强制规则相关的问题继续接受核心核对。既有非阻断建议可在历史问题中折叠查看，不催办、不新增提交阻断；原始历史报告字节不变。

开关改变不重写旧报告。关闭“显示预测分数”时，页面、对话回复、复制文本、图表提示和新导出隐藏预测数值、预测区间及派生分差；保留风险、评分覆盖、逐项缺口和不可可靠估分原因。该开关不隐藏正式成绩登记的技术分、综合分与满分，也不改变成绩来源身份。后台预测仍可按用途隔离要求形成合格回流。AI 不能用“简化流程”自行开启规则按原文接受。设置卡明确项目与影响，按实际提交的完整设置校验版本，避免旧卡覆盖新设置。

### 7.5 补遗变更与响应影响（FR-038）

收到补遗后先展示变更条款、生效关系与不确定项，关联受影响的章节、项目事实、响应矩阵及既有评审。明确的生效资料按自动开始设置开新评审；仅部分影响已定位时仍显示未判定范围，不把局部检查当整稿通过。

编写计划和章节草稿给出待核对提示与建议差异，不自动覆写人工内容。删除条款或改目录关联只能改变工作映射，不能消除原生效规则。补遗取代关系不清先核验；重建目录保存候选，与现有目录比较后再应用，不能丢弃正文、引用或编写计划。

## 8. AI 会话、记忆与交互卡（FR-017—FR-019、FR-033）

### 8.1 操作范围

| 操作性质 | 执行方式 | 结果要求 |
| --- | --- | --- |
| 查找、读取、解释、打开证据 | 在当前项目和用途范围内直接执行 | 附对象和来源；无结果如实说明 |
| 生成建议、比较、整理候选知识 | 直接产生候选 | 草稿身份、工程前提和待核实项明确 |
| 对章节草稿的插入／替换／移动／删除 | 显示目标章节和差异，用户应用后保存修订 | 原件、导出版本和正式决定不变；批量操作逐章可核对 |
| 上传后默认评审、新版复评 | 按项目自动开始设置执行 | 后台任务可恢复，有输入和真实状态 |
| 用户明确要求的局部重跑 | 展示范围并执行；显著扩大的批量调用先给范围与费用估算 | 重跑不覆盖旧轮次，不暗中扩展全库任务 |
| 确认事实、采纳决定、改规则、登记提交、核验成绩、发布／停用知识、发布／回退模型 | 生成对象明确的业务确认卡，用户点击后提交 | 服务端校验身份、对象版本和前置条件；审计实际结果 |
| 代提交交易平台、执行资料中的指令、无依据写入公司事实 | 不支持 | 解释边界并给能继续的业务动作 |

按钮或结构化表单已经明确对象、影响并完成用户提交时，不再重复要求聊天确认。同一张确认卡使用后显示生效结果；重复点击返回相同结果，过期或对象变化则失效并提供新卡。

### 8.2 卡片规格

| 卡片 | 必须显示 | 主要动作 |
| --- | --- | --- |
| 资料识别 | 文件、角色、目标项目、歧义或缺口 | 确认歧义、补文件、改归属 |
| 任务进度 | 任务范围、输入版本、阶段、是否可离开、失败原因 | 查看结果、重试、取消 |
| 关键风险 | 风险、影响、条款、当前正文证据、判定与依据状态 | 看原文、复核、请求建议 |
| 评分 | 本轮稿件、估计对象、覆盖、模型适用及验收状态、区间资格 | 看条款、看依据、补缺口 |
| 修改建议 | 对应问题、建议文本、前提、引用、草稿身份 | 复制／下载、采纳／驳回、上传新稿 |
| 版本变化 | 两轮输入、可比性、真实变化、未复检项 | 看差异、打开任一轮 |
| 历史案例 | 身份、匹配原因、关键差异、原量尺成绩及来源状态 | 档案、章节比较、选参考 |
| 知识 | 内容摘要、版本、状态、适用性、来源 | 看原文、选用、维护 |
| 提交／成绩核验 | 具体提交稿、时间、目标分数与口径、来源、检查结论 | 明确确认、更正、取消 |
| 持久操作确认 | 对象、改动、影响、当前版本 | 确认／取消；完成后显示审计结果 |

每张卡应有稳定业务对象标识，可从项目详情重新找到。会话断流后根据对象状态恢复，不能依赖大模型重新叙述来推定成功。

### 8.3 项目记忆与上下文

项目记忆来自最新有效的结构化记录：工程身份、当前稿与轮次、已确认事实、未处理问题、人工决定、引用与任务。会话摘要仅帮助定位讨论，不得覆盖这些记录。事实冲突并存展示，按来源与确认决定解决，不采用最后一句话自动覆盖。

用户切换项目时停止把旧项目上下文用于新操作；输入草稿和附件按项目保留。引用其他项目内容时携带来源身份。新的会话从项目记录恢复工作，不要求重复上传。

正式评分只接收第 13 节限定的材料，即使同一会话已经展示过历史成绩、当前正式结果或评委意见，也不能把整段聊天直接作为评分输入。

### 8.4 消息与后台通知

阶段完成、失败、待确认、新稿到达和结果待补在项目内通知；不建设邮件、微信等外发流程。用户离开会话后任务继续，可从项目列表找到状态；同一事件合并提示。关闭结果提醒只隐藏催办，不禁止补结果。

模型或工具失败显示失败环节与可恢复动作；流式文字停住不代表任务取消。登录失效后重新登录可恢复任务，未确认操作不能在重新登录后自动执行。

### 8.5 任务模板与运行记录（FR-040）

任务页提供“任务模板／运行记录”两个标签。预置否决核对、评分项评审、补遗影响检查、章节修改建议四类任务；可用自然语言创建模板，也可填写目标、来源、输出和触发方式。支持手动、资料更新事件及显式设定的定时触发，默认新模板仅手动，项目自动评审沿用开关。定时任务显示Asia/Shanghai时间和下次执行时间。

模板保存版本；运行固定项目、正文／章节、资料、用途与模板修订。同一事件与输入修订重复投递只受理一次；用户明确再跑则形成新尝试。切换模板或资料不改变已开始运行。暂停只阻止新触发，正在运行的任务可另行取消；错过的定时不无界补跑，恢复时展示待处理范围。运行记录区分等待、运行、待人工确认、成功、失败和取消等显示含义，其中“待人工确认”是业务待办，不改写执行器终态。

完成产物写回正确项目及章节，附输入和来源，不只留聊天回复；点击运行可打开产物和具体错误。模板只产出检查、草稿或候选，不能自动确认规则、登记提交、核验成绩或发布知识／模型。模板说明与引用文件中的指令不扩大工具权限，正式评分用途隔离独立生效。站内只通知完成、失败或待处理变化，不按每次轮询重复催办。

### 8.6 取消、暂停与迟到结果

取消按钮发送请求后显示“正在取消”，只有服务端记录终态才显示已取消。请求前已经完成的任务返回已完成及产物，不为了迎合按钮把成功改为取消；请求在执行中生效时，停止未开始步骤，运行中的外部调用可能已经产生费用，实际结果如实记录，不承诺撤回或退款。

已确认提交、知识发布、事实更正等正式决定不随任务取消回滚。取消生效后迟到回调可留审计或历史产物，不得继续发布当前有效结果或覆盖新稿；重试是新尝试，保留取消记录。暂停模板只阻止新触发，不取消在途任务，关闭助手同样不取消运行。

## 9. 评分预测的产品规格（FR-002）

### 9.1 预测对象与呈现条件

预测对象是指定提交候选正文在指定生效要求下的技术总分，保留原技术满分及聚合口径。商务分、价格分、综合分和中标概率不是同一个目标。资料不足时可以只做部分条款判断。

| 情况 | 对外呈现 |
| --- | --- |
| 仅部分评分项可评，或总分口径未核实 | 部分条款分数、对应条款满分、占技术满分的覆盖；明确“暂不能可靠预测技术总分” |
| 全部评分结构和必要输入可用，但无适用且独立验收通过的业务模型 | 原始逐项估计及“未校准”原因；不提供伪装成正式预测区间的上下界 |
| 存在独立验收通过、范围匹配的业务模型，且本轮满足输入质量和覆盖门槛 | 技术总分预测，原量尺满分、模型适用范围、验证信息；只有区间经过验证时展示预测区间 |
| 模型通过验收但当前评分办法／工况不适用，或关键输入异常 | 提示不适用／无法可靠估分；保留有效逐项判断，不悄悄套用其他范围的精度 |
| 系统调用或解析失败 | 失败及影响范围，不能显示 0 分或沿用旧分冒充新分 |

总分呈现资格取决于评分结构可核对、必要输入有效、适用模型和覆盖门槛；门槛须按评分协议明确，不由前端临时猜测。缺失关键评分项时不能仅凭覆盖比例高就放行。首个正式总分版本默认要求全部评分项都有有效处理结果；例外必须先在独立评测中证明并写入协议。

### 9.2 覆盖与示例文案

评分分值覆盖 = 已有有效判断且可计入的评分项满分之和 ÷ 本项目技术满分。评分项不能重复计入，已确认不适用项须遵守原评分办法的分母口径，不能任意从分母剔除。

示例：目前两项得分合计 4/8，技术满分 60，应显示“已评条款 4/8；覆盖技术满分 8/60；暂不能预测技术总分”。不能显示“预测技术分 4”，不能把 4/8 外推为 30/60。

规则核对覆盖与评分分值覆盖分别计算。一项判定“无法判断”可能是工具成功运行后的有效状态，但仍不代表该评分项具备可靠分数；一次任务完成不能把二者都变成完整。

### 9.3 解释与改善建议

每个可能失分点包含评分条款、当前正文依据、判断、缺口和建议动作。只有技术总分标签时，系统可以解释自己的逐项判断，不能声称还原官方逐项扣分原因。

建议区分“补充缺失依据”“处理矛盾”“核实工程可行性”“改善表达结构”。不承诺“补这一段必得两分”，不把字数增加或复制高分稿当作可靠提高技术分的方法。

### 9.4 三种可信状态分别展示

1. 模型验收：未验收／验收未通过／通过指定独立评测，附适用范围和版本。
2. 当前预测：适用／不适用／资料不足／失败，附覆盖与输入。
3. 在线成绩对照：无配对／配对不足／可计算样本统计，附核验配对数、分母、时间范围和不确定性。

现有 20 组开始显示在线误差的门槛只属于统计展示，不授予模型验收资格。模型从未通过独立验收，即使已有 20、100 或更多在线配对也不能显示“模型已验收”。UI 不单独使用含义不明的“已校准”绿标。

默认按所选方法／模型版本及适用范围查看在线误差，并显示有效分母。跨方法汇总只作为总体观察，不能用旧模型的大量样本为新模型授予精度。具体分层不足时显示不足，不拿全库平均代替。

### 9.5 精度验收与拒绝估分

沿用训练方案中的原量尺／满分百分制换算及冻结协议。建议目标不在本文改写为已承诺阈值。发布报告至少包括 MAE、P90、偏差、接近比例、基线增益、区间覆盖与宽度、整轮稳定性、成功预测覆盖和分层结果。

报告必须列出所有应评案例、成功、失败、拒绝估分和无标签数量。不能通过只保留容易案例满足精度。样本不足时报告局限，可以继续数据整理和有限试点，不能宣布“分数与正式分高度一致”。

### 9.6 评分输入与相对表现

评分方法按[四层训练路线](../05-技术与设计/评分预测训练与验收方案.md)执行：正式逐项判断使用完整相关章节与必要图表，三次结构化结果交给统计模型；普通问答的片段检索不等于评分项已完整读取。同场排序与技术入围概率只有在相应数据齐备、独立评测和概率校准通过时展示，明确覆盖范围和事件定义，不与中标概率混用。

## 10. 问题、改稿、比较与实际提交

### 10.1 问题处理（FR-010）

沿用待复核、已确认待修改、暂缓、修改中、待复检、已解决、已驳回的业务含义；实现枚举以契约为准。关键转移如下：

| 动作 | 结果 | 不能产生的暗示 |
| --- | --- | --- |
| 确认问题 | 记录判断和理由，等待修改 | 不代表已解决 |
| 请求修改／采纳建议 | 保存建议和采纳决定；预览后可应用到章节草稿 | 不改写原PDF，不代表已生成评审稿或问题已解决 |
| 用户说“改好了”但没有新评审稿 | 提示生成工作草稿的评审版本，或上传外部新稿 | 不直接关闭问题 |
| 上传新稿并复评 | 形成新轮次及问题对应关系 | 不覆盖旧轮次 |
| 复检不再发现原冲突且依据有效 | 新轮次标明已解决及证据 | 不把工具失败当解决 |
| 人工驳回／暂缓 | 保存理由、作用对象和状态 | 暂缓仍属未处理，不能消除提交阻断 |

工期修改建议必须核实工作面、关键路径、资源和外部约束；把 240 天改写为 180 天不构成可行方案。AI 不擅自补足未核实的数量、资质和工程参数。

### 10.2 两轮比较（FR-020）

输入必须是实际存在的两轮评审，明确正文、规则、事实和方法版本。展示新增、仍存在、已解决、未复检的问题，以及相同评分项的判断变化。

评分办法、规则满分或方法版本不同，先提示不可直接归因。原始变化可以查看；若需要归因于改稿，应在同一冻结方法和可比规则下另行跑两稿。不可比较的分值不计算成“提升 X 分”。

新版不满足旧问题复核所需信息时标“未复检／无法判断”。解决一个风险后出现另一个风险应同时显示，不给笼统“所有问题已解决”。

### 10.3 标准提交登记（FR-035）

标准“登记提交稿”保留四类服务端闸门：

1. 输入是当前最新、与所选实际提交正文一致，生效招标、补遗、规则和事实没有更新。
2. 本轮必要来源与核心规则提取范围无已知未处理缺口或冲突；已识别且生效的核心规则核对完整，没有未完成或失败项。完整性按第7.3节分层表达，不把已识别条款全部运行当作证明原文零漏提；纯评分项失败不计入此核心核对分母。
3. 废标／否决／强制类规则已人工确认，或项目显式开启规则按原文接受。
4. 没有未处理的关键问题及废标／强制响应类问题，包括关闭可选检测之前已发现、尚未通过有效复核解决且尚未被有理由人工驳回的关键风险。已解决或已被有理由驳回的记录保留历史，不再以该问题阻断提交。

只剩非阻断改进建议时仍可登记，卡片明确剩余建议；“没有待办”和“允许登记提交”分别表达。评分总分无法可靠预测本身不必阻止提交，核心否决核对不完整则阻止。

确认卡显示项目、标段／轮次、投标主体、实际稿件、对应评审、时间与回执；点击确认时重新校验条件。用户停留期间上传了新稿，旧卡不能成功登记。系统登记不等于在交易平台提交成功。

### 10.4 已发生事实的补录例外

历史导入、线下提交或系统故障期间，实际投标可能已经发生但没有通过系统检查。必须允许在独立的“补录已发生的提交”入口记录真实稿件、时间、来源和缺失检查原因。该入口不调用放行闸门来伪造通过，不提供“已检查可提交”结论，不属于交易平台代提交。

补录记录持续显示“未经过系统完整检查”，有足够原件时可做事后评审，但不能补造当时预测。该事实可以参与历史查阅；能否进入训练仍按真实资料与标签准入判断；不能参与“事前预测误差”统计。补录与标准登记的区别在卡片、导出和审计中一致。

提交更正建立指向旧记录的新记录。截止之后上传的新稿不能自动取代实际提交稿；确需更正必须提供实际提交依据。重新打开项目不意味着截止时间延长，也不授权将事后改稿记为截止前提交。更正可能影响成绩配对、统计、知识和模型，进入第 14 节影响检查。

### 10.5 章节编制与AI修改（FR-037）

章节页为可展开树形表，显示标题、类型、编写状态、关联要求、页数预算和待处理问题。支持新增、移动、复制、删除、上下级调整；鼠标拖动与键盘动作等价。来源目录和正文解析不可靠时保留原始结构待核验。删除、批量移动或重建先预览影响；保留可恢复修订，不能解除评审要求。

点击章节打开详情，包含标题、编写计划、对应招标／评分要求、选定参考及可编辑正文。支持段落、标题、列表、表格、图片和原页引用；未支持的Word对象须在导入预览列明，不能静默丢弃。既可从现有稿导入，也可从要求生成候选目录，经确认后开始编制。

选中文字可解释、改写、缩写、扩写、补依据；AI提出插入／替换草稿及来源，预览新增、修改、移动、复制、删除，显示文字标记并逐项应用或拒绝。撤销新增修订，不重写历史。缺少项目参数时使用明确待补项，不把参考项目数量、工期或资质搬为本项目事实。局部重生成保留未选章节和人工改动；批量覆盖人工修改必须给出逐章差异。

正文编辑自动保存，显示保存中／已保存／失败；“已保存”只在服务端确认对应修订后出现。网络断开保留本地待提交内容并提示，同章节并发修改发现修订冲突后展示差异，不最后写入覆盖。新生成建议绑定基准修订，基准已变化时须重新比较；切项目、上一章／下一章前保留当前编辑。事实和引用不因纯文字修订自动获确认。

点击生成、生成并评审或离开当前章节时，要区分已保存修订与本地待保存内容。生成动作先完成所选内容保存并取得确认，再固定快照；保存失败则停在可恢复错误，不能静默生成上一版。用户显式从版本列表选择既有保存版生成时，才可使用该旧修订并标明身份。

AI修改应用前除检查正文基准修订外，还检查相关规则、事实与来源当前有效性。已停用、撤回或当前用途不允许的来源不能新增应用；保留候选及失败原因，允许移除失效来源后重新生成，不自动用旧缓存补入正文。已经形成的历史草稿和报告保留当时来源及后续影响提示。

### 10.6 模板、版本生成与版面核对（FR-039）

目录模板定义章节结构；版式模板定义封面、字体、页边距、页眉页脚、编号等，分别选择和保存。项目生效要求优先，模板与暗标或格式条款冲突时提示核对；不得因企业模板默认值覆盖强制要求。

“生成版本”固定草稿快照、引用、目录、模板与资料修订，后台产出Word和PDF；失败分格式报告，成功文件可独立下载但不能冒充另一格式已成功。生成期间继续编辑不影响该版本，界面显示基于哪次保存。版本列表分别标记最新生成、当前评审、实际提交，不以一个“当前”标签混同。

章节页数预算是编写辅助，格式核对以实际生成PDF的物理页、图表和目录结果为准。生成后预览超页、缺图、乱码、断表、目录／编号和暗标残留等可检测项；未覆盖项明确列出。正式评审读取具体生成PDF，不能对编辑器未定稿直接给通过结论。下载Word后在外部修改须重新上传实际文件并生成对应证据，不能继续使用旧PDF的评审结论。实际提交以参加交易平台提交的文件为准。

### 10.7 Word与PDF的对应关系

DOCX与PDF由同一次受控构建产生时，记录源文件／草稿、构建版本和两种产物身份。外部同时上传的Word与PDF不因同名、大小或上传时间相近就被认定同稿。可以直接评审所选PDF；尚未核验对应关系的Word仅作为关联原件，报告不声称同时验证了Word。

需要以DOCX交付时，应从该实际DOCX产生可追溯PDF并核对图表、分页与要求，评审引用该渲染身份；后续更换DOCX必须重建对应关系。DOCX转换未通过产品验收时，保留PDF路径，并说明Word交付尚未获得对应系统检查资格；已在线下发生的提交仍可有据补录。

单份DOCX上传成功但解析／转换失败时，在该原件行和持续错误卡显示“Word原件已保存／本次对应检查未完成”、具体缺口及受影响范围；主要动作是“上传此修改稿的PDF”，只有错误仍可重试时才提供重试。该动作带入原项目、标段／轮次、资料角色及改稿来源，用户只核对必要的文件目标，不必先进入版本导出或章节编辑。重新选择的PDF按自己的逻辑文件目标建立独立版本，与原DOCX记录用户声明的关联；不同格式不能强行写成同一逻辑文件的新版本，也不能把该关联当作受控渲染或已核验同稿。旧DOCX、失败记录和既有评审保留。界面和报告明确实际选作本轮评审的PDF名称与版本；PDF评审完成只授予该PDF对应结论，未核验的DOCX仍显示“Word交付未获对应检查资格”。取得可核验的转换／对应证据后才能另行更新对应资格。

## 11. 历史项目、档案与导入

### 11.1 查找与详情（FR-021）

支持自然语言和结构化条件搜索：工程／项目名、地区、类型、标段／轮次、主体、提交时间、评分办法、工期、是否有核验技术分、结果、缺口。未实现的条件不假装精确过滤。排序显示匹配原因，成绩仅在口径明确时展示。

案例卡显示实际主体、工程特征、原量尺技术分及来源状态、入围／中标等结果、资料缺口。高分与中标分开；“未入围”“被否决”和“未知”不合并。

档案详情可回答：依据哪组招标补遗、实际提交哪一稿、当时做过哪些系统评审、正式成绩来源何处、复盘哪些已核实、哪些内容适合参考。没有历史预测就显示没有，不用当前模型生成的回测分冒充当时预测。

### 11.2 比较与选用（FR-023）

提供项目条件对照、相同评分项章节参考与选用。比较先显示工程规模、工况、地区、评分办法、企业资源等差异。不同技术满分即使都换成百分制，也不能直接推断内容优劣。

选作参考只建立引用，不复制整个项目，不迁入企业事实，不自动重评分、不增加训练资格。AI 可以按任务自动选择已确认且适用的参考；用户能够查看与移除。被移除的参考从后续任务上下文退出，旧轮次保留当时引用。

### 11.3 批量导入（FR-022）

导入对象是资料包和登记表。流程为接收、内容检查、归组预览、处理异常、确认入库、完成报告。用户可确认无争议组并暂存争议组，不要求整批一次解决。

| 异常 | 行为 |
| --- | --- |
| 项目／主体／轮次匹配不确定 | 暂存该组，请求确认，不静默并入 |
| 同名异稿或多份“终稿” | 展示摘要和区别，请确认实际提交稿 |
| 只有综合分或缺满分 | 保留档案，标记技术标签缺失 |
| 有技术分但出处未核验 | 保存待核验，不进入正式主评测配对 |
| 相同文件或重复批次 | 关联既有内容，幂等续跑，独立样本数不增加 |
| 解析失败或缺页 | 保存原件与失败范围，档案可查，评分样本暂不准入 |
| 一份结果含多家企业 | 按主体拆分标签关联，原件可共用 |
| 包含外部企业资料 | 明确外部身份，不能成为本公司可用业绩／设备 |

入库报告分别给出档案数、有效提交数、已核验技术成绩配对数、当前实验准入数、重复数、待补数和失败数，说明集合可能重叠，不机械相加。批次取消保留已确认入库结果，报告实际完成范围；再次执行仅处理剩余或更正内容。

## 12. 企业知识的维护与使用

### 12.1 知识分类与字段（FR-024）

| 分类 | 内容 | 特别约束 |
| --- | --- | --- |
| 本公司可用事实 | 人员、设备、资质、业绩等已核实资料 | 主体、来源、有效性及当前可用条件；历史具备不等于本项目现在可用 |
| 工法与技术措施 | 沟槽、支护、交通导改、质量安全等 | 工况、前提、参数依据与局限 |
| 规范与规则 | 标准、地区规则、评分办法 | 发布与生效时间、适用地区、版本、失效／替代关系 |
| 复盘经验 | 经核实的否决原因、有效做法、常见缺口 | 区分官方理由、人工判断和待证实推测 |
| 参考章节 | 历史施组的结构、方法与图表 | 原项目和企业身份不丢失；专属事实不能直接套用 |

条目最少保存标题、内容、分类、来源对象和定位、主体、适用范围、状态、版本、确认人及时间。有效期限有据才填，未知不当作永久有效；需时效核查但有效性未知的条目不能通过适用性检查。多来源条目保留各出处，摘要不能替代原文。

### 12.2 产生、确认与更新（FR-025）

可直接上传资料建立候选，也可在项目复盘时由 AI 提议。提取先剥离或显著标识项目专属名称、工期、数量和企业事实。确认卡呈现内容、出处、主体、适用条件与影响。登录成员完成确认，不新增岗位审批层级。

确认人需要补核实材料时条目保持待确认，不提供“一键跳过来源并发布”。AI 不能自行将候选变为已发布。内容更新产生草稿新版本，发布前可比较变化；并发修改提示冲突，不覆盖他人决定。

### 12.3 检索、引用与冲突（FR-026）

先按用途、状态、主体、工程条件、地区、时间和版本筛选，再做关键词／语义召回。用户看到相关原因、原文和不适用之处。没有合适知识时明确说明，不扩大到失效内容凑答案。

当前生效招标与补遗用于确定本项目要求；适用强制规范用于核查合规。出现冲突、规范适用不明或多份依据互相矛盾时要求核验，不用简单“最近文件优先”决定。历史知识只能提供参考。

每次实际引用记录条目版本、摘录、用途、目标任务和适用说明。知识索引不是主记录；重新建索引不改变知识状态和历史引用。检索失败与没有结果分别提示。

### 12.4 停用与影响追踪（FR-027）

停用即时影响新增引用资格；即使搜索缓存仍含旧结果，执行任务前仍须校验当前状态。已在运行任务使用被停用来源的，完成时标记受影响，不把结果自动作为最新可信结论；用户可重新评审。

影响列表分在办项目、已提交项目、归档项目，以及引用该知识构造的实验／模型数据。系统给复核任务，不自动替换工程措施或更改提交稿。旧报告增加后续失效提示，正文与当时原始判断保留。

## 13. 正式成绩、样本准入与信息隔离

### 13.1 正式结果登记（FR-009）

先选具体提交，再录入结果。必需核验：项目、标段、轮次、投标主体、实际稿件、技术分／综合分目标、满分、聚合方式、成绩原件及页码、发布时间和取得时间。官方来源存在而未核实对应关系时仍为待核验。

数值约束为满分大于零、分值不小于零且不大于满分，使用十进制；未知保存未知，不填零。零分只有原件明确给出时才登记；未给分的被否决案例保留否决结果与无技术分。只有综合分时保留综合分，不反推缺失技术分。

多评委分数按该项目正式办法聚合，不能擅自选最高、简单平均或去极值。原件只给最终技术分时保留该事实，不伪造评委分项；缺少聚合说明时标未知，按实验协议判断准入，不能默认使用未经核验口径。

冲突成绩进入待处理；更正追加记录，并指向被更正记录，不能选一条“最新且不冲突”的旧成绩掩盖仍未解决的新冲突。

### 13.2 严格样本准入（FR-028）

| 层次 | 条件 | 可用于什么 |
| --- | --- | --- |
| 可查档案 | 项目身份和资料来源可记录 | 查阅、补材料；不代表可参考或可评分 |
| 可参考内容 | 来源与使用条件可核实，通过任务适用性检查 | 内容建议，不含未授权的企业事实转移 |
| 有效技术标签配对 | 唯一实际提交稿及规则、技术分满分口径、来源对应且已核验，无未解决冲突 | 正式成绩对照候选 |
| 训练／评测准入 | 上述条件及完整解析、去重分组、时间记录、实验来源要求、明确数据用途 | 对应实验的候选集合 |
| 实验已选用 | 已冻结成员、划分、方法与用途，无信息泄漏 | 指定训练／开发／最终测试之一 |

公司台账或口头报送可暂存并做明确标记的探索实验，不与已核验官方原件的主验收结论混报。是否允许某类来源进入实验由冻结协议决定；即使允许，也要分别报告官方原件子集。待核验记录不得进入正式在线误差统计。

同一提交的更正前后不计两份独立样本；同项目多企业、相同正文和同模板形成相关组。数据组规模、独立项目数与样本数同时报告。样本合格不等于必须训练，也不保证精度。

### 13.3 用途隔离（FR-036）

| 任务 | 允许读取 | 不得进入其正式输入的内容 |
| --- | --- | --- |
| 当前正文合规评审 | 本轮生效招标补遗、正文、必要且确认的项目事实 | 事后结果、评委意见、以历史案例代替本项目响应 |
| 普通内容建议 | 适用且来源明确的参考正文／企业知识 | 把历史技术分、排名和评委评语作为当前项目已得分的证据 |
| 正式评分预测 | 冻结评分要求、正文、允许的事前事实与受控方法输入 | 目标提交正式成绩、评委意见、事后修改、含这些信息的聊天摘要或工具结果 |
| 受控评分锚点 | 仅符合该实验训练来源、分组和时间限制的锚点 | 测试／验证成绩、未来取得成绩、近重复来源泄漏 |
| 成绩核验与复盘 | 具体提交、正式结果、当时预测、允许的参考 | 将事后解释回写成当时预测；冒充官方分项归因 |

打开历史案例成绩后，用户说“重新评分”，必须启动干净的评分任务，不能把当前聊天整体传入。正式模型输入从结构化白名单构建；隔离还覆盖向量索引、摘要、提示、缓存和引用衍生物。

离线独立测试时，全局历史库与企业知识中的测试项目派生内容同样需要隔离。不是只删掉目标案例的分数就算无泄漏；同组其他成绩、同正文知识片段、评委复盘也可能泄漏。训练方案定义的分组与时间限制适用于全部检索通道。

### 13.4 事前预测与回测

文件发布时间、生效时间、人员实际取得时间和系统录入时间分别记录，未知时不推断。历史材料晚入库不表示其内容在当年提交时不存在；回测需核实当时有效版本，不能用入库时间替代生效时间。反过来，事后改写的文件即使名称含旧日期，也不能进入当时评分输入。无法证实时间关系时标不确定并按实验协议排除相应正式结论。

用于在线真实误差的预测必须在成绩取得前、针对实际提交稿产生，保存可核验时间和方法。提交后才跑的历史预测标回测，不冒充事前预测。用户展示、手工输入或从其他通道取得的结果都要记录已知时间；只用上传时间不足以证明盲预测。

登记提交时绑定选用的评审预测；默认选对应冻结输入中、实际提交时间之前最新的一条成功且可证明未见标签的预测，保留预测ID和方法版本。不存在则登记“无合格事前预测”。补录只能关联有原始时间与输入证据的既有预测，不能事后生成。

同一有效提交只贡献一份主在线配对；更正以追加记录更新有效关系，不事后挑选最接近成绩的一次。后续重跑保留为独立回测，不覆盖绑定。无法证明预测未见标签则排除正式在线误差，保留档案说明。

## 14. 模型改进、发布与错误更正

### 14.1 数据到模型的工作流（FR-029）

接收案例 → 预检查 → 核验提交与成绩 → 冻结分组和时间划分 → 固定基线与方法 → 开发验证 → 冻结发布协议 → 最终独立测试 → 观察运行 → 人工业务发布。

批量实验先离线预览样本、重复次数、并发和预计调用／费用，确认后按冻结manifest执行；单样本失败隔离，恢复只处理未完成或明确重试的失败项。影子模型以相同冻结输入独立比较，不替换业务预测、不重复增加官方样本数；方法改变另建实验，不能在线挑最接近已知成绩的一次。

首批建议用 10–20 份真实资料验证入库与口径；随后按约 300 份资料形成开发与独立测试。数量是采集规划，不是精度承诺。先复用现有逐项判断与简单监督校准，算法路线和样本建议唯一维护在训练方案。

模型状态区分候选、验证未通过、观察中、业务使用、已回退／停用。业务发布要求：来源和划分检查通过、协议门槛满足、模型可部署且适用范围已限制、观察与回退方案具备。没有确定精度协议不能发布成“已通过业务验收”的模型。

模型维护视图从成绩对照或次级设置进入，不作为投标人员日常必经页面。发布卡明确范围、模型、证据、替换对象和回退方式。业务模型更换只影响之后任务；历史预测保留原版本。已开始任务继续使用启动时固定的模型，发现模型存在严重问题则标记影响并停止新增使用。

### 14.2 实验验收约束

相同项目、模板和近重复正文按连通组划分，较新项目保留时间留出。填补、归一化、参数选择、锚点与邻居只使用相应训练来源。最终测试只用于最终判断，不反复调到达标；后续方法调整须使用新的独立证据。

训练报告保存成员、数据摘要、用途、取得时间、来源核验、实际输入／检索清单、方法及缓存身份。任何一层无法证明隔离时不得给出正式通过结论。范围外项目回退到明确未验收的逐项判断或拒绝总分，不自行扩大已知精度适用范围。

### 14.3 错误更正与影响（FR-030）

| 错误 | 必须处理 |
| --- | --- |
| 配错提交稿、技术分、满分或主体 | 追加更正，暂停错误配对的统计与新训练资格，重算当前有效统计 |
| 发现训练标签或正文错误 | 找出用过它的数据批次、实验与模型，标记受影响并暂停受影响模型新增业务使用 |
| 错误内容已变成知识 | 停用相关知识版本，列出引用项目 |
| 规则、解析或方法错误 | 保留旧报告；生成有明确原因的新轮次或实验，不覆盖原结果 |

影响检查按引用关系追踪；当前结论未查清时显示“待复核”，不能继续标可信。恢复使用需有复核证据和明确决定；旧统计报告保留原数据身份并增加失效说明，修正后的统计另行生成。

## 15. 报价、报告与业务对照

### 15.1 报价（FR-006）

沿用招标计分公式和结构化数值工具。输入包含公式、满分、基准价取法、最高限价、必要参数和对手估计；缺少公式或关键参数时不编造最优报价。对手报价为假设，显示情景范围；结果保留公式与输入。

AI 可以解释和发起试算；保存方案由人确认，留审计。金额与分值使用十进制。价格分变化与技术分换算注明条件，不转化为成本、利润或必中标建议。报价模块关闭时对话、导航和报告遵守同一设置。

报价保留多候选、受限区间曲线、有出处的首次预填和手动保存历史方案；试算不自动保存成方案。查看指定版本使用其原公式、输入和假设；参数更新后旧曲线标待更新，不由迟到结果覆盖新参数。

### 15.2 报告与导出（FR-007）

报告是项目业务结果的完整呈现，可从工作台一键进入。包含项目、稿件、评审输入、关键风险、响应矩阵、评分覆盖和适用状态、引用与待办。支持既有 Word 报告和批注 PDF；新入口保留原功能。

系统区分三类文件：投标正文用于交付，评审报告用于理解结论，批注审阅稿用于修改参考。按钮与文件详情按用途和格式命名：“下载投标正文（Word）”“下载投标正文（PDF）”“下载评审报告（Word）”“下载批注审阅稿（PDF）”；尚待生成时沿用第3.5节的“生成版本／生成并评审”，在正文版本区明确生成对象，不能用没有用途的“下载Word/PDF”。结果页直接取回报告与批注稿，正文从正文版本区取回；下载不增加泛化确认。文件详情、提示与默认文件名均带用途、项目／稿件版本，标准提交选择器只以真实artifact_kind识别资格，不凭文件名推断。

页面、对话卡片和导出引用同一业务数据。导出显示生成时间、对应轮次和是否历史结果，不把新旧轮次拼接。隐去预测分数的项目，导出同样隐去。失效引用、未确认依据、部分覆盖、未经过系统完整检查的补录提交都必须保留说明。

在原 PDF 上的批注绑定文件版本和原页，不能给其他版本套用坐标。生成失败显示失败，不返回空文件冒充成功。跨项目批量导出及机器可读迁出见第 17 节。

投标正文生成时不自动插入系统风险结论、界面来源徽标、AI操作说明或审阅批注；作者有意写入的规范引用和正文注释按实际要求保留。待补事实、未确认占位及暗标残留须在版面／内容检查中列出，不能直接删除以掩盖关键缺口。标准提交选择具体正文版本；批注稿或报告误选要提示用途冲突。线下确已提交的错误文件仍可据实补录，不能替换成另一份干净稿伪造事实。

重新下载报告时，固定当时评审数据，同时采用当前显示设置及来源影响提示生成对应展示副本；展示副本有自己的文件身份与设置版本，不覆盖原始产物，也不另造评审或训练样本。缓存键包含报告、展示设置和影响状态，关闭分数后不能直接返回含预测数值的旧缓存。已经下载到用户设备的旧文件不会自动改变，界面须提示其对应生成时点。

### 15.3 指标与复盘（FR-011）

入围、中标、否决闭环、正式成绩误差与整改得分变化沿用一期方案的分母和状态定义。正式在线误差的样本来源收紧至第 13 节合格事前配对；这一收紧需实现、契约说明和回归检查同步完成。

风险闭环分别统计已解决与误报驳回，提交时开放数读取当时快照。逐轮走势绑定正文、规则和方法，不可比时明确断点；隐藏预测仍可查看风险计数，不泄露分值或差分。

统计展示时间范围、项目范围、口径、核验状态与样本量。未知结果不填未中标；候选人不等于最终中标；分母为零不显示 0% 的效果结论。因样本更正重新计算时标明当前有效数据身份。

没有官方分项时，复盘可以给出待核实的差异假设，不把某段文字直接认定为正式扣分原因。模型替换、规则变化和项目差异不得混成改稿收益。

## 16. 非功能、异常与可访问性

### 16.1 非功能需求

| 编号 | 要求 | 验收方式 |
| --- | --- | --- |
| NFR-001 | 问题、判定、评分解释和知识引用可回到真实原件版本与位置 | 抽查正文、缺失型判断、跨项目参考和失效来源；伪造引用不得生效 |

| NFR-003 | 失败、未知、覆盖不完整不显示通过 | 逐项注入解析、模型与工具失败，核对卡片、报告、闸门 |

### 16.2 性能与容量的验收口径

初始测量负载为 300 个历史案例、1,000 条知识、5 个同时在线成员、2 个同时运行的评审任务，使用真实资料页数和图表比例。该负载是测量方案，不是已验证容量。

建议同步任务受理反馈 P95 不超过 3 秒、元数据列表／筛选 P95 不超过 2 秒，均不含文件内容传输；测量需记录硬件、并发和缓存条件。正式交付前用部署环境确认或调整目标，未完成压测不声称达标。完整评审时限按页数、图表和模型能力测量后冻结；不承诺固定几分钟完成所有标书。

文件大小、页数、批次数量、并发、模型重试次数与任务超时为显式部署限额，上传前可见，超限可恢复。设置值须随验收环境记录；不能以尚未配置限额的方式上线无界批量任务。后台任务在合理阶段给进度，不编造百分比或剩余时间。

### 16.3 异常恢复矩阵

| 异常 | 用户看到 | 状态与恢复 |
| --- | --- | --- |
| 资料缺失 | 缺哪份材料、哪些能力受限 | 保留已上传资料；补齐后接续 |
| 登录失效 | 登录提示与待保存内容状态 | 不执行未确认写入；登录后重新核对对象和修订，恢复显示不等于自动重放原确认或旧保存 |
| 模型不可用／输出不合法 | 失败环节与已完成范围 | 有效已完成结果保留，失败项重试，不记通过 |
| 上传完成但解析失败 | 原件已收、解析失败及原因 | 可以下载原件、换有效版本或重试 |
| 断流或浏览器关闭 | 重开后显示服务端任务状态 | 不启动重复任务，不从聊天文字推定成功 |

| 用户取消批量任务 | 已完成、未开始、正在取消分别计数 | 保留已确认成果；续跑幂等 |

## 17. 归档、清理、初始化与恢复（FR-031、FR-032）

### 17.1 保留规则

归档不自动删除数据。默认不做按时间自动物理清理正式原件、提交、结果、已发布知识或审计；实际保存周期由公司确定后配置。短期会话展示、缓存、解析中间件和正式业务记录分别管理。

删除消息／隐藏会话不级联删除业务对象。误上传的未引用草稿可从活动视图移除，保留必要操作记录。已进入评审、提交、知识或样本的原件有依赖时不提供直接物理删除；显示依赖并走专门处理。删除与撤销确认必须清楚显示范围。

真正清理原件时，需要检查项目、提交、知识、实验、模型、索引和备份影响，明确不可恢复范围与既定备份策略。未确定公司清理规则前保留原件；不能用“删除会话”暗中承担清理职责。临时凭据和有期限下载链接不当作永久证据地址。

### 17.2 全新系统初始化与资料入库

本产品全新建设，没有旧系统迁移、旧接口兼容、状态映射或双系统切换需求。项目、版本、轮次、人工决定、提交和成绩从新系统独立建立身份，不要求保留旧系统ID或沿用旧状态。

公司提供的历史标书、招标补遗和正式成绩作为新资料批次入库；先dry-run核验摘要、出处、成绩口径及正文关联，异常进入核对队列。资料录入不等于训练准入，不承接旧系统模型资格，不补造当时预测。

首次部署从空库初始化默认设置和方法配置；初始化失败可在隔离环境重试，正式资料入库后不得用重置覆盖真实记录。备份恢复、档案导出及未来结构升级属于正常运行要求。

### 17.3 导出与备份恢复

项目迁出至少包含原件清单与摘要、各版本、评审输入、问题决定、提交、正式结果、会话业务操作、引用与知识版本映射；模型迁出包含数据与实验身份及可部署配置，不包含密钥。导出依赖的原件不可用时报告缺失，不声称完整。

备份涵盖数据库、对象存储和模型产物的关联一致性；检索索引可以重建。恢复演练应从备份恢复项目、正式成绩、知识版本、审计及模型引用并核对内容摘要。RPO／RTO 由运行环境验证后确定，是正式运行门槛，未演练不能声明灾难恢复完成。

### 18.3 验收场景写法

每个 AC 包含前置条件、用户操作或系统事件、期望业务状态和可见结果、禁止出现的行为、对应 FR／NFR。实际执行时补环境、资料和版本、结果与证据。未执行的软件场景保持未执行，不用文档推演结果填成通过。

优先验证四条长路径：新项目上传至新版复评；历史批量导入至成绩配对；知识发布至失效追踪；评分预测至正式结果、更正和模型回退。每条路径包含中断、重试和版本变化。

真实用户试用另外观察三个任务：①给两项独立关键阻断及若干普通建议，用户处理第一项后能否继续发现第二项，并区分剩余建议是否阻断，不用登记按钮最终挡住代替信息可理解；②给替代明确、局部变更、互相矛盾三组补遗，用户能否回看原页，只确认有据关系，对无法确定项保留待核实，不按上传顺序猜测；③给最终技术分、仅综合分、主体冲突三组官方材料，用户能否复用所选提交身份、只核差异、保存未知或待核验，不把零或预测分填为官方技术分。首轮同时观察首次上传找到主要下一步，以及外部改稿后认清受检文件和恢复入口。记录卡点、误认和实际动作，用于可用性验收；不增加默认表单、审批或经营过程指标。尚未真实试用时保持“待观察”，不把规格推演当用户验证。

交付状态分别记录“A1快速评审可用”“评分研究链路可运行”“模型业务验收通过”，各自附实际证据或未完成原因；不能用一个总完成绿标替代三者。首批组合演示同时检查：一个核心风险从两侧原文、外部改稿到有效复检；同稿评分的完整章节输入、三次独立判断、逐项缺口、费用与失败范围。未验收时只展示第9节允许的原始逐项估计与未验收原因，不能强行给正式技术总分或区间。该演示是双P0链路验收，不替代真实检测效果、独立评分精度和生产验收。没有官方标签时可以继续开发和有限试用，交付单明确尚缺材料及未完成的模型验收。

需求索引中的A包含A1与A2，按对应功能验收，不把A2全部完成作为A1可用的条件。上述阶段规定业务交付依赖。为优先验证评分预测，在身份、原件、版本、证据与用途隔离基础建立后，B的首批案例核验、C的完整章节判断和基线实验可与A的最小工作区并行，不等待A全部页面、在线编辑器、版式模板或任务平台完成。编辑、模板、触发器与导出的新增状态和接口必须独立实现验收；不把浏览器编辑器演示当完整产品。实验入口不提供正式提交或模型业务发布；正式登记需A1的核心闸门；将分数作为已验收业务预测使用还需C的模型验收，模型未验收不阻止合格的核心核对和真实提交登记。D的来源、版本和用途隔离基础可以并行建设，但不能先全量抽知识阻塞评分样本入库。阶段不绑定未经评估的周数；按可核实退出条件判断完成。

登录、私有存储、基本备份和来源校验从首批真实资料入库起启用；E 阶段完成容量、恢复演练和稳定运营验收，不表示可以到 E 才开始保存备份。任何阶段未达到正式运行门槛时，仅按已验证范围试用，不将开发环境视为正式服务。
