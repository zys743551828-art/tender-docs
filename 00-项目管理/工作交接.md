## 3. 本机开发环境（Windows）

工具都装在 D 盘（用户要求：非必要不装 C 盘）。

| 工具 | 位置 | 说明 |
| --- | --- | --- |
| Python 3.11.9 | `D:\tools\Python311` | 与后端 Docker 镜像一致 |
| Node.js 22 | `D:\tools\nodejs22\node-v22.23.2-win-x64` | 必须用 22：Node 24 下前端测试的 MSW 请求拦截挂起，151 项失败 |
| pip / npm 缓存、npm 全局目录 | `D:\tools\cache\pip`、`D:\tools\cache\npm`、`D:\tools\npm-global` | 用户环境变量 `PIP_CACHE_DIR` 与 `~/.npmrc` |
| Docker Desktop | `D:\Docker\Docker` | 其 WSL 数据盘在 `C:\Users\74355\AppData\Local\Docker\wsl`（约 1.7 GB），迁到 D 盘需在 Docker Desktop 设置里由用户操作 |

已建好的依赖环境：`tender-app/backend/.venv`（`pip install -e '.[dev]' bandit`）、`tender-research/.venv`（`pip install -e '.[dev,store]'`）、`tender-app/frontend/node_modules`（`npm ci`）。

后端测试需要可建库的 PostgreSQL。原 `bidwb-test-pg` 已按用户要求关闭。后续验证使用独立临时容器，结束后 `docker stop bidwb-fusion-check-pg` 会自动移除；不重启用户关闭的容器：

```bash
docker run --rm -d --name bidwb-fusion-check-pg --tmpfs /var/lib/postgresql/data:rw,size=512m -p 127.0.0.1:15432:5432 -e POSTGRES_HOST_AUTH_METHOD=trust postgres:16.15-bookworm
```

在 Windows 上运行 Python 程序前设置 `PYTHONUTF8=1`。测试时设置 `BIDWB_TEST_ADMIN_DSN=postgresql+psycopg://postgres@127.0.0.1:15432/postgres`。数据库地址使用 `127.0.0.1`，避免 `localhost` 的 IPv6 连接停顿。前端、Shell 脚本和 Dockerfile 由 `tender-app/.gitattributes` 固定为 LF，无需修改全局 Git 设置。核心容器启动命令见 `tender-app/deploy/README.md` 的本机联调小节。
