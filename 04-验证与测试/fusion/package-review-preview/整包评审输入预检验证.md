# 整包评审输入预检验证

应用提交 `8fd4c06`，融合分支 `fusion/bid-workbench`，部署在现有 `fusion_v3`。本片是 F01-06 的输入适配首片：把明确选择的本方包、权威依据、要求清单和可选人工范围记录组合成只读输入预览，并报告当前阻断。**不提供正式评审执行器，不创建评审任务，不改写旧正文、规则、包或清单头。**

## 选择与身份

接口为 `POST /api/v1/bids/{bid_id}/packages/{package_id}/revisions/{revision_id}/requirement-inventories/{inventory_id}/review-input-preview`。路径与正文固定实际项目、包、修订、要求清单和摘要；人工记录显式选择或以成对 null 表示不附，不取最近一次记录，不跨历史拼接覆盖。错误摘要返回422，错包清单或跨清单记录返回404，不回退到其它输入。

响应 manifest 为 `bid-package-review-input/1`、`kind=preview`，包含所选冻结视图的完整成员、文件版本、解析、物理页段与身份，另含清单、可选人工记录；规范摘要只标识这组不可变选择。它不是已持久化的新评审身份，不能当作正式 `review-content/1` 输入、任务回执或历史冻结证明。

当前主体／标段／轮次、包头、清单头、规则集、项目生命周期和来源政策／效力是独立观察。换包头、撤回来源或关闭项目后，所选旧输入的 manifest 与摘要保持不变，变化体现在 blockers；不按当前值重造历史。

成员未冻结解析、未知页数或未划分范围均保留未知；已知页数按逻辑页段并集检查物理断口，共享区间不重复计数，也不能盖住真正未分配的页。未知页数不造假页码，极大安全页数不逐页循环。

精确抽取输入／完成绑定不能单独证明要求完整性。`review_ready=false`、`launch_available=false`，保留要求完整性未证明与执行器未接入等阻断。人工范围记录只附上下文，不设置“必须先人工认定全部满足才能运行评审”的循环条件。既有单正文评审入口尚未改造成整包执行，不从本预检静默调用它。

## 接口、交互与隔离

预检复用 Session、Origin、CSRF，业务查询处于 REPEATABLE READ／READ ONLY 事务。不需要 Idempotency-Key，也不登记 Command、operation 或模型请求；通用客户端附带幂等头不产生业务写入。没有新DDL、角色授权或初始化计划变化。实际 OpenAPI、前端生成类型与契约说明同步。

要求清单工作面新增“整包评审输入预检”，默认不自动请求。所选记录仍在加载或存在未决写入时禁用；返回后显示中文阻断、成员解析／页数／逻辑范围和明确版本，技术摘要折叠。成功预检仍显示“暂不可正式评审”，没有启动按钮。

响应核对目标与权威修订、主体／标段／轮次、清单／规则集与范围记录摘要，错误就绪声明拒绝。切换清单清除旧观察，离开再返回同一清单也递增代次，迟到响应不能恢复旧结果；StrictMode 和卸载有相同边界。本片不增加CSS选择器、浮层或全局DOM操作。
