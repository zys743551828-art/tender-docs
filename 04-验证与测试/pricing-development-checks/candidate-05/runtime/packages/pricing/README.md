# 有据报价后端

本模块对应产品Owner《报价最小产品协议》，为新系统的独立、按需报价工作面提供后端。当前实现需要主API集中include `apps.api.pricing_routes.router`，实际OpenAPI通过`packages.pricing.contracts.extend_openapi(actual)`补齐；函数只扩展已注册操作，不把目标路径当实际交付。

## 实际流程

1. `GET /bids/{bid_id}/pricing-context`取得登记所需强ETag；`GET .../pricing-formula-sources`从生效招标、补遗的精确原页选择证据。
2. `POST .../pricing-formulas`一次人工“确认并登记公式”。强If-Match来自context，使用真实会话、CSRF和幂等键。参数、量尺、取整、完整原文对应解释及两项明确确认缺一拒绝，不增加第二审批。
3. 从公式详情取得ETag，`POST .../pricing-simulations`独立试算；输入明确相同金额单位/币种，服务器不换算。合法但区间不满足或假设不足可以形成真实null分情景。
4. 需要保留时，以模拟ETag及服务器simulation_id `POST .../pricing-plans`。保存读取服务器冻结输入和结果，不信客户端分数。试算不会自动保存；公式和方案列表及详情支持回看。

所有十个报价操作都遵守pricing开关；关闭后返回403和设置入口说明，保留既有对象与记录，开启不自动试算或保存。当前其他聊天、提醒和报告没有新增价格结果输出，本模块不宣称那些未来展示入口已实现。浏览器表单保护、防抖、迟到响应处理、曲线断点和整站展示开关仍由前端与集成验收负责。

## 公式与来源

formula_version_id是服务器生成的不可变manifest blob ID。manifest记录项目、当时资料快照及修订、标段轮次范围、受限计算参数、单位/币种、取整、解释、精确parse/page/evidence/source及head、完整祖先摘要、确认人/时间及计算器实现SHA。原文按完整证据块逐字匹配，禁止用截取条件的quote登记。来源必须是本项目当前生效招标/补遗、最新完整解析及可用无缺口原页；canonical original/parse身份复用RAG helper。

manifest在来源图中实际登记为feature/prebid_content，并关联精确parse子来源与原件祖先及证据引用；追加人工决定，不借用模板或规则表。对象PUT在数据库事务之外；最后短事务以bid→graph锁重核当前context、精确证据、全部祖先head、项目范围与时效后，一次登记blob、feature、血缘、引用和决定。竞争失败的stage对象不成为可用公式，可按独立私有对象清理规则回收。

试算、显式保存和幂等重放同样重核来源、实现身份与项目范围，不能用旧确认或旧响应绕过撤回、新解析或补遗。同一生效招标/补遗范围的无关资料快照变化不强迫重新确认；新补遗未核对时旧公式不能继续计算。历史读保留当时公式/输入/结果，动态提示当前影响，绝不重新计算冒充旧值。READ COMMITTED外的旧快照资格检查失败关闭。

## 精确受限计算

仅支持最低有效报价比例法、包含本方及全部数值有效对手假设的算术均值偏离法。每个候选/曲线点重新计算自己的基准价，同价不同对手保留数量，只有本方候选按Decimal值去重。主候选始终保留，补充最多50、对手最多200、曲线最多101点。金额/系数是有界Decimal字符串；满分须可精确表示为两位小数，最终仅支持half_up_2dp、half_even_2dp。

均值分母在代数上消去，精确乘积之后只有一次最终除法，避免循环小数基准价把精确半分位推错。例如本方20、对手21/23、满分30、系数1的原始分恰为28.125：half_even是28.12，half_up是28.13。输入界限和受控高精度保证不使用float或中间金额取整。

主price_score与各点score允许null；本方超区间eligible=false，假设数量不足可eligible=true，均给notes。只有真实计算出的零分才是“0.00”。eligible仅代表本公式价格数值区间，不代表整体投标资格。返回每点基准价、有效数量、排除原因和计算步骤；不虚构最优报价、成本利润、中标概率或技术分补偿。

规则范围依赖一次有据人工解释确认；本系统没有宣称能自动证明任意自然语言条款与参数完全等价。随机、抽签、去极值、分段、基准价预取整等已识别未支持词样保守拒绝；受限schema拒绝任意脚本/表达式或额外口径。代表性真实条款仍需业务验收，合成原文不代替该结论。

## 验证边界

`tests/test_pricing_calculator.py`是独立手算及数值边界；`test_pricing_contracts.py`检查实际闭合契约；`test_pricing_integration.py`使用真实独立非owner PG、会话/CSRF与显式内存对象。原生OSS探针须单独显式开启，只新建、读回并删除本次自有的一个合成公式对象，检查远端I/O无idle-in-transaction，不操作既有对象或bucket设置。

本模块不调用模型，不启动Kafka进程，也不赋予任何提交/模型资格。自测不替代独立测试、架构、产品及用户评审、主API接线、浏览器任务或真实招标条款适用性验收。

## 候选02：金额单位词边界

候选01自查确认原文“万元”会被子串判断当作支持“元”。02曾试图修复词边界，但独立架构评审再次用“兆元”“韩元”真实HTTP请求证明仍会截掉未知前缀。02整体未通过；其冻结输入、对象写入和独立失败证据保留，不由后续修复改写。

对象I/O实现未因这一修复变化；原生OSS证据仍明确属于候选01的一对象探针，不将其写成02重跑通过。02新增受限真实PG的单位拒绝、合法万元、混用及先前错误状态反例，完整工程回归另行冻结。该修复不提供货币或单位自动转换，不扩展支持范围。

## 候选03：完整声明与可信原页

03使用正向完整声明语法：例如“金额单位元，币种CNY”“金额单位：万元，币种人民币”“以人民币元为单位”。声明值按整段token核对，只认识元、万元及显式CNY/人民币；未知词、未知倍率、外币、混用或歧义均不支持，不通过枚举黑名单剥掉前缀。币种选null仅允许原文没有明确币种声明，不能忽略原文的外币声明。

金额单位/币种支持字段须由所选完整证据块自身证明，且与公式方法证据属于同一文档、解析版本及物理页。跨页条款当前保守不支持；无关页的有效声明不能拼接为本公式的单位。服务器再读取该原页全部证据块，按解析顺序直接连接，不插入可把“韩”“元”分开的人工边界，核验原页全部声明一致。仅选择“元”单字或省略相邻未知前缀不能取得资格。语法不能证明任意自然语言的含义，人工对照完整条款的原有责任仍保留。

新登记准备、登记最终短事务和所有当前适用性检查均使用此守卫；非法输入在PUT前拒绝。模拟、保存和幂等写重放不得继续使用旧误配公式。已有模拟和已保存方案仍返回原冻结结果并提示当前不可用，不重算改写。对象读写与数据库分阶段边界不变，本轮不重复原生OSS探针；01探针只能证明当时对象IO范围。独立评审及代表性真实条款验收仍需另行完成。
