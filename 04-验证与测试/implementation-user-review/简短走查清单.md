# 实际界面简短走查清单

**状态：待界面启动，尚未执行，不作UI通过结论。** 用于T0及最小PDF闭环的用户视角走查；按[团队职责](../../00-项目管理/团队协作与质量准则.md)检查理解、负担、文件／状态误认和异常接续，不代替独立软件测试、架构验收或真人试用。

## 1. 执行前登记

记录工程提交／工作区摘要、启动地址、契约／PRD身份、浏览器及视口、服务配置和夹具身份。使用无敏感内容的代表性招标、正文V1、外部修改稿V2及补遗；准备两个独立关键问题和若干非阻断建议。记录采用真实适配器、显式测试适配器还是未配置，测试结果不能作为真实检测效果。

按阶段可执行的范围走查，未实现或无法启动的模块标“待实现／待执行及原因”，不填通过。浏览器截图、实际操作及可见反馈是本轮依据；后台事务、来源隔离、Kafka重放和模型精度由对应角色提供测试证据，不从页面推定。

## 2. 核心任务

先按任务做，不预先提示按钮位置；表中观察点用于事后核对，不变成产品额外表单或确认步骤。

| 编号 | 给执行者的任务 | 观察与记录 |
| --- | --- | --- |
| UI01 | 登录后，把现成招标与正文放进去，找到先处理什么 | 上传入口能否找到；是否被要求先建知识库、目录、模板或任务；批次进度与受理／检查完成是否分开；模型未配置时是否如实说明 |
| UI02 | 看懂一个关键风险，并核对招标和正文依据 | 是否可就地打开两侧原页、辨认文件版本；无法定位／缺失型问题是否说明范围；返回问题是否保留位置；是否被迫转去全局聊天 |
| UI03 | 处理第一项后，继续找影响提交资格的问题 | 对应U03：能否发现第二项关键阻断、区分普通建议；记录主动作推进和折叠入口的实际表现，不用提交最终被拦住替代发现过程 |
| UI04 | 取回修改依据，再找到实际投标正文 | 对应U01：按钮、文件详情、下载文件名能否区分评审报告／批注审阅稿／投标正文；是否绑定正确轮次；是否多出泛化确认；不能用静态示意图证明实际按钮合格 |
| UI05 | 在外部Word改好后，把新稿放回同一项目并复检 | 无需在线编辑器；新旧文件和评审身份清楚；采纳或“改好了”不直接显示解决；比较仅展示实际复检变化，旧轮次可回看 |
| UI06 | DOCX转换失败时，用自行导出的PDF继续 | 对应U02：原文件行持续显示原件已存／检查未完成；能否原处“上传此修改稿的PDF”，保留项目与改稿来源；无需重传招标或先进入编辑器；只给所选PDF结论，未核验Word不显示已获检查资格 |
| UI07 | 收到补遗后，弄清哪里变了并继续处理 | 旧报告过期与当前输入清楚；不覆写人工内容；未知范围不冒充已检查。对应U04的明确替代／局部变更／互相矛盾三组资料，观察是否回看原页、无依据时保留待核实 |
| UI08 | 完成提交前检查，登记确实提交的文件 | 确认后置且不重复聊天确认；非阻断建议和不能可靠估分不额外阻断；具体正文／轮次／时间清楚；系统登记不冒充交易平台成功；已有线下事实走有据补录，不伪装通过 |
| UI09 | 发现漏提的核心要求，补入后重新评审，再次提取 | “补充并确认条款”是否找得到；失败保留输入，成功后能辨认条款已确认但正文待复评；不二次确认；有效人工要求重提后保留、不重复；来源不明留待核验，有据结束义务留历史 |
| UI10 | 官方成绩出来后，登记能核实的内容并复盘 | 对应U05，待成绩模块具备后执行：技术分／仅综合分／主体冲突三组；复用提交身份，只核差异；未知不填零、预测不抄成官方分，待核验可保存；不为走查新增审批 |

章节编制和历史知识引用按对应模块交付另行走查；首批不要求进入这些页面。若当前界面尚不含UI10等模块，明确保留待执行，不据此虚构A1全范围已验收。

## 3. 穿插的异常与阅读检查

- 上传中断、短期链接过期：可接续已完成部分，不要求重传全部；文件已收到与解析失败分开显示。
- 模型不可用、单项失败：保留有效已完成范围；不显示零分、旧分或全通过；恢复入口明确，不无界重复启动。
- 刷新、重新登录、两人更改或旧任务迟到：恢复正确对象及版本；未确认操作不自动执行，旧卡失效保留输入，旧完成结果不覆盖新稿。记录可见行为，事务证明另交测试。
- 关闭可选检测：已有未解决关键风险仍可见、能处理；有效解决／有理由驳回后不再由该问题阻断，保留历史。
- 键盘及390px窄屏完成上传、原页、复检与核验；1100px附近阅读正文和来源，检查焦点返回、文字而非仅颜色、无整页横向溢出。内网环境核对PDF及中文资源实际加载，不以资源配置存在代替运行证据。

## 4. 单项记录与结论

每项记录：任务编号、实际输入及版本、执行方式（智能体浏览器走查／真人试用）、实际动作、观察到的文字／状态、截图或录屏定位、帮助／卡点、结果（符合／发现问题／待执行）、可复现问题与最小修正。真人试用另记参与者匿名标识及是否受到提示；没有实际测量不报点击数、耗时、完成率或满意度。

先把可复现问题报PM和产品负责人，涉及实现缺陷交开发、测试复验；不自行修改主规格降低预期。结论明确绑定所查实现与范围，区分“实际界面走查完成”“真人任务待观察”和“真实业务效果未验收”；此前设计通过不自动沿用为UI通过。
