# 本机基线失败分类

## 1. 证据范围和结论

输入为应用融合工作树的`workbench/.local/backend-baseline-local.log`、同名XML及`mypy-baseline.log`。这次pytest使用`--maxfail=20`，在18项失败、2项setup错误时停止；已有184 passed、200 skipped，**不是完整后端套件结果**。日志和运行环境属于本机证据，未提交的工作树不能当固定候选验收。

20个失败节点分类为：8项缺少固定输入并绑定原云绝对路径、8项POSIX私有权限语义不适用于Windows、1项创建符号链接权限不足、1项Windows隔离子进程环境缺陷、2项固定源码因CRLF转换导致摘要不符。前缀用例尚未暴露可确认的业务判定算法缺陷；环境或fixture失败不能解释为业务已经正确。

不得通过补空JSON、拿当前SQL替换固定SQL、改预期hash、吞掉权限检查或新增无条件skip来清绿。200项跳过的原因与剩余未执行测试应另行盘点，本记录不替这些测试给结论。前端148项测试、lint、typecheck和build的结果由G0运行报告维护，不纳入本表的后端通过数。

## 4. mypy六项诊断

全量mypy扫描131个源码文件，六项均为Windows类型环境没有的POSIX能力；它们不是可以单靠类型忽略解决的跨平台运行能力。

| 位置 | 缺失属性 | 运行含义与处理 |
| --- | --- | --- |
| `packages/uploads/journal.py:26` | `os.O_NOFOLLOW` | multipart孤儿候选日志依赖无跟随打开语义；Linux运行验证，原生Windows需等效安全打开方案 |
| `packages/uploads/journal.py:30` | `os.fchmod` | descriptor私有权限不可在Windows简单等同chmod；不删除安全步骤来消除类型错 |
| `packages/authoring/build.py:275` | `os.killpg` | LibreOffice超时路径的进程组回收是POSIX实现；Windows需独立进程树／Job Object设计，普通process.kill不自动等效 |
| `packages/authoring/build.py:275` | `signal.SIGKILL` | 同一超时回收路径；正常转换成功不覆盖这条反例 |
| `apps/api/object_transfer.py:275` | `os.O_NOFOLLOW` | 临时对象key日志同样依赖无跟随语义 |
| `apps/api/object_transfer.py:279` | `os.fchmod` | 同样依赖descriptor私有权限 |

目标API／Worker在Linux容器内运行时可采用对应POSIX能力，本机Windows负责开发与调度不要求移除这些边界。Linux类型门通过仍须目标容器真实执行；原生Windows完整上传／构建能力在尚无等效实现时保持未验收。

## 5. 最小修复及实际复验

最小反例使用同一个现有Python3.12运行时，不安装软件、不访问数据库和模型：

```python
subprocess.run([sys.executable, '-I', '-c', 'import asyncio'],
               env={'PATH': os.defpath}, capture_output=True)
# 本机返回1：WinError 10106，发生在 import _overlapped。
subprocess.run([sys.executable, '-I', '-c', 'import asyncio'],
               env={'PATH': os.defpath, 'SYSTEMROOT': os.environ['SYSTEMROOT']},
               capture_output=True)
# 本机返回0。
```

实际修改只在`qa/assistant_browser_fixture/safety.py`与`tests/test_assistant_browser_fixture.py`：共用的`process_environment()`默认仅PATH，Windows额外允许SYSTEMROOT；业务角色环境继续只提供各自DSN与必要fixture设置。测试子进程使用`-I -X utf8`及`encoding='utf-8'`，不复制整个父环境、代理或密钥。新用例通过真实子进程检查asyncio导入、隔离开关、UTF8中文及OWNER_DATABASE_DSN／DEEPSEEK_API_KEY／AWS_SECRET_ACCESS_KEY／PYTHONPATH不泄漏。

运行`pytest tests/test_assistant_browser_fixture.py -q -p no:cacheprovider --tb=no`得到**9 passed、7 failed**：原网络守卫、新真实子进程及POSIX环境白名单用例通过，余下七项全部在POSIX私有目录构造处失败，与第2节一致。测试需要本机回环初始化能力；真实HTTP和非回环连接仍由fixture守卫拒绝。两文件ruff check与ruff format --check通过。未修改LocalObjects权限检查、未新增skip、未伪造固定输入；不将这次局部修复称为完整本机基线已通过。

另对`safety.py`运行bandit通过；单独mypy检查该QA文件报告原有`HTTPTransport.handle_request`和`AsyncHTTPTransport.handle_async_request`两处方法赋值的`method-assign`，位置不在本次修改区。全量131源码mypy并未覆盖此QA文件；本次没有新增忽略来遮掉这两项，也没有宣称该文件mypy通过。
