# CPU 解析替代路线静态依赖观察

结论：候选 03 的保守 CPU 替代路线可用于开发与其明确标记的部分读取范围，不阻塞这些范围继续集成。该判断不替代 Docling／PaddleOCR 目标资格、真实资料精度、视觉语义或生产隔离验收。

观察输入为 `parsing-development-checks/candidate-03/candidate.json`，SHA256 `2c94690cabd1a29fdf461d2879b8000d527fa404d3b1249d4082d5ba66e9309f`。核对当前十二份源摘要、阅读 README、服务端及 HTTP 端口，并检查 core 中资源限制、可见性降级及缺口传播分支；这不是重新独立执行 OCR。

服务 loopback、Bearer、禁访问日志／文档；HTTP 适配器 trust_env=false、禁止重定向，绑定原件 SHA、解析与配置身份，核页顺序、尺寸、块摘要和 bbox。OCR 在计算阶段，发布由 Worker 的受限事务执行。CPU profile、六类模型／配置／依赖与字体等身份均单独声明，不能沿用目标解析器资格。对不可核验字层、遮挡、裁剪、扫描和图形保留 partial／缺口，quality_benchmark 明确 not_business_validated；上层不得把该 partial 变成“正式完整评分输入已读完”。
