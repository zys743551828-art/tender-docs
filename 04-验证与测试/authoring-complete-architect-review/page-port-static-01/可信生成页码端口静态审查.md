# 可信生成页码端口静态审查

结论：所读具体实现没有新增静态阻塞，可进入受控的独立端口真实转换测试；本结论不授予转换对应、原上传Word或完整编制资格。

输入 [candidate.json](../../authoring-complete-development-checks/page-port-static-01/candidate.json)，SHA256 `ddd11c50e4191b865b7e423bf895bd620ceb42a97c4927167112f60ecc755c86`；5自有源和14依赖在执行前后全部匹配，另核3份外部协议/Word03候选与public profile。输入和独立证据摘要见 [review-record.json](review-record.json)。

已核对的信任边界：

- generated_verification.verify不是相信manifest或trusted标志：它以当前固定生成器从完整snapshot重新生成，逐字节比较DOCX，随后核全部固定ZIP部件、内容类型、关系、XML命名空间/元素/属性和页脚规范PAGE子结构。重算manifest不能让篡改字节通过。动态域只允许一个footer直接段落内的`fldSimple instr=" PAGE "`，固定一个run和缓存1；无其他域标签、拆run指令、嵌套域、外链或未知部件。
- generator/profile固定生成器、内容/结构schema、模板/结构依赖、校验器和adapter摘要；Word03 renderer/inspection/runner三源码逐字节固定，实际执行前还通过原build_profile比较image、资源、字体、options与实际资产身份。新端口复用原只读挂载/非root/无网/资源限额/输出上限/超时/清理helper，没有另增宿主soffice或任意命令入口。
- 同一生成PAGE字节走外来Word检查仍conversion_eligible=false，不给上传原件放宽拒域规则。端口无HTTP/DB/对象/模型参数；snapshot是否真实冻结、API最终引用资格和Worker发布fence必须由后续业务接线另验，不能由本纯端口自行证明。
- inspect_pdf实际用PDFium页数、A4/rotation和逐字符bbox分离页眉/页脚/主体。每页必须匹配固定header/footer与1..N页码；主体数字保留，完整归一化文字及列表编号比对。缺口使转换partial，不能仅因进程返回0升级complete；异常失败不返回可用PDF。清理失败会降级已生成结果。此处文字/几何对应不等于全部视觉或语义质量。

独立执行：25项通过，包含原20项纯机制测试及5项自有真实PDFium读取测试。自有夹具是明确的两页ASCII合成PDF，不是LO产物：正确Body1/Body2与页码1/2无缺口；第二页仍1、正文数字2丢失、页码在正文区、额外正文文字分别出现对应缺口。见 [test_geometry.py](test_geometry.py)、[JUnit](independent-junit.xml)。整个进程硬禁止启动subprocess、网络连接和DB连接，未执行新Docker、未访问provider或业务数据库。

真实验收仍须覆盖：单页/多页/中文、真实列表编号和长页眉页脚、正文与页码同值数字、PAGE实际刷新、缺字体/缺字、低边距重叠、超时与清理失败；实际生成DOCX与PDF两端SHA/profile/renderer/font/options绑定；API真实冻结快照→无连接生成/转换→Worker同fence最终来源重核、取消/迟到拒绝。本候选没有main/engine/API业务接线，不把本静审或合成PDF当这些路径已通过。TOC当前仍为静态文本目录，章节实际页范围unknown；不以页码成功替代RICH、原件Word↔PDF资格或正式评分。
