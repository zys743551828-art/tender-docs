# 接口与任务实现规约

[OpenAPI](openapi.json)是接口形状主记录，[协议Schema](protocol.schema.json)是对象定义主记录。本规约固定调用顺序、事务边界、Kafka处理分支和前端对接方式。所有处理器名称表示待实现入口，不表示应用代码已存在。

上传分片／重授权、逻辑文件head、规则批量确认及人工漏提更正、事实撤回、逐行check_status、报价版本及研究预览／恢复入口按[保留功能实现规约](保留功能实现规约.md)调用。数据类型从OpenAPI生成，不以旧接口的ETag、分片ETag数组或确认枚举代替目标定义。

## 1. HTTP通用协议

正式目标前缀为`/api/v1`，采用同源Cookie会话；不在URL传token。命令写入携带X-CSRF-Token和Idempotency-Key。资源条件写入携带强ETag，例如`"draft:<uuid>:17"`；If-Match中的类型、ID、revision必须和目标资源一致。禁止用列表ETag保存其中一个对象。读取返回对象ETag，异步受理同时返回operation_url与具体资源引用。

| 场景 | 返回 | 必须包含 |
| --- | --- | --- |
| 新建同步资源 | 201 | Location、对象、ETag |
| 查询／条件更新成功 | 200 | 对象、ETag；Cache-Control: private,no-store用于敏感投影 |
| 接受后台工作 | 202 | operation、resource_kind、resource_id、disposition、operation_url |
| 退出 | 204 | 清除Cookie，服务端会话撤销 |
| 缺条件头 | 428 | 目标对象和重新读取入口 |
| 修订不符 | 412 | expected/current revision，不返回敏感原文 |
| 资料冲突／gate阻断 | 409 | code、blockers和修复入口 |
| 格式／参数／容量 | 415／422／413 | 字段或文件级错误，不启动模型 |
| 暂时限流／依赖失败 | 429／503 | Retry-After与retryable；前端只重试可重试请求 |

幂等重放返回第一次提交的业务结果，并标`Idempotent-Replayed: true`；对象之后又变化时，响应保留原命令结果，同时给最新资源查询URL，不能伪装成第一次结果又重新生效。

SSE连接采用Fetch流式客户端以便发送Last-Event-ID与处理401／410。响应text/event-stream，反向代理关闭缓冲，15秒keepalive。关键事件包含stream_id、seq、event_type、object_ref和revision。事件保留起始7天；过期返回410 RESET_REQUIRED，客户端先重取快照再从新游标连接。临时token不在承诺重放范围。

## 2. 必须闭合的调用序列

### 2.1 首次上传到评审

1. 登录取得会话Cookie、CSRF与成员对象。
2. POST /bids：只需项目名；工程／标段／轮次可后补。后台按公司默认主体创建工程与首轮身份，返回bid和settings。
3. 创建upload-batch→按每个文件取得upload授权→直传字节→complete；upload状态先verifying，不能显示“已入库”。
4. 查询批次文件核验结果，所选文件全部verified后commit，携带bid ETag；资料角色冲突先处理，不用文件名猜测。
5. 自动评审开启时commit返回安排的operation或latest pending意图；关闭时页面显示明确“开始评审”。人工按钮与助手均RequestReview，冻结、稳定as_of及三种摘要统一执行[详细设计第3.2节](../AI投标工作台详细技术设计.md#32-输入修订与摘要)。
6. GET review、matrix、findings与operation分别读取覆盖、风险和执行状态；证据通过GET evidence查看原件及physical_page。
7. 用户处理问题后上传新正文或在编辑器构建新正文，形成新review；旧问题按新输入复检，不因卡片关闭视为解决。

### 2.2 保存、生成与复评

GET draft返回整体revision、目录及各节当前revision；编辑节正文按需读取，避免首次下载全部大JSON。PATCH draft将当前脏节与各base_revision一并提交。页面只在保存ACK后清除已发送内容的脏状态；请求期间的新改动仍保持脏。

点击生成先flush保存队列，取得draft_revision，再POST builds，明确template_version和formats。默认follow_up由项目auto_review决定，人工可显式请求review。轮询或SSE读取build各格式状态，只有成功PDF才能进入对应评审；DOCX成功不掩盖PDF失败。

### 2.3 标准提交与线下补录

GET gate给阻断列表；POST submissions携带最新bid ETag、正文版本和review，在服务器重新计算条件。模型未校准或分数隐藏不阻断；不允许报告／批注稿通过标准入口。线下事实补录用submission-facts，必须提供实际文件和证据，独立显示“未经过完整闸门”。

结果登记关联有效submission，值与满分均Decimal字符串，可为未知。正式配对必须经来源核验；上传结果截图不等于已经成为合格训练标签。

### 2.4 RAG问答与AI补丁

公开POST retrievals仅接受界面context、query、bid和limit；purpose、allowlist、实验组和模型profile由服务端选择。聊天读取引用结果生成解释，正式写入以可预览action返回。确认action前重读section和source heads；过期提案失败，不能转为“强制覆盖”。

## 3. Kafka topic、顺序与运行配置

配置主记录见[execution-policy.json](execution-policy.json)。任务topic按document、review、export、research分开，分区key为operation_id:step_key。领域事件按bid key发到domain.events，各职责用独立group。相同group的实例竞争消息；不要为每个实例随机group，否则每份任务会执行多次。

起始配置：任务topic6分区、retention7天、cleanup.policy=delete；领域事件retention14天；死信retention30天。生产replication.factor=3、min.insync.replicas=2；开发单节点使用1／1并明确隔离配置。消息上限256KiB，应用信封目标≤32KiB，文件与大结果只用对象引用。retention是消息日志窗口，不是业务档案周期。

Producer enable.idempotence=true、acks=all、delivery.timeout.ms=120000、request.timeout.ms=30000。Outbox租约30秒，投递进程每10秒续租，直到成功回执或终止；没有续租时不能用30秒claim去等待120秒后认为仍独占。租约竞争可能重复发布，领域event_id和收据负责去重。

Consumer disable auto commit/store，max.poll.interval.ms起始300000，poll循环每≤1秒运行；处理放有界执行池。每分区最多一个在途，派发后pause，worker结束后由poll线程处理完成队列并commit offset+1。只有poll线程操作consumer，计算线程不调用commit／pause／resume。未完成消息在重分配后可重放。

## 4. Outbox投递算法

[worker-functions.sql](worker-functions.sql)提供claim、ack和续租辅助函数。主循环：

~~~text
每次批量最多100条：
  事务A：claim_outbox(token)，提交，释放数据库锁
  对每条：使用稳定outbox.id作为event_id，按契约构造消息并produce
  poll producer回调，期间为未结束claim续租
  成功回调：事务B以id＋claim_token调用ack_outbox，提交
  可恢复失败：释放当前claim或等租约到期，保持published_at为空
  不合法信封：持久隔离并告警，不能把published_at填成成功
~~~

PG提交后尚未publish可续投；Kafka成功但ack前崩溃会重复publish，消费者按事件与阶段收据消除重复副作用。Producer幂等只保证其协议范围内重试，不能消除Outbox进程重启后所有重复。

## 5. 阶段领取、执行与提交

阶段计划写operation_steps，明确每个必需step及依赖，缺一不能汇总。任务message.generation对应dispatch_generation；fence是同一阶段的执行权，每次接管单调增加，二者不混用。

~~~text
acquire(message):
  校验信封、handler_version和message大小
  事务：调用lock_worker_bid(bid_id)，再锁operation、step计划与收据
    operation终态／取消中：确认无新执行权，返回SKIP_TERMINAL
    message.generation < plan.generation：返回SKIP_OBSOLETE
    message.generation > plan.generation：持久隔离并告警，禁止猜测新代次
    依赖未完成：写短期到期Outbox接管，返回DURABLE_DEFER
    已成功收据：返回REUSE_RESULT
    存在有效执行租约：返回OWNED_ELSEWHERE，由已有PG执行与对账负责接管
    无收据或租约失效：提升fence，记录owner_token、attempt_count、120秒lease
  提交后执行远程计算，每30秒续租；续租失败则停止发布权

finish(result,expected_fence):
  先上传受控产物并核对digest
  事务：相同锁序，先lock_worker_bid，再重查state、fence、generation、来源与输入
    已成功effect：返回原产物
    取消／失效fence：不登记有效结果；临时对象交延迟清理
    有效：写领域产物、step收据、effect、后继Outbox、审计与SSE
    所有必需阶段终态时，分别确定core_coverage、score_mode和operation状态
  事务提交后通知poll线程允许提交该partition的offset+1
~~~

普通执行使用WORKER_DATABASE_DSN对应tender_worker；研究样本执行使用RESEARCH_WORKER_DATABASE_DSN对应tender_research_worker，不能为了联调换初始化owner。两角色均走上述锁序。研究finish同事务写effect／step收据、research_run_items、审计和stream_events，样本研究产物不发布业务预测或model_routes。研究汇总调度只锁run更新计数并写Outbox，逐样本取消／重试另起bid事务，避免run→bid反向锁。

研究模型调用在领取成功后的短事务调用reserve_research_call：参数含run、operation、step、input_digest、generation、fence、owner、调用ID、logical key、attempt、请求/profile摘要和预留金额。函数重验执行租约与run归属，锁run后原子扣预留并插入model_calls；INSERT失败整笔回滚。返回call_id、new_reservation、state：只有new_reservation=true且本事务提交成功可发送该次请求；false仅复用查询／对账原调用，不能重发付费请求。原reserved／unknown可能已经计费，失联后先用供应商幂等键或账单对账；需要新请求须新attempt、重新预留并共享最多3次上限。run取消/暂停、旧generation/fence、过期lease均拒绝新的预留。远程请求只在事务外执行，不把数据库锁持到模型响应。此入口是用途受限的账本事务，不替代远程供应商自身幂等能力。

Kafka位点提交失败不回滚已经提交的领域结果；下一消费者重放读取收据。OWNED_ELSEWHERE只有PG已有持久owner与有限期lease时才能ACK原消息；对账必须接管过期未完成步骤，不能依赖内存里的那条消息还在。

## 6. 重试、死信、取消与失联

| 分支 | 持久动作 | 何时允许提交offset |
| --- | --- | --- |
| 网络暂时错误／429 | 记录失败，预算内提升dispatch_generation并写available_at | 重试Outbox提交后 |
| 输出Schema错误 | 相同logical_call_key内定向修复，最多累计3次模型请求 | 得到合法结果或已可靠接管失败后 |
| 原件非法／未知handler | 明确failed或隔离，写dead-letter Outbox与定位码 | 失败记录和死信投递意图提交后 |
| worker失联 | 对账锁step，废止旧fence并发布下一generation | 对账不伪造业务成功；重放按收据处理 |
| 用户取消 | 锁operation写cancel_requested，禁止新领取／发布，废止执行租约 | 消费者确认取消状态后可跳过；取消收尾再记cancelled |
| 成功与取消并发 | 同一operation锁确定先后 | 成功先提交则返回既有成功，取消先提交则迟到产物无发布权 |

退避起始为2、8、30秒加0—20%抖动，同时尊重Retry-After和总截止时间；不在Kafka poll线程sleep。单次逻辑模型调用最多3个reserved请求，结构修复、网络重试、进程接管共用预算，不把每层3次相乘。未知是否计费的请求标unknown并占用预算。replicate1／2／3是三次独立判断，各有自己的logical_call_key，不是故障重试。

失联扫描每30秒批量≤100条，用SKIP LOCKED。数据库now与lease_until判断，不依赖客户端时钟。人工取消终态表示系统已停止后续发布，不承诺外部模型已经停止计费。死信重放创建关联原操作的新operation，显示范围和预算，不能重放已生效人工决定。

## 7. 前端实现与组件验收

页面按功能拆模块，Query缓存只保存服务器事实；编辑器和上传维护局部过程状态。API类型由OpenAPI生成，统一错误中间件；412弹差异面板，409展示阻断入口，401保留未提交输入并要求重新登录后再确认。

| 页面 | 首次必取数据 | 后续订阅／局部加载 | 完成条件 |
| --- | --- | --- | --- |
| 项目列表 | BidPage＋筛选 | 项目摘要事件失效对应query | 快速进入主要下一步，归档筛选独立 |
| 资料 | MaterialView＋UploadBatchView | 各upload.operation，证据按需 | 可恢复上传与明确批次结束，不漏补遗 |
| 风险结果 | ReviewView＋FindingPage＋MatrixView | score独立就绪，证据抽屉懒加载 | coverage失败不显示0风险；一个主要动作 |
| 章节 | DraftView＋目标SectionView | 单节内容，保存ACK，AI补丁预览 | 持续输入时保存串行；冲突可恢复；不丢脏内容 |
| 版本导出 | BuildView＋ArtifactView | 每格式状态及policy revision | 保存失败不生成旧稿，格式失败单列 |
| 提交结果 | GateView＋SubmissionView＋OutcomeView | 核验与更正事件 | 标准／线下补录明确，未知结果不当未中标 |
| 知识 | KnowledgePage＋KnowledgeView | source impact与版本 | 停用立即阻止新应用，历史引用保留提示 |

组件必须覆盖loading／empty／partial／failed／stale／ready及键盘路径。禁止在空响应默认填0、默认全覆盖或绿色通过。关闭助手不卸载editor；后台完成只出现可进入通知，不抢当前路由。390px宽可上传、查看证据、复评及核验，详细版式引用视觉主记录。
