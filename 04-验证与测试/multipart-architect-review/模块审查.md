# 分片上传模块架构审查

结论：冻结候选的分片模块机制通过，未发现阻塞模块集中接线的问题。候选注明 `main_wired=false`，本结论不代表主路由、浏览器并发／续传或真实云端独立验收已经完成。

候选 SHA256 `8fa3b069cf40b56f82b2bf09d13734eb400a9214b921baa50fa3c6d8781bec0a`，八份当前源与冻结副本均逐项核对，执行前后保持一致。状态协议以 `twb-multipart/v1:` 和固定 JSON 字段区分初始化预留、未知、可用、完成中、完成及终止；不会把普通原生 UploadId 误解释成内部状态。provider ID 不进入 grant 或私有候选登记。

初始化先持久预留，只有首次处理器持有 nonce 才尝试原生 init；响应未知保持稳定上传身份，重放不重建或列桶找会话。完成以命令身份冻结阶段，网络在短事务外，通过精确 HEAD、全量 GET、尺寸与 SHA 对账；同键并发最终只产生一个 verify operation。状态 CAS 不能撤销败方已经发生的远端写，完整 SHA 和现有 verify Worker 的再次实际字节核验共同阻止其成为正式文件。分片模块本身不直接发布 document_version。

同源 PUT 经真实 Cookie 会话、Origin、CSRF 及绑定方法、上传、项目、逻辑 key、片号、大小、修订、整文件摘要和到期的 HMAC 授权；接收前、网络前与网络后分别核验授权，拒绝压缩与不符尺寸。刷新、终止及完成使用短 bid／upload 事务；远端请求不持该事务。并发限制诚实限定为每进程四个，不声称全局限流。

架构师在全新 PostgreSQL 与非 owner API／Worker 下独立执行九项既有用例：含实际 ASGI、持久命令、同键并发、响应丢失、败方远端写入、未知初始化与外会话拒绝。对象端口为显式内存 OSS API 替身，仍执行原生适配包装与真实 Worker 核验机制；没有真实 OSS 请求、桶配置变更或收费调用。见 `candidate01-independent-result.json`、JUnit 与 `probe_candidate01.py`。首次运行八过一失败源于探针构造 OSS 异常缺失参数，修正仅涉及探针，原失败 JUnit 保留为 `fixture-exception-construction-junit.xml`，不归因产品。

开发提供的六项真实 PG／OSS 用例仍属开发证据。集中接线应继续保证 complete 的 If-Match／幂等摘要、匿名与 CSRF 拒绝、真实文件版本 CAS、浏览器最多四并发／恢复及所有实际路由契约一致；该边界由对应集成候选及独立 QA 验收。查询票据须继续排除访问日志；孤儿候选登记不是删除授权。S3 multipart 不在本范围。
