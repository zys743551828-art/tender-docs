只在明确全新的预览环境创建私有管理员口令文件。以下命令交互输入，不把口令写进参数或输出；文件已存在会拒绝覆盖。owner/checks口令由启动器首次生成，已有口令不重置。


## 运行与恢复边界

API/Worker/协调器须分别装配受控依赖。新预测 API 宿主使用 package_prediction_pipeline.composition.api；协调器使用 composition.coordinator；Worker使用 package_prediction_tasks.composition.compute。这些是现有任务执行器的装配接口，不是新长期服务的自动启动许可。缺依赖返回不可用，默认不调用真实模型。

## Word转换安装与验收

当前选型为官方预构建Gotenberg 8.39.0，架构取舍见[成熟组件ADR](工作台实现架构.md#adrword-转换采用成熟组件与薄适配)。旧Word03冻结源码、身份与结果保留，[来源核查](../04-验证与测试/Word03来源与复现核查.md)仅用于旧基线追溯；不再要求用户寻找丢失的旧镜像才能推进新版。

从应用`workbench`目录、已安装工作台锁定依赖的Python环境运行。Docker Desktop Linux或Linux本地daemon须可用；当前发布验证平台为linux/amd64。先获取官方既定版本，不构建Word镜像：

```sh
docker pull --platform linux/amd64 gotenberg/gotenberg:8.39.0-libreoffice@sha256:298c3989049baf530afe7137b64374c22810bb863ef1ed91d256e33f335af161
python deploy/word_prebuilt.py describe
python deploy/word_prebuilt.py profile --lane external --profile <新私有目录>/external.json --receipt <新私有目录>/profile-resources.json
python deploy/word_prebuilt.py convert --profile <新私有目录>/external.json --source <合成样本.docx> --output <新私有目录>/output.pdf --report <新私有目录>/conversion.json --receipt <新私有目录>/conversion-resources.json
```

所有输出路径必须未存在；目录由操作者建立并限制访问。`profile`实际检查本地镜像身份；转换时等待健康就绪，按次创建非root、只读根、无外网、限额容器，结束精确回收；不运行常驻公开转换服务、不修改全局Docker配置。容器内部curl访问其自身loopback3000，无宿主映射端口。`convert`的退出码只反映转换执行，必须另读`coverage/gaps`：HTTP200与PDF可下载不等于复杂布局已合格。宏、外链及外来动态域仍拒绝；字体替代和不支持布局保持缺口。

API/Worker外来Word入口读取`WORD_RENDER_PROFILE_PATH`。受控PAGE/RICH分别用同一`profile`命令的`--lane page|rich`生成各自新文件，并配置`AUTHORING_GENERATED_RENDER_PROFILE_PATH`、`AUTHORING_RICH_RENDER_PROFILE_PATH`；普通`convert`只接收external profile。私有配置由操作者按启动角色提供，不通过请求体选择profile，不覆盖旧Word03 profile。新协议结果不能冒称旧字节身份。

本轮API/Worker真链使用宿主Python进程调用本地Docker；Word组件可在具备受支持本地daemon的Windows/Linux宿主运行。现有full Compose没有装配Word profile/daemon入口，`check_compose.py`与`fusion_full_control.py`还明确拒绝挂载docker.sock，本轮没有放宽该约束。因此上述宿主模式验证不能写成全容器部署已经接通Word；容器化完整环境的受限转换执行入口仍需单独设计与验收。

一次性真实PG/API/Worker/S3组合验证入口为：

```sh
python deploy/word_prebuilt_acceptance.py --report-dir <已存在父目录中的新报告目录>
```

此工具要求预先具备代码常量中固定的PG17、Seaweed/S3及Gotenberg镜像，本身不build/pull。它创建新库、独立非owner角色和私有临时对象存储，采用合成DOCX且不调用模型；成功、失败、取消均核对本轮资源回收。它直接驱动outbox/fence而非Kafka broker，不能作为Kafka验收。Windows原生测试通过私有S3签名传输合成字节，不证明Linux产品同源分片上传已通过；产品同源上传契约不变。最终PDF、源件、脱敏摘要与资源回执位于新报告目录。

已测CLI三项（中文成功、复杂布局保留partial、外来域拒绝）、真实PG/S3/API/Worker链一项和PAGE样本通过；RICH合成两页样本最终complete、无gaps，见[实际原件与PDF](../04-验证与测试/Word03来源与复现核查.md#新预构建方案实际验收)。转换合格与默认解析器覆盖度分别判断，本轮原生主链的解析仍为partial，不能把转换complete改写成整份资料已解析完整。真实中文标书/生产环境及业务人员签收尚未完成。
