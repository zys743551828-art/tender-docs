# HistoricalInput application candidate 01

This is an appended, current-created retrospective input authority. It is not an old review, online prediction, StageA real-data opening, trained-model qualification or paid execution. Frozen proof02 and StageA remain unchanged.

The actual router is `apps.api.historical_input_routes.router`; the independent actual extension is `packages.model_governance.historical_input_contracts.extend_openapi`. Four operations: capabilities; submission input context with exact readable version names/material choices; create input; read immutable input/current qualification. Shared main/live wiring is not included in this candidate.

Create requires authenticated session, CSRF, idempotency key and current input-context strong If-Match. The body has only submission, historical subject authority, exact claim/material IDs, rule set and reason. The server derives actual body, original submitted_at, method, current decisions and current-created freeze. Clients cannot supply old review, arbitrary prompt, old created time, verified flag or real/model qualification.

Every exact body/tender/supplement version requires independently proved content_existed and known_to_bidder at or before original submission; tender/supplement also need effective coverage. Published is not known_to_bidder. Current proof heads, actual original/parse/page/digest, latest parse, complete ancestor heads and current publication are checked again. Original upload/obtained/source known times remain untouched; only the explicit historical branch interprets independently proved old facts. Current known/head windows must still be no later than the current freeze/current execution. Missing evidence or ambiguous purpose fails closed.

All necessary scoring rules must belong to the explicit historical material snapshot, and their exact source evidence must be from selected tender/supplement. The initial supported method sends the entire complete body for each rule, including every physical page and body evidence block; it does not send top-k, proof raw text, label documents, chat or other judgment outputs. Exact physical pages must be 1..page_count. Unsupported drawings/BOQ/external facts/visual observations and over-capacity full inputs are refused. A material snapshot may also contain its body reference; it does not enter the tender/supplement requirement set, and actual scoring body remains independently fixed to the original submission.

The API captures in an RC/group/bid/graph transaction, closes it, builds/stages clean objects, then recaptures and compares the whole frozen identity in a new short transaction before registering objects/typed maps and calling SQL seal. No SQL locks are held across object PUT/GET. Reads check actual object SHA/size outside SQL and recheck current authority afterward. Old stale results remain readable; replay never reauthorizes changed proof/parse/head. SQL seals prevent late child append with the same scope lock. Canonical parse UUID5 and canonical package digest construction use the shared API helpers; the SQL authority compares complete typed evidence and reconstructed JSON payload, and future execution rechecks canonical package digest. SQL does not claim to reimplement Python canonical JSON/UUID5.
