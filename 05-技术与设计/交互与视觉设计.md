## 2. 视觉基础

默认使用浅色工作界面：近白色外框、白色内容面、细灰分隔、蓝色主动作、浅色状态标签，优先接近公开产品图的密度。深色模式作为同一组件体系的次级适配，不让系统主题改变首轮视觉核对基准。

| 强调色 | #155EEF；悬停#004EEB；选中浅底#EFF4FF |
| 页面／侧栏／内容底 | #F8FAFC／#FAFAFA／#FFFFFF |

每个页面一个主要实心按钮；当前输入有缺口时优先补缺／恢复，不能仍提示处理过期稿中的问题。次要操作白底描边，危险动作只在对应对象附近出现。正文链接和章节名可用蓝色；整段内容不全染蓝。紧凑日期与数字对齐，不把技术校验值放进日常表格。

## 3. 全局框架与导航

全局列表页侧栏目标宽216px，顶部显示产品与工作区，底部为帮助、通知和账号。“投标工作”保留投标项目、历史项目、企业知识三个常用入口；“工作平台”承接AI助手、任务、资料库和业务复盘，内容顺序依PRD第3.1节。企业知识入口指向资料库中的同一条目，不复制内容。进入项目时全局侧栏可收成64px图标栏，旁边显示184px项目菜单；展开状态在个人浏览器记忆，不改变业务对象。

项目入口落点、主动作顺序和自动评审归并以PRD第3.5、3.7及7.2节为准；显式历史链接不被最近位置覆盖。

主内容顶部为面包屑、项目名／标段／轮次、截止与当前版本，右侧放主要动作。项目菜单依次为概览、招标资料、响应矩阵、章节编制、评审与评分、版本与导出、提交与结果；参考与事实、报价、设置在辅助区。不是在每一页重新列出完整流程向导。

下列为全新前端的目标路由，按新系统入口实现，不能当作当前应用已经存在：

| 页面 | 目标路由 |
| --- | --- |
| 投标项目／历史项目 | /projects、/history |
| AI助手／任务 | /assistant、/tasks |
| 资料库及其企业知识 | /library、/library/knowledge |
| 项目概览／资料包／矩阵 | /projects/:id/overview、/materials、/matrix（后两项接相同项目前缀） |
| 章节编制／版本／评审 | /projects/:id/outline、/versions、/review（后两项接相同项目前缀） |
| 提交与结果 | /projects/:id/submit |

新系统内部历史对象与深链接必须打开所指对象及版本，不能把历史报告链接重定向成没有上下文的空白首页；不承接旧app路由兼容或迁移。

## 4. 投标项目与新建

页面从上到下为标题与“新建投标”、当前工作摘要、视图和筛选、项目表格。摘要只表达即将截止、待处理否决风险、等待复核、资料有更新，点击可筛表；不展示销售额或无分母的中标率。

表格默认列为项目／标段、阶段、当前状态、截止、未处理关键风险、当前稿件、最近更新与行菜单。技术分只在用户选择该列且资格与显示开关允许时出现。过滤条包含在办／全部、阶段、工程类型、截止、资料状态，允许隐藏列并保留个人视图。跨页操作后恢复筛选与滚动。

已有招标和完整正文时，拖入后直接按自动开始设置评审，完成直达风险与结果，不强制走目录或模板设置。新建编制项目采用可保存的资料包流程：先输入名称并上传，再集中处理身份与文档用途，最后显示已收资料及“进入工作区”。不强制填写完整项目表单。后台解析受理后允许离开。已有正文可直接评审；只有招标可进入章节准备，不伪造完整合规结果。

## 5. 项目概览与资料包

概览保留项目身份和一条主要下一步；资料完整性、正在执行的任务、未处理关键风险及最近版本分区显示，不把“执行成功”当“可登记提交”。用户可直接跳进章节、矩阵或评审，助手也可给对应打开按钮。

招标资料采用文件表格和顶部上传动作。文档角色、版本、生效关系、解析质量、原页和引用范围在详情中展示。补遗到达显示影响抽屉：变更条款、影响章节、旧评审、未定位范围和核对动作。人工改写的章节只标待核对，不自动替换。

条款重建或重新生成目录先出候选差异；正文、编写计划和人工关联都在影响预览中可见。用户可以逐项接受，取消保持现状。未知的补遗先后关系不按文件名或上传顺序推断。

## 6. 章节编制

默认是树形章节表，列为多选框、标题、类型、编写状态、关联要求、页数预算和待办。章节展开使用缩进和细层级线。已保存、待补事实、修改待确认、待复检等是编写状态，另显示最近评审身份。

点击标题打开章节详情。左侧约三分之一放标题、类型、页数预算、编写计划、对应要求和重点参考；右侧约三分之二放正文编辑器，顶部为上一章／下一章、查看来源、生成建议。宽度不足时属性可折叠，正文始终有足够阅读宽度。

正文提供标题、段落、列表、表格、图片、撤销与重做。选中文本出现解释、改写、精简、扩写、补依据；选区操作只产生候选差异。变化用“新增／修改／移动／复制／删除”文字及颜色表达，逐项接受或拒绝；确认应用后显示保存状态和可撤销修订。删除、重建和批量替换必须显示影响范围。

编写计划、要求引用与参考文档分开，不让写作提示成为招标规则。新增关联不能表示正文已满足，删除关联不能把要求从响应矩阵抹掉。页数预算不足给提示，实际合规以导出PDF及原要求为准。

## 7. 响应矩阵与评审

响应矩阵的主要列是要求摘录、类型、生效来源及原页、对应章节、判定、人工状态和动作。要求可按层级展开，固定表头、搜索和筛选。点击章节进入正文；点原页打开来源；选中行可问助手或建立对应章节的建议任务。颜色类别必须配文字。

旁侧来源视图高亮真实原页与摘录，可在招标要求和正文响应之间切换。没有找到响应展示检查范围；工具失败显示失败。全表和当前筛选导出范围明确，不能把隐藏行当不存在。

覆盖详情分别呈现来源已读范围、核心条款提取范围与已知缺口、已识别核心规则核对、评分分值覆盖，并另列人工确认；不把几项合成一个完成百分比。标“已识别核心规则核对10/10”，不可标为“原文规则100%无遗漏”。真实检测质量无标注证据时显示待验证。关闭可选检测后已有未处理关键风险继续可见、可点开处理，并写明先前发现／本轮未运行，不能留下看不见却阻断的提交错误。业务口径以PRD第7.3—7.4节为准。

评审与评分页分“关键问题／响应覆盖／评分项／完整报告”。风险行可打开原文、要求修改或复核；评分项能看完整章节输入、覆盖和判断依据。关闭预测分数时隐藏预测数字和派生分差，仍可看缺口；正式成绩登记字段正常显示。总分、区间和模型资格按PRD，不以美化卡片省略拒绝估分原因。

### 7.1 默认评审结果：简洁结论与下一步

现成稿上传后的默认结果保持简单：一句关键结论、当前稿及依据是否更新、关键风险、评分可用性和一个主要下一步。其余待办折叠，原文、全部问题、矩阵和完整报告可直接打开；用户无需先浏览全部功能菜单。可选报价和检测依项目开关呈现，不为未使用模块留下必填步骤。

结果下方直接显示简短AI输入区，复用项目主会话，可用一句话发起查找、解释或修改建议。进入章节工作区沿用当前问题和引用，返回保留位置与进度；上传外部Word改稿也可接续同一复检。输入区和按钮不出现开发、训练或任务配置术语。

## 8. 就地AI助手

评审结果页保留直接可见的简短输入区，每页右下另提供蓝色AI入口；打开后停靠右侧，目标宽360px、可调320—480px。支持收起、历史会话、新会话和全屏。收起不取消任务，切页仍保留原任务对象；当前页面变化只改变新的操作上下文，不搬移旧会话和确认卡。

顶栏显示项目／章节和任务用途。输入区固定在面板底部，“+”可上传和选来源，“@”带入有身份的对象，常用建议为“解释本条要求”“完善这段措施”“检查遗漏”。正式评分入口显示固定输入范围，不能通过普通聊天来源选择扩大。

回复优先给摘要、可点来源及具体动作；长任务显示可展开的实际阶段，完成后给回写对象的打开按钮。导航、章节修改与正式决定使用不同卡片，按钮说明具体对象。提议跳转不强行导航；应用内容不自动登记提交。

右侧同一面板切换“AI助手／来源”，避免同时挤出第三、第四个详情栏；可将来源在新页打开。大段阅读可全屏，返回恢复选区、章节和滚动。全屏助手之外的业务页面始终有直接按钮。

## 9. 版本、模板与导出

正文版本、评审报告、批注审阅稿明确分组；下载按钮与文件详情使用下表的用途名称，文件名带用途、项目和稿件版本。取回文件直接执行，不增加没有具体必要性的确认步骤；标准提交资格按真实产物用途判断。

| 取件位置／文件用途 | 按钮文字 | 必须可见的身份 |
| --- | --- | --- |
| 评审结果／Word评审报告 | 下载评审报告（Word） | 对应评审轮次与正文版本；用于理解结论 |
| 评审结果／批注PDF | 下载批注审阅稿（PDF） | 对应原PDF版本；用于修改参考 |
| 正文版本／DOCX | 下载投标正文（Word） | 具体正文版本及对应检查资格 |
| 正文版本／PDF | 下载投标正文（PDF） | 具体PDF及评审关系，不能混同批注稿 |

尚待生成时沿用“生成版本／生成并评审”，在正文版本区明确生成对象，按钮仍按自动开始与明确人工请求规则命名。正文下载不把生成成功等同于可登记提交。

页面顶部主要按钮按自动开始设置显示“生成并评审”或“生成版本”；开启时可从次级菜单选择仅生成，关闭时生成后可明确点击开始评审。按钮名称必须对应实际动作，显式人工评审不要求重新开启自动开始。下方按时间列出草稿快照、Word／PDF文件、生成状态、检查缺口和对应评审。最新生成、用于当前评审、实际提交分别标记。每行可查看、比较、下载或发起评审；重复下载不创建新评审或独立样本；显示设置、影响状态变化可生成新的展示副本，保留原始产物。

生成面板分别选择目录模板和版式模板，显示来源草稿及资料版本。Word或PDF有一种失败时分别报告，不能用另一格式的成功掩盖。预览显示真实物理页及可检测的超页、缺图、乱码、断表、目录和暗标残留问题；无法核对的条款另列待核验。

外部Word修改后重新上传的文件另建版本，不继承旧PDF通过结论。正式登记面板明确最终文件、评审轮次和提交检查。历史补录仍为独立入口，不用颜色和按钮误导成通过标准检查。

## 10. 资料库与任务

资料库采用统一列表外框和分类入口，文档、企业知识、公司事实、模板分别有自己的状态列。文档可已上传但未解析；知识可待确认、已发布或失效；公司事实需来源与有效性；两种模板清楚区分。打开详情看来源、版本、适用性和引用影响，选作参考明确目标项目。

任务页仿照“模板／运行记录”组织。模板列表展示名称、用途、触发、启停和最近运行；创建可用自然语言或表单。运行详情展示对象、实际输入、阶段、产物、失败与恢复动作。运行统计只用于技术诊断，不当中标效果。只显示真正实现可运行的触发选项，未实现的产品目标不做可点击假按钮。

## 11. 响应式、恢复与可访问性

1440px以上可同时展示收起的全局栏、项目菜单、中央内容和助手。1100—1439px默认收起全局与助手，保证正文；需要助手时可覆盖部分工作区并可返回。更窄时项目菜单收为抽屉。390px手机将章节、来源和助手分别全屏呈现，任何时候只保留一个主要详情层，不横向缩成四栏。

编辑保存失败要有常驻文字和重试，离开前保留未提交输入；不能仅用短暂toast。断线或重新登录从业务记录恢复任务，未确认操作不能自动执行。同章节冲突给出两边变化，旧AI建议也要重新比较。所有拖动有键盘替代，图标有名称，焦点与选择可见，状态不只靠颜色。

### 11.1 页面动作与恢复反馈

| 动作／状态 | 持续可见的反馈 | 继续方式 |
| --- | --- | --- |
| 输入尚未保存、准备生成 | 保存中／失败及待保存内容 | 确认保存后才固定生成版本；失败就地恢复，不用上一稿冒充 |
| 生成中又修改正文 | 正在生成的修订及最新草稿分别标记 | 可继续编辑，完成产物只对应所冻结快照 |
| Word成功、PDF失败 | 每种格式自己的结果和缺口 | 可取成功文件，PDF可靠性不足不自动正式评分 |
| 上传DOCX已收但解析／转换失败 | 原文件行和持续错误卡显示“Word原件已保存／本次对应检查未完成”，列具体缺口 | 主动作“上传此修改稿的PDF”，带入原项目／角色及改稿来源；保留原件和旧轮次，查看缺口，错误可重试时才给重试 |
| 已补上传PDF但与DOCX对应未核验 | 具体受检PDF名称／版本，另标“Word交付未获对应检查资格” | 直接检查所选PDF；保留用户声明关联，不将外传PDF冒充受控转换，也不把两种格式强写成同一逻辑文件版本 |
| 新资料到达、旧评审完成 | 资料已更新、该报告对应旧输入 | 保留旧结果，进入最新资料的处理状态 |
| 来源已失效或临时链接过期 | 区分来源资格失效和读取链接过期 | 前者重选来源；后者重新授权读取同一文件，不换证据对象 |
| 取消与完成竞争 | 正在取消／已完成／已取消以服务端为准 | 有效产物仍可打开，迟到结果不能覆盖当前对象 |

草稿、生成、评审、提交身份在按钮附近可见；“已保存”不暗示“已评审”，“已生成”不暗示“可登记提交”。Word/PDF对应关系和取消语义以PRD第10.7及8.6节为主记录。

## 12. 设计交付与验收

本文件中的三张图片仅作目标布局参考，数据均为虚构；对应SVG位于同目录assets。图内按钮文字以本文第9节用途命名表为准，泛称“下载Word/PDF”等不能作为当前实现规格；PNG／SVG不代表按钮文案已同步。前端实现后须核对真实按钮与产物身份。颜色、间距和界面结构已具体化，交互仍须按PRD场景在真实软件中验收。tender-design中的十个HTML页面及当前tender-app保存既有实现，不因本规格形成而声明完成GovDash式改造。

界面验收还须核对快速评审与章节编制可以在同一项目往返，三个常用入口可直接进入、可选功能不增加核心流程前置条件。真实试用按PRD第18.3节观察第二项关键风险的发现、补遗关系核验、成绩登记差异处理，同时检查首次上传与外部改稿恢复；未实施时标待观察，不增加默认流程或审批。

界面验收至少走通：项目列表到资料包；矩阵定位到章节；选区建议到差异应用；生成PDF到实际评审；补遗影响到新稿复检；来源选择到用途隔离；关闭助手后任务完成并回到产物；Word外部修改后重建证据；窄屏和键盘操作。关键反例见[PRD逻辑检查与场景验证](../04-验证与测试/PRD逻辑检查与场景验证.md)。
