# 普通模型调用账本架构审查

结论：本候选普通模型调用账本机制通过，未发现阻塞该模块接入的架构问题。范围为六份冻结源及已记录依赖；不构成完整 A1.1、正式评分、真实计费或模型效果验收。

输入：`apps/api/a1-ledger-candidate-01.json`，SHA256 `78441a80539fa76f128e6dcc56f42476edb7e5daffc3c334d328358f369a7c5f`。六份源在执行前后均与清单一致，身份见 `candidate01-inputs.json`。

预留在 bid → operation → plan → receipt 的受限事务内校验有效租约、代次和 fence，完成持久预留后才离开事务请求 provider。同逻辑调用仅首次预留可发送；reserved、unknown 和失败记录均不因任务重放自动重新收费。共享 command 的调用数与最大输出 token 预算在 bid 锁下聚合，单次上限亦有检查。成功复用校验对象 SHA；取消后迟到成功仅补记真实使用量，旧 fence 无法发布业务结果。普通 Worker 不领取研究协议任务。

独立执行了开发六项真实 PostgreSQL、非 owner 角色用例，并增加四项检查：同键并发仅一次预留；共享命令调用数并发不超额；输出 token 并发不超额；取消及 reconcile 后迟到响应保留 usage、操作仍 cancelled、旧 finish 返回 false 且业务 effect 为零。全部通过，见 `candidate01-independent-result.json`、`candidate01-independent-tests.xml` 和可复跑的 `probe_ledger.py`。模型 HTTP 使用显式 MockTransport，对象使用显式内存端口；收费调用和真实对象请求均为零。

预算证明针对实现声明的调用次数与预留最大输出 token，不是货币账单或供应商发票。完整 A1 的 prepare/评审自动接续、真实 Kafka 故障、界面、人工决定与事实变更、gate 和提交仍由相应候选单独验收。正式评分保持 unavailable；普通调用机制通过不授予模型正式资格。
