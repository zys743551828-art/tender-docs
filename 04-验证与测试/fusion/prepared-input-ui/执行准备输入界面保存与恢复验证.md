# 执行准备输入界面保存与恢复验证

应用 `6765a8d4a962acce5bc951053de4be507eaef771`，分支 `fusion/bid-workbench`，本机预览 `http://127.0.0.1:5188`／fusion_v5。冻结输入工作面可显式保存执行准备输入、恢复未确认的原请求，并按编号读取同一冻结输入的历史准备记录。后端基础见[持久化与事务](../prepared-input/执行准备输入持久化与幂等恢复验证.md)。

## 行为与边界

- 用户先复核选定冻结输入的当前条件；精确解析证据匹配才可新建准备输入。保存只发送该冻结摘要、观察到的语义上下文摘要和 `rerun:null`，服务端重新核原件和稳定输入。原件核验时点与观察时点可以不同，语义内容必须对应。
- 请求发送前将完整scope、冻结输入身份、幂等键、原请求体和上下文摘要保存至当前会话的恢复记录。记录不含正文、原件定位或口令。写入失败则不请求；损坏或身份错配则阻止新请求并提示保留记录核对。
- 网络失败、异常回执或已进入恢复的请求遭拒时，保留原请求。恢复显式重放原键、原体，不替换为新候选，不自动重发。首次新请求收到明确的上下文／输入／项目或原件拒绝才解除待确认状态；通用错误保持未知。
- 回执通过scope、冻结／输入／证据引用、操作主体、已知唯一阻断、全部false标志、上下文语义、微秒时间顺序、内容／执行身份及manifest摘要校验后，才显示“执行准备输入已读回并校验，尚未启动评审”。本机完成记录写入失败时仍保留待恢复请求。
- 准备快照摘要和上下文快照摘要覆盖不同私有内容，前端仅核格式与公开绑定，不要求两者相等、不宣称验证了私有快照正文。主体身份摘要在冻结公开视图中未提供，精确主体绑定由服务端校验。
- 按编号读取只接受同一scope、冻结输入和记录ID，允许历史操作者；不清除待确认保存。切换scope后的迟到保存、编辑历史编号后的迟到读回均不能覆盖当前界面。
- 保存及历史结果只代表不可变的 `prepared_input`，无正式启动按钮、任务、Outbox或报告；当前来源、事实资格和其他阻断仍须在正式启动前重查。

组件负责交互，`executionInputRecovery`负责会话恢复契约，`executionInputValidation`负责公开响应核对；CSS限定于冻结输入组件。合成预览请求仅在页面内模拟，QA目录不进入最终部署。
