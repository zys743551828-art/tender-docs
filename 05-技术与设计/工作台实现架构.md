## 任务和报告生命周期

1. UI按当前成员、bid和technical scope恢复；`GET prediction-pipeline`读取，`POST /advance`推进，`POST /cancel`取消（前缀 `/api/v1/bids/{bid_id}/technical-scopes/{scope_id}`）。封闭请求不接受任意证书选择或分数。
2. 自动开关开启时以冻结scope命令为意图，关闭时等待已有开始评审命令；核查未就绪或文档版本/parse/file_digest集合不相等不提交。多个/零合格认证明确拒绝。
3. 固定计划写原审计，UUID5命令去重；先授权，再写私有对象，再短事务复验入队。重试与丢ACK查原操作，不创建平行队列。
4. Worker按原lease/generation/fence取得执行权，读固定对象并计算；计算完成不是正式结果。过期主机结果不得覆盖新主。
5. API发布前复验认证、输入、取消和范围；结果与发布标记同事务。协调器默认关闭，启用后恢复已有任务，无需浏览器常驻。
6. 统一报告绑定同scope最新合格核查、当前人工决定/设置/报价及结果；对象读取和Word计算在事务外，最终快照不一致拒绝。partial/unknown保留，隐藏数值所有出口一致。

实际全部路由以[机器快照](https://github.com/zys743551828-art/tender-app/blob/50657762cb2eaa08f81db87e188eba8e629dd131/workbench/packages/contracts/fusion-implemented.openapi.json.gz)为准；目标 contracts/openapi 不代表已注册。接口改动先导出实际OpenAPI，再生成前端操作类型。

## 执行、费用与模型质量分开

材料审核通过只授权指定模型/profile/输入版本和价格条件的执行申请。发送边界仍复验有效性与预算；未知计费不按零展示、不重新发送，撤销后允许已有调用结算。真实调用默认禁用，凭据经受控宿主注入，不进请求、日志或Git。DeepSeek名称沿用现有配置，不证明外部型号/能力有效。

预测认证是另一条权威链：显式冻结阈值、原生final报告、合格live观察/回退、绑定模型与输入身份、有效期/撤销。人工批准执行不等于准确性验收。所有正向fixture仅验证机制。

生成端口由`packages/domain/providers/generation.py`定义统一配置、结果、同步/异步调用契约，`factory.py`只装配已实现的DeepSeek适配器。业务代码通过端口调用，不按厂商名字拼HTTP请求；其它厂商/协议返回明确未实现，不能靠改名称冒充适配。`GENERATION_PROVIDER/PROTOCOL/MODEL/BASE_URL`由进程配置选择，兼容既有`DEEPSEEK_MODEL/BASE_URL`与现有凭据；模型API不属于依赖版本锁。端点仅接受显式HTTPS配置，不接收调用请求中的任意URL。

响应ID、usage、错误、总超时与异步取消仍保留；已发送请求结果不明时不自动重发。执行profile绑定端点、协议、用途及模型，切换不能复用另一配置的费用事实。当前助手SQL费用授权仍绑定既有DeepSeek官方端点与已登记价格，未登记端点/价格返回拒绝而不是发送；厂商端口可扩展不等于费用授权自动扩大。27项新端口测试与75项既有传输/错误隔离回归通过，无真实付费调用。

## 实际接口与状态消费

统一前缀为 `/api/v1/bids/{bid_id}/technical-scopes/{scope_id}`：

| 相对路径 | 操作 | 消费语义 |
|---|---|---|
| `/prediction-pipeline`、`/advance`、`/cancel` | GET、POST、POST | 恢复或推进既有开始意图；不让客户端任选认证 |
| `/prediction-tasks` | POST（202） | 显式固定命令提交到原持久任务系统 |
| `/prediction-tasks/{command_id}`、`/advance`、`/cancel` | GET、POST、POST | 原命令状态/发布恢复/取消；接受不代表结果有效 |
| `/formal-predictions`、`/{command_id}` | POST、GET | 保留直接预测兼容用例与当前资格复检读取 |
| `/formal-predictions/{command_id}/report[.docx]` | GET | 配套预测报告，仍有效但不替代四部分组合 |
| `/formal-predictions/{command_id}/unified-report[.docx]` | GET | review_id及可选simulation_id绑定共同快照，按当前设置隐藏 |

pipeline可显示cancelled、blocked、ready或report_blocked等服务端状态，UI不能把Worker succeeded直接显示为有效预测。ready后仍可能因资格/设置/输入变化在生成时拒绝；历史已失效结果不给数值。未配置装配返回不可用，不能用空卡片冒充评审成功。准确字段、错误码和required集合以实际OpenAPI为准。

原生执行helper不是可直接调用的RPC；PUBLIC及普通受限Worker不能直接执行live_send_current。当前SQL安装/2和执行方法/3修正安装权限，旧方法/归档事实按原版本保留，详见运行说明。

## ADR：Word 转换采用成熟组件与薄适配

决定：保留已实测的 **Gotenberg 8.39.0 官方预构建镜像**负责 DOCX 渲染与 PDF 转换，适配层只处理提交、超时、状态、结果读取及必要的运行观测；不自建 Word 镜像，保持既有严格检查，仅做已复现表示差异的必要协议适配，暂停扩写新几何算法。转换服务负责渲染，本项目额外的“原 DOCX／PDF 排版对应资格”仍是独立业务要求，不能以服务成功返回或肉眼正确代替资格通过。

2026-10-30 在用户 Windows 本机只读核对官方仓库、发布及安装资料，比较如下；版本为访问时状态，未按 stars 排名，也未运行新的候选服务。

只读根不等于没有可写临时目录；无外网也不等于所有网络均不存在。`network=none` 阻断容器外部访问，容器内 loopback 仍可用，已能通过 `docker exec` 在镜像内部以 curl 访问 `127.0.0.1`；这不证明宿主或其他容器能访问服务。完整链路使用受控内部网络连接本地 API／存储，与独立离线容器检查分别记录。

本次五条路线的官方资料均未提供原 DOCX／PDF 全部视觉对应的保证。代表性边界见 [Gotenberg PDF 标记语义讨论](https://github.com/gotenberg/gotenberg/issues/1676)、[unoserver 特定页眉批注](https://github.com/unoconv/unoserver/issues/211)、[ONLYOFFICE 特定浮动表格挂起报告](https://github.com/ONLYOFFICE/DocumentServer/issues/3856)、[Collabora 断词与换行互操作](https://github.com/CollaboraOnline/online/issues/15973)及 [docx2pdf 任务计划 COM 初始化](https://github.com/AlJohri/docx2pdf/issues/115)；这些是个案或功能讨论，未在本项目复现，不作为普遍缺陷或方案质量排名。

组件版本沿用生态原生机制：镜像使用官方版本与平台 digest，Python 使用标准 lock 和 pip 原生 `--require-hashes`，不再新增自建摘要注册表或资格门禁；外部模型 API 不纳入版本锁定。后续若确需独立引擎或在线编辑，再用同一小组样本评估 ONLYOFFICE 的收益、部署与许可条件，不先扩写自研排版规则。

## 容器内 Word Worker 的本机执行边界

当前应用`4108b686c9c5174b6e14ae8f29cfc89c665dd752`继承2a64dfe已落地的`word-conversion-execution/2`，并新增标准Web构建材料；Word v2检查点`2a64dfe`的[CI41100590565](https://github.com/zys743551828-art/tender-app/actions/runs/41100590565)已11/11成功；当前4108对应[CI41103933851](https://github.com/zys743551828-art/tender-app/actions/runs/41103933851)正在跟踪，终态未确认，不标为已绿。TEST-WORD-EXECUTION、TEST-WORD-EXECUTION-HOST、TEST-WORD-EXECUTION-DISPATCH职责如下：

| 位置 | 执行职责 |
|---|---|
| Linux Worker | 原profile及来源准入、PAGE/RICH生产和manifest核验、字体事实与请求精确绑定、原字体替代/字形判gap、原PDF全文/页码/表图图注检查、RICH目录循环及最终coverage。外来Word保留宏、外链及动态域拒绝。 |
