# 首批实现的产品验收清单

本清单供前端、后端、测试及产品Owner执行T0与A1最小PDF闭环验收，只细化已冻结规格，不修改产品规则或扩大首批范围。**清单未整体执行，不能据此宣布完整A1或业务P0通过。** T0＋PDF资料切片已有实际产品走查，范围、三项整改复验及限制见[实际产品评审](PDF资料切片实际产品评审.md)；清单中其余完整A1项目仍待实现和执行。实现具备后，按实际提交、配置、运行结果及限制逐项记录。

业务依据为[PRD](../../02-业务与产品/AI投标工作台PRD.md)，界面依据为[交互规格](../../05-技术与设计/交互与视觉设计.md)，技术字段与接口读取[详细协议](../../05-技术与设计/detailed-design/README.md)，职责和阶段以[任务板](../../00-项目管理/实施任务板.md)为准。这里不另造API、枚举或完成标准。

## 1. 执行条件与完成边界

准备一组可公开用于测试的合成招标、V1／V2正文与补遗，包含已知核心违反、纯评分缺口、可解决问题和明确原页证据；真实资料另在授权环境执行。记录应用提交、契约摘要、部署配置、存储／模型适配器及输入文件摘要。测试适配器须显式标识；正式配置缺失时不得自动返回测试结果。

| 阶段 | 本阶段能声明什么 | 仍不能声明什么 |
| --- | --- | --- |
| T0底座 | 登录、空库及命令／后台操作状态实际可用，相关质量门禁及真实PG／Kafka机制测试通过；由技术和测试角色提供证据 | 只跑健康检查、示例消息或静态契约，不等于上传评审链路完成；不得勾选A1可用 |
| A1软件流程 | 下文核心与异常路径在真实API及浏览器实际执行，明确哪些使用测试适配器；产品／用户角色核对真实界面 | 测试适配器的脚本化结果不证明真实模型、存储、解析效果或业务可用性 |
| A1真实适配联调 | 在明确的真实存储、模型与代表性文档范围内联调，报告实际解析、引用、失败及恢复；据证据和限制判断“A1快速评审可用” | 不自动获得否决检测真实质量、正式评分精度或生产上线资格；不扩大至未试的格式与文档 |
| 评分研究并行 | 在用途与执行底座可用后验证完整章节、三次独立判断、样本／预算／恢复，单独标“评分研究链路可运行” | 不能因为A1完成、研究调用成功或有20组配对就标“模型业务验收通过” |
| 后续业务及生产验收 | 真实标注质量、独立评分评测、容量和恢复分别提供证据；模型及发布按原门槛放行 | 不把本清单、模拟角色走查或开发单节点当作真实用户、业务效果或生产验收 |

A1可独立交付；评分研究并行推进，不等待完整编辑器、任务平台或知识维护页面。两个P0的交付状态分开记录，组合演示口径见[PRD第19.2节](../../02-业务与产品/AI投标工作台PRD.md#192-交付顺序与退出条件)。

## 2. A1完整交付前必须走通的核心路径

下表按使用顺序执行。每行保存实际画面、操作对象与后端结果；点击成功的提示不能替代持久对象和再次打开后的状态。

| 编号／操作 | 前端须可见、可做 | 后端及刷新后应成立 | PRD依据 |
| --- | --- | --- | --- |
| IP-01 建项目并上传一批招标／正文 | 简短建项目或直接上传；自动识别后只集中核对影响结论的身份／角色歧义；无需先选模板、建知识或配任务 | 成功原件保留；批次完成后按自动开始受理一轮，不能每收一个文件重复评审 | 3.4—3.6、6.1、7.1—7.2 |
| IP-02 等待评审、离开再回来 | 真实阶段与对应稿件可识别；可离开，重开项目可找到运行或产物；无配置时明确不可运行及恢复条件 | 输入被冻结；刷新不重建等价任务，不把聊天流结束当任务成功 | 5.4、7.2、8.4 |
| IP-03 看关键风险和矩阵 | 默认一句关键结论、评分适用性及一个主要下一步；所有问题／矩阵可直接进入；第二项关键问题不因处理第一项而丢失 | 已知违反能对应条款与正文证据；来源范围、核心提取、核对执行、评分覆盖及人工确认分开 | 3.7、7.3、9 |
| IP-04 打开原页、返回问题 | 能切换招标原页和正文响应；无可信框则显示整页并说明，返回保留位置；内网中文资源随站点可用 | 页码、文件和版本与本轮一致；缺失型判断列已查范围，不伪造正文引文 | 7.3、16.1 |
| IP-05 处理问题与规则 | 可确认、驳回、暂缓并留理由；规则批量确认只处理明确选项，不覆盖既有决定；不在首次评审前强迫全部确认 | 采纳建议或说“改好了”不等于解决；暂缓仍未处理；有理由驳回不再以该问题阻断，历史可查 | 7.2、10.1、10.3 |
| IP-06 补出漏提核心要求 | 当前规则／来源核对处“补充并确认条款”，展示原文、页码、条件／例外、范围与影响；合法提交无需再次确认 | 一次原子追加新包与新增人工确认，旧评审过期并给重新评审入口；确认规则不等于正文满足；后续模型漏提不消除仍有效人工要求 | 7.3 |
| IP-07 外部改稿V2复检 | 直接上传新版，明确新文件／此文件新版本；可看V1历史报告、V2进度及实际复检变化，不要求进入编辑器 | V2有独立身份与新轮次；旧报告不覆盖；只有有效复核才解决原风险，未复检／失败不能变已解决 | 4.4、7.1、10.1—10.2 |
| IP-08 标准登记与事实补录 | 提交检查明确最终正文／评审／时间；条件未满足能定位原因；已在线下发生的提交有独立补录入口 | 当前输入、核心范围与核对、人工确认、关键问题由服务端重新检查；纯评分未验收不单独阻断；补录持续注明未完整检查、不补造当时预测 | 10.3—10.4 |
| IP-09 取回正确文件 | 结果页“下载评审报告（Word）”“下载批注审阅稿（PDF）”；已有投标正文从独立正文版本入口取回，按钮标用途及格式，无泛化确认 | 真实文件内容、用途、版本和请求一致；批注绑定原PDF；报告／批注不能冒充标准提交正文；不要求A1先具备正文生成器 | 15.2 |

IP-03的评分行为按实际接入进度记录：未接入或失败如实显示，已具备逐项判断则核其证据与覆盖；不能用“未验收”标签填补未实现能力。A1完成不能掩盖并行评分任务的真实进度。

## 3. 同批必测异常与恢复

| 编号／注入条件 | 期望交互与状态 | 不可接受的结果 |
| --- | --- | --- |
| IE-01 上传片失败／授权过期，随后刷新 | 原件状态与缺片可恢复；按需要重选本地文件并只补缺片；保留同批成功文件 | 要求重传整批，或只凭浏览器缓存显示文件已校验 |
| IE-02 必要页面／附件解析失败、核心输出不合法 | 持续显示原件已收、失败范围及可执行恢复动作，保留有效部分；未运行、失败、无法判断各有文字 | 空结果显示通过、错误变0分／满分一半、关键范围不明却宣称全稿完成 |
| IE-03 若该切片已接受DOCX，注入解析／转换失败 | 原文件处“Word原件已保存／本次对应检查未完成”，提供“上传此修改稿的PDF”、查看缺口及可重试时的重试；所选PDF身份明确 | 重传招标、强制在线编辑、同名即认定同稿或把PDF结论授予未核验DOCX；未接入DOCX时应如实提示支持范围并保留PDF路径 |
| IE-04 双击／请求重试、两个成员上传竞争版本 | 同一请求重复得到原结果；版本冲突保留已核验文件与输入，并让用户重新核对目标 | 重复调用／决定、迟到回调抢占当前稿、用旧卡覆盖新版本 |
| IE-05 评审运行中上传V2或补遗，旧任务随后完成 | 旧结果可查看且标历史／过期；当前待处理范围指向新输入，保留当前工作位置 | 以最后完成时间覆盖当前结果；补遗变化后继续用旧报告放行 |
| IE-06 已发现关键矛盾，再关闭检测并复评 | 已有未解决且未被有理由驳回的关键风险继续可见、可处理；本轮标“未运行”；有效复核／有据驳回后按真实状态结束阻断 | 关闭／零新发现就洗掉风险，或风险不可见但提交仍报无法定位的阻断 |
| IE-07 补充条款缺依据／歧义，或有效人工条款被模型漏提 | 前者保留输入、整笔不确认；后者来源有效仍保留并合并等价项；效力不明转待核验，有据替代／更正可结束义务 | 部分写包／确认、二次确认审批、人工劳动静默丢失或失效条款永久被当作有效要求 |
| IE-08 模型不可用、断流、取消与重新登录 | 失败环节可见，任务依服务端恢复；请求取消显示“正在取消”，实际终态明确；登录后保留工作但不自动执行旧确认 | 停止流式文字就当取消；未配置回填演示成功；登录后重放未确认写入；旧完成抢当前 |
| IE-09 隐藏预测分数／关闭报价，重开页面并重新导出 | 新输出一致隐藏预测数值、区间及派生分差；风险／缺口保留，官方成绩字段不受误伤；关闭辅助模块不增加必填步骤 | 从复制文本、图表或旧导出缓存泄露预测；误隐藏正式成绩或核心风险 |

至少用键盘及390px窄屏走IP-01、IP-04、IP-07、IP-08的关键操作，检查焦点、原页可读和返回状态；不用宽屏PNG代替。适用来源：[PRD第16节](../../02-业务与产品/AI投标工作台PRD.md#16-非功能异常与可访问性)。

## 4. 证据与角色收口

每项实际执行后记录：编号、应用提交／配置、输入摘要、真实或测试适配、操作步骤、预期与实际、画面或运行记录、后端对象／轮次、结论、限制及缺陷。只完成部分切片时标“未实现／未执行／受阻”，不为了勾选而模拟成功。T0不要求提前完成整张A1清单；A1完整交付不得以T0通过代替。

开发提供可运行切片和自测；测试独立回归；产品Owner核对行为与范围，用户角色核对实际路径与状态理解，架构师核技术实现边界；PM综合证据放行。产品Owner收敛四方反馈，必要规则变化先报PM重开候选，不在冻结审查期间静默改规格。

真人试用继续使用[PRD第18.3节](../../02-业务与产品/AI投标工作台PRD.md#183-验收场景写法)的第二项关键风险、补遗关系、成绩核验任务。成绩完整维护、章节编制、知识管理及报价复杂页面按对应阶段验收，不因这份清单提前塞入T0／最小PDF切片。源码与运行成果具备后，再形成实际产品review结论。
