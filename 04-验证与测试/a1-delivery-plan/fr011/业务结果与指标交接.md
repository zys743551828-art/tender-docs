# 业务结果与指标最小交接

本文件由产品Owner落实[PRD第15.3节](../../../02-业务与产品/AI投标工作台PRD.md#153-指标与复盘fr-011)、第13.4节及[一期方案第7节](../../../02-业务与产品/一期方案与验证计划.md#7-指标与验收口径)。一期的阶段结果与分母继续保留；在线误差按当前PRD收紧。范围是FR-011及它需要的业务结果登记，不新增CRM、成本利润、商机、商业看板或岗位审批。当前outcomes只表达成绩及核验，不能由技术分推断入围或中标。本交接未执行软件验收。

## 1. 最短入口与对象关系

项目已有实际提交时，在实交详情进入“登记实际结果”；复用项目、工程、标段／轮次、主体与实际稿件，只选择真实阶段、来源和时间。有官方分时链接已有成绩登记，不重复填已知身份，不要求先有分数才能记结果。只有候选公示就记候选，只有分数但无阶段结论就保留阶段未知。

一次“保存实际结果”追加事实；不是交易平台操作，也不自动核实。已有明确官方原页且用户明确点“核实此结果”时追加人工核验决定，服务端确认完整依据后才显示已核实。不增加岗位审批，也不强迫普通查看者逐项确认。更正同页展示原／新差异、来源及原因，一次“保存更正”追加新记录并移动有效头，旧记录仍可读。

成绩outcome与阶段结果独立：可分别缺失、冲突或更正。建议实际实现独立不可变BusinessResult及每提交唯一有效头，避免把阶段塞进现有score_kind或推算字段；数据库和路由实现由技术Owner收敛，不改本文件所引用的冻结SQL。

## 2. 最小字段与阶段

以下为actual契约需要定义的字段，不宣称已注册。ID由服务端和可信选择投影提供，用户不手填UUID。

| 对象 | 必需内容与语义 |
| --- | --- |
| BusinessResultRequest | submission_id、stage、source_type（user_reported／official）、source_version_id（无官方原件时可null）、evidence_refs（document_version_id／evidence_id／physical_page／quote）、announced_at（公布时刻可未知）、known_at（实际取得／获知时间）、reason |
| BusinessResultView | id、bid_id、submission_id、上述原内容、created_by／created_at、supersedes_id；独立verification（pending／verified／conflict／rejected）、核验决定身份；当前head_revision／current、usable与unusable_reasons |
| BusinessResultCorrectionRequest | base_result_id、完整的新结果字段及correction_reason；绑定当前结果头强If-Match，不能只对历史记录改字 |
| Metrics scope | period_from／period_to、as_of、项目范围／统计单位、verification_scope、口径标识、有效提交／结果头摘要、各类排除数和缺口；默认按真实submitted_at选择时间窗，不按晚录入时间改业务归属 |

stage白名单与界面文字固定：

| stage | 显示及边界 |
| --- | --- |
| pending | 结果未出／阶段未知；不能当未中标 |
| technical_shortlisted | 技术入围；尚未等于最终中标 |
| not_shortlisted | 未入围 |
| rejected | 被招标方否决；和verification=rejected“该记录未采信”分开 |
| candidate | 中标候选；不能记最终中标 |
| awarded | 已中标；须有对应真实结论 |
| not_awarded | 已明确未中标；不能用没有消息代替 |
| cancelled | 项目取消；独立展示，不进两项率的分母 |
| failed_tender | 流标；独立展示，不进两项率的分母 |

stage是事实类型，verification是证据核验，二者不能混为同一状态。普通报送可保存pending核验并用于明确标注的公司台账；verified须官方原件、逐字位置、正确项目／轮次／主体／实交关系、公布与取得时间及真实核验人。来源／关系不明不授verified，冲突保留。不能把缺分当0，也不能把高分自动填成入围或中标。来源失效、身份变化后当前结果若不可用，留原因并排除对应结论，不回退到较旧verified记录冒充当前有效。

## 3. 有效提交与分母

统计单位为本公司一次正式投标的工程／标段／轮次／主体。只用当前未被更正或重新实交替代的submission head；实际发生且有据的offline_fact也属真实台账，持续保留未完整检查标签，不能误当通过gate。样本admission与有效实交不是同一口径。

同一单位只能贡献一个当前提交；后续新稿没有实际提交依据不能改头。同单位出现两条无法判明的有效关系时列身份／提交冲突、待核实，不按最新完成时间或相似名字消重。旧提交和旧结果可查但不重复计数；替换成新实际提交后，其结果未登记即未知，不能沿用旧提交的结果。

默认公司台账使用当前、可用、verification=pending或verified且stage明确的记录，分别给未核实与已核实数量，不能把全部叫官方已核实。verification=conflict／rejected和不可用来源排除率的分母并单独列数；提供verified_only口径时界面始终显示当前口径。无头／stage=pending为未知，冲突另列，均不补成未中标。

| 输出 | 唯一算法 |
| --- | --- |
| effective_submissions | 上述当前有效实交单位数，不是训练样本数；若兼容目标admitted_submissions，必须明确同一台账口径 |
| known_outcomes | 当前可用且非pending的阶段结果数，包括取消／流标；另列unknown_outcomes、conflicted_outcomes、unusable_outcomes，不重叠冒充全部已知 |
| stage_counts | 各明确阶段分别计数；candidate不并入awarded，技术分不生成阶段 |
| shortlist_rate | （technical_shortlisted＋candidate＋awarded＋not_awarded）／（这四类＋not_shortlisted＋rejected） |
| win_rate | awarded／（awarded＋not_awarded＋not_shortlisted＋rejected）；candidate、technical_shortlisted尚非最终结果，不进此分母 |
| 每个MetricRatio | numerator／denominator为真实整数，value为Decimal比值字符串；denominator=0则value=null，显示“暂无可评价结果”，不写0% |

取消、流标、未知、核验冲突都不能被当作未中标冲进率；“未核实报送”与“官方已核实”数量始终可见。没有基线／真实试点不得显示提升中标率的因果承诺。

## 4. 风险闭环与冻结快照

沿用QualificationMetrics的identified／resolved／dismissed／open_at_submission／official_rejections，但每个数字注明范围与快照。按本项目最近一轮适用评审中的否决／强制义务问题及其跨轮关联去根身份去重；其他一般建议不混入，不能按每轮复制finding ID重复算发现。resolved与dismissed分别计数，不把有理由驳回误报称成功整改；confirm、defer、采纳建议均非解决。

提交登记在同事务保存不可变open_risk_snapshot，可放既有gate_snapshot／evidence的明确子对象或独立快照记录；实现存储由技术Owner决定。至少冻结submission_id、review_id／manifest_digest、body_version_id、scope_issue_ids／根身份、当时决定／核对证据身份、open／resolved／dismissed计数、assessment_as_of、frozen_at和basis。snapshot不是从当前finding状态动态重算的缓存。

assessment_as_of指实际submitted_at，frozen_at是系统冻结时刻，不能混同。可依据当时已存在的评审／决定审计重建时写basis=reconstructed_from_audit及依据；当时同步可证明时写contemporaneous。事后补录且没有当时证据则basis=unknown、计数null，不把今天重评状态或空集假装当时0项。页面标明“当时风险状态未知／登记快照口径”，不伪称交易平台瞬时观测。

提交后解决／驳回或重新打开只更新当前处理态，不改当时快照。聚合open_at_submission在没有任何已知快照时为null；部分有快照时可汇总已知部分，必须同时给known_snapshot_submissions／unknown_snapshot_submissions及scope_note，不能宣称覆盖全部实交。official_rejections读取业务阶段rejected，不能由系统风险推断招标方实际否决，更不能自动认定具体风险导致否决。

## 5. 逐轮走势与在线误差

逐轮点沿用RoundTrendPoint：固定review_id、正文／规则／事实及方法、created_at、风险计数、PredictionView、comparable_to_previous与break_reasons。正文修改与方法／规则／适用范围变化分开；不可比处断线并写原因，不计算成改稿提升。官方技术分只关联其真实实际提交稿，不能铺到每一历史轮。最多20个项目的选择按现有一期范围；项目内稳定分页，前后端不把截取列表当完整走势。

show_prediction关闭时服务端返回hidden投影，省略预测值、区间、差分、换算和可反推它的误差；风险计数仍可看。指标MAE／bias也排除隐藏预测对应配对并说明排除范围，不能通过聚合或导出旁路泄分。

在线误差只收当前有效实交绑定的、实际提交前已成功且可证明未见标签的预测，正文／输入与提交完全匹配，官方技术总分及满分已核实且无冲突。每提交只一份固定主配对；事后重跑是回测，不能挑最接近官方分的一次。当前模型没有正式资格也不能因监控门槛赋资格。

输出至少prediction_pairs、needed_pairs=20、online_error_state（no_pairs／insufficient／sufficient）、mae、bias、excluded_pair_counts、scope_note。0对或1—19对的mae／bias均null；20对起才可显示百分制MAE和有正负号bias。单对误差是100×预测／预测满分−100×官方技术分／官方满分，MAE取绝对值均值，bias保留符号。均用Decimal。20只是在线误差展示门槛，不是模型验收通过、已校准、可发正式区间或因果效果资格。更正或隐藏导致剩19对时再次隐藏误差，不沿用旧值。

## 6. 实际接口交付与错误

建议新增业务阶段登记／单项／列表／更正及核验动作，分别绑定项目／具体submission；可沿用既有追加决定机制，但不能复用成绩核验来假确认阶段。具体路径与对象白名单由后端actual OpenAPI唯一导出，不让前端猜值。目标GET /metrics与GET /bids/{bid_id}/round-trends按本协议扩展读投影；MetricsView目标缺阶段、bias、排除范围等，不能只填固定0凑目标shape。

所有写请求遵守认证、CSRF、幂等与当前强If-Match；创建时来源/身份检查，更正及核验CAS拒绝旧头，同键只追加一次，不覆盖旧记录。409指出来源／身份／冲突，412保留表单并显示差异，422字段定位，401重登后不自动重放旧核验。读取与报告、项目结果卡使用相同有效头和口径；结果提醒开关只停止提醒，登记实际结果入口仍可用。

界面最小是项目内结果登记／历史，以及全局真实结果和风险指标页。显示时间窗、范围、核实构成、样本量和缺口，空态说明下一步来源，不加入商业销售漏斗、泛化审批或自动付费分析。当前能力未注册就准确说明未开放；已有技术成绩继续如实可查。

[待执行验收](acceptance.json)分别覆盖状态、分母、更正、快照、隐藏、20门槛与失败恢复，全部pending_application；产品文案和字段交接不替代实际软件、真人或模型验收。
